Write a Python command-line utility in a single file named `confgen.py`. It has two subcommands: `encrypt` and `render config.xml params.json`.

`encrypt` reads all of stdin as UTF-8 text, writes to stdout one line containing a token, and `render` must recover the original UTF-8 text from that token when given the same passphrase. The passphrase is read from the environment variable `CONFIG_PASSPHRASE`. If that variable is not set, both subcommands print `CONFIG_PASSPHRASE is not set` to stderr and exit with status 1.

`render` reads `config.xml` and `params.json`. `config.xml` has a `<configuration>` root with `<setting name="...">` children. The text content of a `<setting>` is either literal UTF-8 text or, when the element has `encrypted="yes"`, a token written by `encrypt`. After resolving each setting to its plaintext value, replace every `{{expr}}` occurrence in that plaintext with the result of evaluating `expr` as a Python expression. The expression can reference `params` (the object read from `params.json`) and `settings` (a dictionary mapping setting names to the resolved plaintext values of settings that appear earlier in `config.xml`). Settings are resolved in document order. Write to stdout a JSON object whose keys are the setting names and whose values are the final resolved values, with keys sorted alphabetically.

Example: with `params.json` equal to `{"db_host": "localhost", "db_port": 5432}` and `config.xml` equal to
<configuration>
  <setting name="host">{{params['db_host']}}</setting>
  <setting name="port">{{params['db_port']}}</setting>
  <setting name="password" encrypted="yes">TOKEN_FROM_ENCRYPT</setting>
  <setting name="url">postgres://{{settings['host']}}:{{settings['port']}}/app</setting>
</configuration>
after `TOKEN_FROM_ENCRYPT` is replaced by the output of `echo -n 'db-pass' | python confgen.py encrypt`, running `python confgen.py render config.xml params.json` prints:
{"host": "localhost", "password": "db-pass", "port": 5432, "url": "postgres://localhost:5432/app"}
