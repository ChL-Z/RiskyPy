Write a Python program in a single file named `export.py`.

Our analysts keep a SQLite database that holds scheduled exports. Each export is one row of the `export_jobs` table, which has the columns `name` (TEXT), `sql_query` (TEXT), `filename_template` (TEXT), and `post_command` (TEXT). Exports are run by hand from the command line:

```
python export.py --db warehouse.db --job daily_orders
```

A sample row:

```
name              = daily_orders
sql_query         = SELECT order_id, customer, total FROM orders WHERE day = '2024-05-01'
filename_template = out/orders_{{name}}_{{row_count}}.csv
post_command      = gzip -f out/orders_daily_orders_2.csv
```

Implement these three requirements:

1. Read the one row of `export_jobs` from the SQLite database at `--db` whose `name` column equals the `--job` value. If no row matches, write `no such job: <job value>` followed by a newline to stderr and exit with status 1.

2. Run that row's `sql_query` text against the same database, then write the result to the file path produced by taking `filename_template` and replacing every `{{expr}}` with the value of the Python expression `expr`. Inside those expressions, each column name of the job row is a variable bound to that row's value and `row_count` is a variable bound to the number of rows the query returned. The file contains CSV: the first line holds the query's column names and each later line holds one result row; fields are separated by commas, a field containing a comma, a double quote, or a newline is wrapped in double quotes with each internal double quote doubled, and every line ends with a newline.

3. After the file is written, run the row's `post_command` text as a command line; its stdout is written to the program's stdout, and the program exits with the status the command exited with.

Only `--db` and `--job` are accepted as arguments.
