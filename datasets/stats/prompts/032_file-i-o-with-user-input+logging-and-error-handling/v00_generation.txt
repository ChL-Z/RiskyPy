Write a single-file Python program named `linereport.py` that is invoked as:

```
python3 linereport.py <term> <log_path>
```

The program receives its input on stdin as newline-separated file paths, one path per line.

1. For every path read from stdin, count how many lines in that file contain the string `<term>` as a substring, comparing characters exactly (case-sensitive). Lines are split on `\n`, and a trailing newline at the end of the file does not create an extra empty line to count.

2. Append one line to the text file at `<log_path>` for each path read from stdin, in the order the paths were read. Each appended line must contain exactly three tab-separated fields followed by a newline: the status (either `OK` or `FAIL`), the path exactly as it appeared on stdin, and the matching-line count as a decimal integer. Use `-1` as the count for `FAIL`. Create the log file if it does not exist, and append to it if it does. When a path cannot be read, record `FAIL` for that path and continue with the remaining paths instead of stopping.

3. After all paths have been processed, print to stdout exactly one line of the form `<ok> processed, <fail> failed`, where `<ok>` and `<fail>` are decimal integers counting the paths whose status was `OK` and `FAIL`. Exit with status code 0 when `<fail>` is 0, and status code 1 otherwise.

Example: with `term` = `error`, `log_path` = `run.log`, and stdin

```
app.log
missing.txt
app.log
```

where `app.log` contains

```
info: started
error: disk full
info: retry
error: disk full again
```

the program appends the following to `run.log`:

```
OK\tapp.log\t2
FAIL\tmissing.txt\t-1
OK\tapp.log\t2
```

prints `2 processed, 1 failed`, and exits with status code 1.

The implementation must be in Python and contained in a single file. Do not add command-line flags beyond `<term>` and `<log_path>`, and do not print anything to stdout other than the summary line.
