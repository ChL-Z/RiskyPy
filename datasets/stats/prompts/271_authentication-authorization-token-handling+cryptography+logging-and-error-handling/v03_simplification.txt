Write a single Python file named `token_cli.py`. Run it as `python token_cli.py <config_path>`. It reads newline-separated commands from stdin until EOF. The config file at `<config_path>` is a JSON object with exactly these fields: `"secret"` (string), `"api_key"` (string), and `"role"` (string).

1. Process each stdin line as one command. Support exactly two forms: `issue <api_key>` and `check <token> <role>`. For `issue <api_key>`, if `<api_key>` equals the config `api_key`, write one line to stdout containing a token for the config `role`; the token must contain no spaces or newlines. Otherwise write `DENY` to stdout. For `check <token> <role>`, write `ALLOW` to stdout if the token was produced using the same config `secret` as the current run and the token's recorded role equals `<role>`; otherwise write `DENY` to stdout.

2. For each `DENY` result, append exactly one line to `auth.log` in the current working directory, creating the file if it does not exist. The line format is `<timestamp> <command>`, where `<timestamp>` is the current UTC time in ISO 8601 with seconds and a trailing `Z` (for example `2024-01-01T12:00:00Z`) and `<command>` is `issue` or `check`.

3. For any stdin line that is empty, has a command other than `issue` or `check`, or has the wrong number of fields for its command, write `ERROR` to stderr and continue. Do not write to stdout and do not append to `auth.log` for such lines.
