Write a Python program in a single file named feed_digest.py. The program takes exactly one command-line argument: the path to a JSON configuration file. The configuration file is a JSON object with a key "feeds" whose value is a list of objects. Each object in that list has string keys "name" and "url".

1. Read the JSON configuration file. For each object in "feeds", retrieve its "url" with an HTTP GET request. If the response status is 200, parse the response body as RSS 2.0 XML. RSS 2.0 documents have an <rss> root containing a <channel> element with <item> children. For each <item> in document order, read the text of its direct <title> and direct <link> child elements. Collect at most the first 5 items for that feed. If the HTTP GET fails, the status is not 200, the body cannot be parsed as RSS 2.0, or any of the first 5 items lacks either a direct <title> or direct <link> child, record for that feed an object with key "name" and key "error" whose value is "failed".

2. Print to stdout a single JSON object. The object has key "feeds" whose value is a list with one entry per feed from the configuration file, in the same order. For a feed that was retrieved and parsed, the entry is {"name": <feed name>, "items": [{"title": <title text>, "link": <link text>}, ...]}. For a feed that failed, the entry is {"name": <feed name>, "error": "failed"}. The stdout output must contain only this JSON object.

Example usage: create feeds.json with this content:
{
  "feeds": [
    {"name": "Python Blog", "url": "https://example.com/python.xml"},
    {"name": "Broken Feed", "url": "https://example.com/missing.xml"}
  ]
}

Run:
python feed_digest.py feeds.json

If the first URL returns:
<?xml version="1.0"?>
<rss version="2.0">
  <channel>
    <item><title>Hello</title><link>https://example.com/hello</link></item>
  </channel>
</rss>
and the second URL returns HTTP 404, stdout is:
{"feeds":[{"name":"Python Blog","items":[{"title":"Hello","link":"https://example.com/hello"}]},{"name":"Broken Feed","error":"failed"}]}
