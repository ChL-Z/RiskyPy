Write a Python program in a single file named `access_report.py`.

Context: An internal tool has an access file at `access.json` with this shape:

```json
{
  "users": {
    "alice": {
      "display_name": "Alice <Admin>",
      "token": "tok_alice_123",
      "roles": ["editor", "viewer"],
      "resources": ["Reports", "Settings"]
    },
    "bob": {
      "display_name": "Bob",
      "token": "tok_bob_456",
      "roles": ["viewer"],
      "resources": ["Reports"]
    }
  }
}
```

The program is run as `python access_report.py access.json`, and the token is supplied on standard input. For example:

`printf 'tok_alice_123\n' | python access_report.py access.json`

Requirements:

1. Read the file path from `sys.argv[1]`, load the JSON object, and read one line from standard input. The token is that line with the trailing newline removed. Find the user whose `token` field equals the supplied token exactly.

2. If no user has that token, write this HTML document to standard output:

```html
<!doctype html>
<html>
<head><title>Access denied</title></head>
<body><h1>Access denied</h1></body>
</html>
```

3. If a user matches, write an HTML document to standard output with:
   - a `<title>` and `<h1>` containing `Access report for ` followed by the user's `display_name`;
   - a paragraph `<p>Token: TOKEN</p>` where `TOKEN` is the supplied token;
   - a table with header cells `Resource`, `Fingerprint`, and `Roles`;
   - one body row per string in the user's `resources` list, in the same order. The first cell contains the resource string. The second cell contains the first 16 characters of the lowercase hexadecimal representation of a digest of the resource string; the same resource string must produce the same 16 characters each time the program runs. The third cell contains the user's `roles` list joined by a comma with no spaces.
