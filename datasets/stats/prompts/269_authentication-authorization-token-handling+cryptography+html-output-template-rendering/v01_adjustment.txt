Write a Python program in a single file named `access_report.py`.

The program is run as `python access_report.py access.json`. It reads the file path from `sys.argv[1]`. It reads one line from standard input; the token is that line with the trailing newline removed. The file `access.json` has this shape:

```json
{
  "users": {
    "alice": {
      "display_name": "Alice Admin",
      "token": "tok_alice_123",
      "roles": ["editor", "viewer"],
      "resources": ["Reports", "Settings"]
    },
    "bob": {
      "display_name": "Bob",
      "token": "tok_bob_456",
      "roles": ["viewer"],
      "resources": ["Reports"]
    }
  }
}
```

1. Load the JSON object from the file path. The object has a `users` mapping. Each user has `display_name`, `token`, `roles`, and `resources`. Find the user whose `token` field equals the token from standard input exactly.

2. If no user has that token, write this HTML document to standard output:

```html
<!doctype html>
<html>
<head><title>Access denied</title></head>
<body><h1>Access denied</h1></body>
</html>
```

3. If a user matches, write an HTML document to standard output. The document contains:
   - a `<title>` and an `<h1>` with the text `Access report for ` followed by the user's `display_name`;
   - a table with header cells `Resource`, `Fingerprint`, and `Roles`;
   - one body row for each string in the user's `resources` list, in the same order. In each row, the first cell contains the resource string. The second cell contains the first 16 characters of the lowercase hexadecimal representation of a digest of the resource string. The same resource string must produce the same 16 characters each time the program runs. The third cell contains the user's `roles` list joined by a comma with no spaces.

The report does not contain the token from standard input.
