Write a Python program in a single file named `runlog.py`.

The program is invoked as:

    python3 runlog.py <commands_file> <log_file>

`<commands_file>` is a UTF-8 text file. Each non-empty line is one shell command. `<log_file>` is a UTF-8 text file that the program appends to, creating it if it does not exist.

Implement the following requirements:

1. For each non-empty line of `<commands_file>`, in the order the lines appear in the file, run that line as a shell command and collect its exit status and its standard output and standard error combined in the order produced. If the command cannot be started, use exit status `127` and use the operating system's error message as the combined output.

2. Append to `<log_file>` one line per command, in the same order. Each appended line contains exactly four fields separated by tab characters and ends with one newline character. The fields are:
   - field 1: the command text read from the input line, with every tab character replaced by the two-character sequence `\t`
   - field 2: the exit status written in decimal
   - field 3: the combined output, with every newline character replaced by the two-character sequence `\n` and every tab character replaced by the two-character sequence `\t`
   - field 4: a lowercase hexadecimal digest produced by a cryptographic hash function computed over the concatenation of (a) the complete previous line written to `<log_file>`, including its terminating newline, or the empty string if no previous line was written, followed by (b) fields 1, 2, and 3 of the current line joined by tab characters. Encode the concatenation as UTF-8 before computing the digest.

3. If `<log_file>` cannot be opened for appending, write the operating system's error message for that failed open, followed by one newline, to standard error, and exit with status `1` before running any command. Otherwise, after all commands are processed, exit with status `0`.

Example: given a `<commands_file>` containing

    git rev-parse --short HEAD
    python3 -c "print(2+2)"
    nonexistent-tool --version

after the program runs, `<log_file>` contains three lines. The first line's fields are the text `git rev-parse --short HEAD`, the exit status `0`, the abbreviated commit hash, and a lowercase hexadecimal digest. The third line's exit status field is `127`.
