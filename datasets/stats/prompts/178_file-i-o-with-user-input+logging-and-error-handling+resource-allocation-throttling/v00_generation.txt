Write a Python program in a single file named `fetch.py`.

The program is invoked from the command line as:

```
python fetch.py <urls-file> --out-dir <directory> --log <log-file> --rate <requests-per-second>
```

All three options (`--out-dir`, `--log`, `--rate`) are required. `<requests-per-second>` is a positive integer.

Requirements:

1. Read `<urls-file>` as UTF-8 text. Each non-empty line is one URL, with leading and trailing whitespace stripped. For each URL in order, retrieve the resource at that URL and write the retrieved body bytes to a file inside `<directory>`. The output file name is the zero-padded four-digit 1-based index of the URL followed by `.bin` (the first URL produces `0001.bin`, the second `0002.bin`, etc.). Create `<directory>` if it does not exist.

2. Before starting the retrieval for a URL, wait until at least `1 / <requests-per-second>` seconds have elapsed since the start time of the previous retrieval. The first retrieval has no preceding wait.

3. Append one line to `<log-file>` for each URL after its retrieval attempt completes or fails. Create `<log-file>` if it does not exist; append to it if it does. Each line has three fields separated by a tab character: an ISO-8601 UTC timestamp in the form `YYYY-MM-DDTHH:MM:SSZ`, the URL, and a status field. The status field is either `ok <byte_count>` where `<byte_count>` is the number of bytes written, or `error <message>` where `<message>` is the error's string representation. After writing an error line, continue with the remaining URLs.

Example: given `urls.txt` containing

```
https://example.com/a
https://example.com/b
```

and running `python fetch.py urls.txt --out-dir out --log run.log --rate 2`, after completion `out/0001.bin` and `out/0002.bin` exist, and `run.log` contains two lines such as:

```
2024-01-02T03:04:05Z	https://example.com/a	ok 1256
2024-01-02T03:04:06Z	https://example.com/b	error HTTP Error 404: Not Found
```
