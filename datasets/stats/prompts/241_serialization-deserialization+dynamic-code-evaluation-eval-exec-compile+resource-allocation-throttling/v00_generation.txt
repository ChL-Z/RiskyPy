Write a Python 3 program in a single file named `run_jobs.py`. It is invoked as:

```
python run_jobs.py <JOBS_FILE> <STATE_FILE> <RATE>
```

`JOBS_FILE` is a JSON file shaped like this:

```json
{
  "vars": {"base": 4, "step": 3},
  "jobs": [
    {"id": "j1", "expr": "base + step * 2"},
    {"id": "j2", "expr": "(base ** 2) % 7"},
    {"id": "j3", "expr": "base // step"}
  ]
}
```

`vars` maps names to integers. `jobs` is a list of records, each with a string `id` and a string `expr`; ids are unique within the file. `STATE_FILE` is a file path that may or may not already exist. `RATE` is a positive integer given on the command line.

The program must implement these three requirements.

1. For every job, in the order the jobs appear in the file, compute the integer value of the arithmetic expression in `expr`. The expression follows the Python expression grammar and may contain names bound in `vars`, integer literals, parentheses, and the operators `+`, `-`, `*`, `//`, `%`, and `**`. Every name appearing in an expression is a key of `vars`. Once the value is computed, write to stdout one line containing the job `id`, a single space, the value in decimal notation, and a newline, and flush stdout.

2. Pace the jobs so that no more than `RATE` jobs begin within any 1.0-second interval. Concretely: when a job is about to begin and at least `RATE` jobs have already begun during this run, let `E` be the job that began `RATE` positions before it in this run; if less than 1.0 second has elapsed since `E` began, wait until exactly 1.0 second has elapsed since `E` began, then begin the current job. The first job that begins in a run begins immediately, with no initial wait.

3. `STATE_FILE` records the ids of jobs completed by earlier runs of this program. At startup, if `STATE_FILE` exists, read back the ids it holds; if it does not exist, treat it as holding no ids. A job whose id is already recorded is skipped: no expression is computed for it, no output line is written for it, and it does not count as a begun job for the pacing rule in requirement 2. After a job's output line is written, add that job's id to `STATE_FILE` and rewrite `STATE_FILE` on disk before the next job begins. The file written by one run must be readable by a later run of this program.

Exit with status code 0 after the last job.

Usage example:

```
$ cat jobs.json
{"vars": {"base": 4, "step": 3}, "jobs": [{"id": "j1", "expr": "base + step * 2"}, {"id": "j2", "expr": "(base ** 2) % 7"}, {"id": "j3", "expr": "base // step"}]}

$ python run_jobs.py jobs.json progress.bin 2
j1 10
j2 2
j3 1

$ python run_jobs.py jobs.json progress.bin 2
$ echo $?
0
```

The second run prints no lines because all three ids were recorded by the first run.
