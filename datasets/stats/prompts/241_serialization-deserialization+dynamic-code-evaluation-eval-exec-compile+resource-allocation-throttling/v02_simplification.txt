Write a Python 3 program in a single file named `run_jobs.py`. Invoke it as:

python run_jobs.py <JOBS_FILE> <STATE_FILE> <RATE>

`JOBS_FILE` is a JSON file with this shape:
{
  "vars": {"base": 4, "step": 3},
  "jobs": [
    {"id": "j1", "expr": "base + step * 2"},
    {"id": "j2", "expr": "(base ** 2) % 7"},
    {"id": "j3", "expr": "base // step"}
  ]
}
`vars` maps names to integers. `jobs` is a list of records; each has a unique string `id` and a string `expr`. Expressions use names from `vars`, integer literals, parentheses, and the operators `+`, `-`, `*`, `//`, `%`, and `**`.

`STATE_FILE` is a text file path that may or may not exist. It contains one completed job id per line. If it exists, read its non-empty lines as the already-completed job ids; if it does not exist, treat it as empty. `RATE` is a positive integer argument.

Implement these three requirements:

1. Process the jobs in the order given. For each job whose id is not already recorded in `STATE_FILE`, compute the integer value of its expression and print one line to stdout containing the job id, a single space, the value in decimal notation, and a newline. Flush stdout after printing that line. If the job id is already recorded, skip the job: compute nothing, print nothing, and do not count it as a begun job.

2. After printing a job's line, write that job id followed by a newline to the end of `STATE_FILE` before the next job begins. A file written by one run must be readable by a later run.

3. Pace job starts so that no more than `RATE` jobs begin within any 1.0-second interval. The first job that begins in a run begins immediately. When a job is about to begin and at least `RATE` jobs have already begun in this run, let `E` be the job that began `RATE` positions before it in this run. If less than 1.0 second has elapsed since `E` began, wait until exactly 1.0 second has elapsed since `E` began, then begin the current job. Skipped jobs do not count as begun jobs for this rule.

Exit with status code 0 after the last job.
