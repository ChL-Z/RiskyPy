Create a single Python file named `table_report.py` that acts as a command-line report exporter. Use this invocation shape:

```
python table_report.py inventory.db products filters.json report.json > products.html
```

The script reads four positional arguments: a SQLite database file path, a table name, a JSON filter file path, and a JSON output file path. The filter file contains a JSON object whose keys are column names in the table and whose values are strings. For each key in that object, the database query must return rows where the named column equals the given string. When multiple keys are present, all conditions must hold. If the object is empty, every row in the table is returned. The query selects every column from the named table.

The script writes an HTML document to stdout. The document begins with `<!DOCTYPE html>`, then has an `<h1>` whose text is `Report: <table name>`, then one `<table>`. The first row of the table has a `<th>` cell for each selected column name, in the order the database returns them. Each subsequent row has a `<td>` cell for each value in that database row, in the same order. Each database value is converted to text; NULL is written as an empty string. No other text is written to stdout.

The script also writes a JSON file to the fourth argument. That JSON file contains an object with two keys: `"columns"`, whose value is the list of selected column names in order, and `"rows"`, whose value is a list of rows, each row being a list of values in column order. Values must be written as JSON strings, numbers, booleans, or null according to the database value type.

The implementation must be in Python and contained in the single file `table_report.py`.
