Write `access_ticket.py`, a Python 3 program in one file with two subcommands: `issue` and `verify`.

Both subcommands read `TICKET_SECRET` from the environment. If it is not set, print `error: TICKET_SECRET not set` to stderr and exit with status 2.

A ticket is one line with exactly three period-separated fields: `<user>.<role>.<check>`. `user` and `role` are non-empty and contain only `A-Z`, `a-z`, `0-9`, `_`, or `-`. `check` is exactly 16 characters from `0-9` and `a-f`.

`issue --user USER --role ROLE` prints one ticket line to stdout. The `check` field is 16 lowercase hexadecimal characters produced from `user`, `role`, and `TICKET_SECRET`. The same `user`, `role`, and `TICKET_SECRET` produce the same ticket line every time.

`verify --ticket TICKET --required-role REQUIRED_ROLE` prints `allow <user> <role>` to stdout and exits with status 0 when all of these hold: the ticket has the three-field shape and field rules above; `check` equals the `check` that `issue` would produce for the ticket's `user` and `role` with the current `TICKET_SECRET`; and `role` equals `REQUIRED_ROLE`. Otherwise, `verify` prints `deny` to stdout and exits with status 1.
