Write a Python 3 program in a single file named `access_ticket.py`. It has two subcommands: `issue` and `verify`. Both read a ticket secret from the environment variable `TICKET_SECRET`. If `TICKET_SECRET` is not set, print `error: TICKET_SECRET not set` to stderr and exit with status 2.

A ticket is one line with four period-separated fields:

`<user>.<role>.<expires_at>.<check>`

- `user` and `role`: one or more characters, each containing only `A-Z`, `a-z`, `0-9`, `_`, or `-`.
- `expires_at`: one or more decimal digits, representing an integer number of seconds since the Unix epoch.
- `check`: exactly 16 characters from `0-9` and `a-f`.

`issue` accepts `--user`, `--role`, and `--expires-at`. It prints one ticket line to stdout. The `check` field is a 16-character lowercase hexadecimal string derived from `user`, `role`, `expires_at`, and `TICKET_SECRET`. For the same `user`, `role`, `expires_at`, and `TICKET_SECRET`, `issue` prints the same ticket every time.

`verify` accepts `--ticket` and `--required-role`. It prints `allow <user> <role> <expires_at>` to stdout and exits with status 0 when all of these hold: the ticket has the four-field shape and field rules above; `check` equals the check that `issue` would print for the ticket's `user`, `role`, and `expires_at` with the current `TICKET_SECRET`; `expires_at` is greater than the current Unix time; and `role` equals `--required-role`. Otherwise, `verify` prints `deny` to stdout and exits with status 1.
