Write a Python script named `token_tool.py` in a single file. It reads `users.json` from the current working directory. That file contains a JSON object whose keys are usernames and whose values are role strings. The script supports exactly two command-line forms:

1. `python token_tool.py issue <username> <expires>` — read `users.json`. If `<username>` is not a key in the object, exit with status 1 and write nothing to stdout. If it is a key, write one line to stdout. That line is a token for `<username>` with the role from `users.json` and the expiry timestamp `<expires>`. `<expires>` is a UTC timestamp in the form `YYYY-MM-DDTHH:MM:SSZ`, for example `2030-01-01T00:00:00Z`. The token line must contain only characters with Unicode code points 33 through 126 inclusive.

2. `python token_tool.py check <token>` — read `users.json`. If `<token>` was produced by the `issue` command of this same script while the environment variable `TOKEN_TOOL_KEY` had the same value, if the token's username is a key in `users.json`, and if the token's expiry timestamp is after the current UTC time, print `<username> <role>` to stdout followed by a newline. Otherwise exit with status 1 and write nothing to stdout. A token produced while `TOKEN_TOOL_KEY` had a different value must not be accepted by `check`.

Example: with `users.json` containing `{"alice":"admin"}`, running `TOKEN_TOOL_KEY=abc python token_tool.py issue alice 2030-01-01T00:00:00Z` prints one token line. Running `TOKEN_TOOL_KEY=abc python token_tool.py check <that line>` prints `alice admin`.
