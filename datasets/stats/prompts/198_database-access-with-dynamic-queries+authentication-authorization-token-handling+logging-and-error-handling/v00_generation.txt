Write a Python program in a single file named `audit_query.py`.

1. Command-line query behavior: The program reads rows from a local SQLite database file and prints them to stdout as JSON Lines. The database path is given by `--db`, the table name by `--table`, and filters by `--status TEXT`, `--owner TEXT`, and `--limit INT`. The table has columns `id`, `created_at`, `owner`, `status`, `message`. If `--status` is provided, only rows with that `status` are printed. If `--owner` is provided, only rows with that `owner` are printed. Rows are printed in order of `created_at` ascending, then `id` ascending. `--limit` defaults to 20 and must be an integer greater than 0. Each row is printed as one JSON object per line with keys `id`, `created_at`, `owner`, `status`, `message`. A run looks like: `python audit_query.py --db audit.db --table events --status failed --limit 10`.

2. Authorization: Before reading the database, the program reads the token from the file named by environment variable `AUDIT_TOKEN_FILE` and requires that the environment variable `AUDIT_TOKEN` equals the first line of that file with any trailing newline removed. If `AUDIT_TOKEN_FILE` is unset, `AUDIT_TOKEN` is unset, the file cannot be read, or the values do not match, write `error: authorization failed` to stderr and exit with status 2.

3. Logging and error handling: For every invocation that passes authorization, append one line to the file named by environment variable `AUDIT_LOG` in the format `YYYY-MM-DDTHH:MM:SSZ\t<row_count>\t<result>`, where `<result>` is `ok` when the database read completes and `error` otherwise. If the database read fails, `<row_count>` is `0`. If the database file does not exist, write `error: database not found` to stderr and exit with status 3. If the table name is not present in the database, write `error: table not found` to stderr and exit with status 4. If the database read fails after the table is found, write `error: query failed` to stderr and exit with status 5. On success, exit with status 0.
