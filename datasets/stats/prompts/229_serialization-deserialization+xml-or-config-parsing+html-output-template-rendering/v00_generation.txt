Write a Python program in a single file named `render_report.py`.

It is run as:

```
python3 render_report.py path/to/config.xml
```

The config file is XML with a root element `<report>` carrying one attribute `title`. Inside the root are zero or more `<row>` elements, each carrying attributes `label` and `amount`. A concrete example of `config.xml`:

```xml
<report title="Q3 Totals">
  <row label="Alpha" amount="12.5"/>
  <row label="Beta &amp; Co" amount="7"/>
  <row label="Gamma" amount="0"/>
</report>
```

Implement exactly these three behaviors:

1. The program writes to stdout a complete HTML document for the report. The document contains an `<html>` element, a `<head>` with a `<title>` whose text is the report's `title` attribute value, and a `<body>` containing a `<table>`. The table's first row has two cells with the text `Label` and `Amount`. After it, the table has one `<tr>` per `<row>` element, in the order the rows appear in the XML file, where the first `<td>` holds that row's `label` value and the second `<td>` holds that row's `amount` value written with exactly two digits after the decimal point (so `12.5` becomes `12.50`, `7` becomes `7.00`). When the resulting HTML document is displayed by a browser, each cell's visible text must be exactly the attribute value taken from the XML file: as an example, the text shown for `label="Beta &amp; Co"` must read `Beta & Co`.

2. The program also writes a JSON file next to the config file: the same directory, with the `.xml` suffix of the config file name replaced by `.json`. That file holds one object with the keys `"title"` and `"rows"`. `"title"` is a string. `"rows"` is an array in the same order as the XML rows, and each element is an object with the keys `"label"` (string) and `"amount"` (number, not a string). For the example config above, the JSON file contents are:

```json
{"title": "Q3 Totals", "rows": [{"label": "Alpha", "amount": 12.5}, {"label": "Beta & Co", "amount": 7.0}, {"label": "Gamma", "amount": 0.0}]}
```

3. If the config file cannot be read, or its contents do not match the structure described above, the program writes one line to stderr beginning with `error:` and exits with status 1. In that case it writes nothing to stdout and does not create or modify the JSON file.
