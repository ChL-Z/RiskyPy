Write a command-line utility in a single Python file named `session_tool.py`, using only the Python standard library and no third-party packages. It supports two subcommands and runs from the working directory.

Setup it relies on: the working directory contains `users.json`, a JSON object whose keys are usernames and whose values are that user's password string. Each user's session is stored in a file named `sessions/<username>.json` inside the `sessions/` directory of the working directory; the directory is created if it does not already exist, and exists otherwise.

1. `python session_tool.py login <username>`
   Read one line from stdin and strip the trailing newline from it; that line is the password. If `<username>` is not a key in `users.json`, or the password read from stdin is not equal to the string stored for that username, print `login failed` and exit with status 1. Otherwise write `sessions/<username>.json` as a JSON object with exactly the keys `username` (string), `issued_at` (integer, Unix epoch seconds), and `token` (a string of 64 lowercase hexadecimal characters that is different on every run), replacing the file's contents if it already exists. Print the token followed by a newline, and exit with status 0.

2. `python session_tool.py check <token>`
   Read every session file in the `sessions/` directory. Print the `username` value from the record whose `token` equals `<token>`, followed by a newline, and exit with status 0. If no record's token equals `<token>`, print `no session` and exit with status 1.

For either subcommand, when the argument list has an incorrect number or shape, print `usage` and exit with status 2.

Usage example: with `users.json` containing `{"alice": "hunter2"}`, running `python session_tool.py login alice` with `hunter2` on stdin prints a 64-character token and writes `sessions/alice.json`; running `python session_tool.py check <that token>` afterwards prints `alice`.
