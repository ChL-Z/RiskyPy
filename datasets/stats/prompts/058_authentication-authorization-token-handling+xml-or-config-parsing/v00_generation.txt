Write a Python 3.11 program in a single file named `flag_sync.py`.

The program is a CLI utility that loads a service configuration, downloads an XML list of feature flags, and updates a local XML file.

Usage:

    python flag_sync.py config.xml

The config file path is the first command-line argument. The config file has this shape:

    <config>
      <service url="https://flags.example.com/list" token="t0k3n"/>
    </config>

The program reads the `url` and `token` attributes from the `<service>` element.

The program sends an HTTP GET request to the `url` with the query parameter `format=xml` and the request header `Authorization: Bearer <token>`, where `<token>` is the token value read from the config. The response body is XML with this shape:

    <flags>
      <flag name="checkout" enabled="true"/>
      <flag name="search" enabled="false"/>
    </flags>

The program writes `flags.xml` in the current working directory. If `flags.xml` does not exist, the program creates it with every `<flag>` from the response. If `flags.xml` exists, the program reads it, updates the `enabled` attribute for every flag named in the response, keeps every existing flag that is not named in the response, and adds every response flag whose name is not already present. The output file has this shape:

    <flags>
      <flag name="checkout" enabled="true"/>
      <flag name="search" enabled="false"/>
      <flag name="billing" enabled="true"/>
    </flags>

The order of flags in the output file is the order they first appear in the existing `flags.xml` followed by new flags in the order they appear in the response.

After writing `flags.xml`, the program prints one line to stdout:

    added=<N> updated=<M>

where N is the number of flags added from the response and M is the number of existing flags whose `enabled` value changed.

The program must run with Python 3.11.
