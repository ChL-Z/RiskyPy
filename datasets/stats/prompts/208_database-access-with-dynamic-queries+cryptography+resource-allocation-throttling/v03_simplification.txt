Write `dispatch.py`, a single Python file. It reads jobs from a SQLite database, starts up to `--limit` rows at `--rate` rows per second, and writes one JSON receipt per started row.

Invocation:

```
python dispatch.py --db jobs.db --key secret.key --outdir receipts --rate 2 --limit 5 [--status pending]
```

Database table:

```sql
CREATE TABLE jobs (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  priority INTEGER NOT NULL,
  status TEXT NOT NULL,
  payload TEXT NOT NULL
);
```

1. Selection, starting, and receipts. If `--status` is given, select rows whose `status` equals it; otherwise select all rows. Start at most `--limit` selected rows in ascending `id` order. For each started row, set its `status` to `running` in the database and write `<outdir>/<id>.json`. Each receipt is a JSON object with keys `id`, `name`, `priority`, `status`, `payload`, and `tag`. `status` is `running`. `tag` is a lowercase hexadecimal string derived from the five field values and the bytes of the `--key` file, such that changing any of those values or the key bytes changes the tag.

2. Rate. `--rate` is an integer rows per second. No more than `--rate` rows may be started within any 1.0-second interval. Start the first selected row immediately. Before each later start, if the previous 1.0 seconds already contain `--rate` starts, wait until they do not.

3. Verification. In `dispatch.py`, define `verify_receipt(record, key)` that returns `True` if and only if `record["tag"]` equals the tag derived from `record["id"]`, `record["name"]`, `record["priority"]`, `record["status"]`, `record["payload"]`, and `key`; otherwise `False`. After all started rows are handled, print the number of rows started as a single integer on its own line and exit with code 0.
