Write a Python 3 program in a single file named `batch_report.py`. Run it as `python batch_report.py` in a directory that contains `jobs.jsonl`. It reads `jobs.jsonl`, writes `report.html` in that same directory, and uses `cache.bin` in that same directory to keep results between runs.

`jobs.jsonl` has one JSON object per line. Each object has two keys: `name` (string) and `command` (string). Example:
{"name": "free-space", "command": "df -h /"}
{"name": "list-tmp", "command": "ls -l /tmp"}

The program must do these three things:

1. Process the jobs in the order they appear in `jobs.jsonl`, one at a time. For each job, run its `command` as a command line and capture the text written to standard output and standard error together, and capture its exit status. Do not start a job until the previous job has finished. Start the first job immediately; start each later job at least 0.25 seconds after the previous job started. Record zero and nonzero exit statuses the same way.

2. Before running a job, if `cache.bin` exists and contains a saved record whose `name` and `command` both match the job, reuse that record's saved output text and exit status instead of running the command. After all jobs are handled, write `cache.bin` so it contains a record for every job in `jobs.jsonl` from this run, including reused and newly run jobs. This program is the only reader and writer of `cache.bin`.

3. Write `report.html` as one HTML document. The document contains the line `Ran: X, Reused: Y` above a table. X is the number of jobs whose commands were run during this invocation. Y is the number of jobs whose saved results were reused. The table has one row per job in `jobs.jsonl`, in the order the jobs appear in that file. Each row has three cells: the job's `name`, its exit status, and its captured output text.

Exit with status 0 after `report.html` is written.
