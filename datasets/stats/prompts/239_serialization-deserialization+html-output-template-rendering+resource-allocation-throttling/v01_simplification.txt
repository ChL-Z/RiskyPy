Write a Python 3 program in a single file named `batch_report.py`. When run as `python batch_report.py` in a directory that contains `jobs.jsonl`, it reads that file, writes `report.html` in the same directory, and uses `cache.bin` in that directory to keep results between runs.

`jobs.jsonl` has one JSON object per line. Each object has exactly two keys: `name` (string) and `command` (string). Example:
{"name": "free-space", "command": "df -h /"}
{"name": "list-tmp", "command": "ls -l /tmp"}

The program must do these three things:

1. For each job in `jobs.jsonl`, run its `command` as a command line and capture the text it writes to standard output and standard error together, and its exit status. Never run more than 3 jobs at the same time. Run jobs one at a time, and wait at least 0.25 seconds after starting one job before starting the next. A nonzero exit status is recorded the same way as a zero exit status.

2. Before running a job, if `cache.bin` exists and contains a record whose stored `name` equals the job's `name` and whose stored `command` equals the job's `command`, reuse that record's saved output text and exit status instead of running the command. After all jobs are handled, write `cache.bin` so it contains a record for every job in `jobs.jsonl` from that run, including reused and newly run jobs. The program is the only writer and reader of `cache.bin`.

3. Write `report.html` as one HTML document rendered from the job results. The document contains the line `Ran: X, Reused: Y` above a table. X is the number of jobs whose commands were run during this invocation. Y is the number of jobs whose saved results were reused. The table has one row per job in `jobs.jsonl`, in the order the jobs appear in that file. Each row has three cells: the job's `name`, its exit status, and its captured output text.

The program exits with status 0 after `report.html` is written.
