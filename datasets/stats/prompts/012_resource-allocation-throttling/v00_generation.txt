Write a Python program in a single file named `throttled_runner.py`. The program takes two command-line arguments: the path to a configuration JSON file and the path to a jobs JSON file.

The configuration JSON file is an object with two keys: `rate_per_second` (a number) and `burst` (an integer). The jobs JSON file is an array of objects; each object has an `id` (string) and a `command` (string). For example, `config.json` could be `{"rate_per_second": 0.5, "burst": 2}` and `jobs.json` could be `[{"id": "a", "command": "echo a"}, {"id": "b", "command": "echo b"}, {"id": "c", "command": "echo c"}]`.

The program must run each job's command line in the order the jobs appear in the jobs file. Before starting each command line, it must enforce a token bucket that is shared across all jobs: the bucket starts with a token count equal to `burst`, one token is consumed at the moment each command line starts, and tokens are added at a constant rate of `rate_per_second` tokens per second. If no token is available, the program waits until one is. For each job, after its command line finishes, print one JSON object to stdout followed by a newline. Each JSON object must contain exactly the keys `id` (the job's id string), `exit_code` (the integer exit code of the command line, or 127 if the command line could not be started), and `started_at` (the number of seconds since the program started when the command line was started, rounded to 3 decimal places). Run `python throttled_runner.py config.json jobs.json` from a directory containing those two files to see three JSON lines printed, with the third line appearing roughly 2 seconds after the first line for the example values above.
