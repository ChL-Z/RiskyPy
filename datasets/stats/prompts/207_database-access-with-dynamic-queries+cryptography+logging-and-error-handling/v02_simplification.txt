Write a single Python file named `export_events.py`. It is run as:

`python export_events.py --db DB_PATH --key KEY_PATH --log LOG_PATH [--level LEVEL]`

`--db`, `--key`, and `--log` are required. `--level` is optional. The SQLite database file contains a table named `events` with columns `id` INTEGER, `ts` TEXT in ISO-8601 UTC form, `level` TEXT, and `message` TEXT.

1. Select rows from `events`: if `--level` is supplied, select rows where `level` equals it exactly; otherwise select all rows. Emit selected rows in ascending `id` order. For each row, write one JSON object per line to stdout and write nothing else to stdout. Each object has exactly the keys `id`, `ts`, `level`, `message`, and `tag`. `tag` is a lowercase hexadecimal string computed from the raw bytes of the key file together with the values of `id`, `ts`, `level`, and `message`: equal `id`, `ts`, `level`, `message`, and key file bytes must produce the same `tag`, while changing any one of those four values or the key file bytes must change the `tag`.

2. Append exactly one line to the file named by `--log` per run. The line is the current UTC instant formatted as `YYYY-MM-DDTHH:MM:SSZ`, a space, `rows=<count>`, a space, and either `status=ok` or `status=error msg=<text>`. `<count>` is the number of JSON lines written to stdout. `<text>` is the failure description with every newline character replaced by one space.

3. If the database file cannot be opened, the `events` table cannot be read, or the key file cannot be read, write no lines to stdout, append a log line with `rows=0` and `status=error`, and exit with status 1. Otherwise append a log line with `status=ok` and exit with status 0.
