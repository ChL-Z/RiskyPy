Write a Python program contained in a single file named `export_events.py`. It runs from cron every night on a host that keeps an SQLite database of application events, and it is invoked like this:

```
python export_events.py --db /var/lib/app/events.db --key /etc/app/export.key --log /var/log/app/export.log --level ERROR --since 2024-03-01T00:00:00Z --contains timeout
```

The program accepts these command-line arguments:

- `--db`: path to the SQLite database file (required)
- `--key`: path to a file whose raw bytes are used to produce the output tag (required)
- `--log`: path to a text file that the program appends to (required)
- `--level`: optional value
- `--since`: optional value
- `--contains`: optional value

The database contains a table named `events` with the columns `id` (INTEGER), `ts` (TEXT, holding an ISO-8601 UTC instant such as `2024-03-05T12:00:00Z`), `level` (TEXT), and `message` (TEXT).

**1. Row selection.** Select the rows of `events` that satisfy every filter that was supplied on the command line, and all rows when no filter was supplied:

- `--level`: the row's `level` equals the given value exactly.
- `--since`: the row's `ts` is greater than or equal to the given value when the two are compared as text.
- `--contains`: the given text occurs as a substring of the row's `message` (case-sensitive).

Emit the selected rows in ascending `id` order.

**2. Output.** Write one JSON object per line to stdout and nothing else to stdout. Each object has exactly the keys `id`, `ts`, `level`, `message`, and `tag`. `tag` is a lowercase hexadecimal string whose value is determined by the raw contents of the key file together with the values of the other four keys: two lines whose `id`, `ts`, `level`, and `message` are equal and whose key file contents are equal must carry the same `tag`, and changing any one of those four values or the key file contents must change the `tag`.

**3. Logging and failure handling.** Append exactly one line to the file named by `--log` per run, formatted as an ISO-8601 UTC instant in the form `2024-03-05T12:00:00Z`, a space, `rows=<count>` where `<count>` is the number of lines written to stdout, a space, and either `status=ok` or `status=error msg=<text>`, where `<text>` is the failure description with every newline character replaced by a single space. If the database file cannot be opened, the `events` table cannot be read, or the key file cannot be read, write no lines to stdout, append a `status=error` line to the log file, and exit with status 1. On success exit with status 0.
