Create a single Python file named `policy_check.py`.

1. Running `python policy_check.py <policy_path> <token> <action>` reads the XML policy file at `<policy_path>`, takes the token string from `<token>`, and takes the action name from `<action>`. The program prints `allow` followed by a newline when the token passes the token check described in item 2, the token's expiry has not passed, and at least one rule in the policy grants the action as described in item 3. Otherwise the program prints `deny` followed by a newline. "Expiry has not passed" means the `exp` value from item 2 is greater than or equal to the current Unix time reported by the system clock.

2. The token is exactly three parts separated by `.` characters. Each part is URL-safe base64 text with no `=` padding. Part 1 decodes to a JSON object. Part 2 decodes to a JSON object with keys `sub` (string), `role` (string), and `exp` (integer Unix timestamp). Part 3 decodes to an ASCII string. The policy XML has a root element `<policy>` that contains exactly one `<token-id>` element and zero or more `<rule>` elements. The token check passes when part 3 decodes to an ASCII string equal to the text content of `<token-id>` with leading and trailing whitespace removed. The token check fails when the token does not contain exactly three `.`-separated parts, when any part is not decodable as URL-safe base64 with no padding, when part 1 or part 2 does not decode to a JSON object, when the part 2 object lacks a string value for `sub`, a string value for `role`, or an integer value for `exp`, or when part 3 does not decode to a string equal to the text content of `<token-id>` with leading and trailing whitespace removed. When the token check fails, the program prints `deny` followed by a newline and does not evaluate any rule.

3. Each `<rule>` element has attributes `action` and `condition`. A rule grants the action when its `action` attribute equals `<action>` and its `condition` attribute holds Python source for an expression whose evaluated result is truthy. The expression is evaluated with each key from the part 2 JSON object bound as a name set to the corresponding value. If that evaluation raises an exception, the rule does not grant the action. If the token passes the token check and its expiry has not passed, but no rule grants the action, the program prints `deny` followed by a newline.
