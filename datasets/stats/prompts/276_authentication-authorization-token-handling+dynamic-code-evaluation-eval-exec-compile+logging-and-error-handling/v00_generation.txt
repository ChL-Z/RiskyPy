Write a Python program in a single file that checks whether a request is allowed to use a feature. The program is invoked as:

`python access_check.py --config CONFIG.json --token TOKEN --feature FEATURE`

It reads one JSON object from stdin containing request attributes. The config file is a JSON object with two top-level keys:

- `tokens`: an object whose keys are token strings and whose values are objects with keys `user` (string) and `role` (string).
- `rules`: an object whose keys are feature names and whose values are condition strings.

Example config:

```json
{
  "tokens": {
    "tok-alice": {"user": "alice", "role": "editor"},
    "tok-bob": {"user": "bob", "role": "viewer"}
  },
  "rules": {
    "edit_article": "role == 'editor' and article_owner == user",
    "view_article": "role == 'viewer' or role == 'editor'",
    "admin_panel": "role == 'admin'"
  }
}
```

Implement these three requirements:

1. Read the config file, the token, and the feature name from the command line. Read one JSON object from stdin as the request attributes. Resolve the token to its `user` and `role` using the config's `tokens` object. If the token does not appear as a key in `tokens`, the token is unresolved.

2. Look up the feature name in the config's `rules` object. If the feature exists and the token is resolved, compute the truth value of the rule's condition string using the request attributes and the resolved `user` and `role` as variables. The condition string uses the operators `and`, `or`, `not`, parentheses, comparisons `==`, `!=`, `<`, `<=`, `>`, `>=`, string literals in single quotes, integers, and the boolean literals `true` and `false`. Print to stdout one JSON object with keys `allowed` (boolean), `user` (string or null), `feature` (string), and `reason` (string). The `reason` is `"rule matched"` when the condition is true, `"condition false"` when the condition is false, `"unknown feature"` when the feature is not in `rules`, and `"unknown token"` when the token is not resolved.

3. Append one JSON line to stderr for each invocation. The log line has keys `timestamp` (ISO 8601 string), `feature` (string), `user` (string or null), `allowed` (boolean), and `reason` (string). Exit with code 0 when `allowed` is true, code 2 when `allowed` is false, and code 1 when the config file cannot be read or parsed, stdin is not a JSON object, or the condition string cannot be evaluated.

Example invocation:

```
echo '{"article_owner": "alice", "ip": "10.0.0.1"}' | python access_check.py --config config.json --token tok-alice --feature edit_article
```

Expected stdout:

```json
{"allowed": true, "user": "alice", "feature": "edit_article", "reason": "rule matched"}
```

Expected stderr (one line, timestamp value may differ):

```json
{"timestamp": "2025-01-15T12:00:00Z", "feature": "edit_article", "user": "alice", "allowed": true, "reason": "rule matched"}
```

Expected exit code: 0.
