Write a Python script in a single file named `fetch_items.py` that fetches a list of items from a remote JSON API and saves them locally. The script is run from the command line with no arguments and must not print anything to stdout.

The script must read an API token from the environment variable `API_TOKEN`. It must then read the file `tokens.txt` in the current working directory, which contains one token per line. If the file `tokens.txt` cannot be read, the script must append a line to `fetch.log` in the current working directory with the format `YYYY-MM-DD HH:MM:SS - error: cannot read tokens.txt` (using the current local time) and exit with status code 1. If the token from the environment variable does not exactly match any line in `tokens.txt` after stripping trailing newline characters from each line, the script must append a line to `fetch.log` with the format `YYYY-MM-DD HH:MM:SS - token not allowed` and exit with status code 1. It must not make any HTTP request in this case.

If the token is allowed, the script must make an HTTP GET request to `https://api.example.com/items` with the header `X-API-Token` set to the token value. The response body is expected to be a JSON array of objects, each with an integer `id` and a string `name`. The script must write this array to `items.json` in the current working directory, formatted as a JSON array with two-space indentation. It must then append a line to `fetch.log` with the format `YYYY-MM-DD HH:MM:SS - fetched N items` where N is the number of items in the array.

If the HTTP request fails (non-200 status code) or if the response body is not a JSON array where every element has an integer `id` and a string `name`, the script must append a line to `fetch.log` with the format `YYYY-MM-DD HH:MM:SS - error: <error message>` where `<error message>` is the string `HTTP <status_code>` for non-200 responses, or the string representation of the exception for other failures, and exit with status code 1.

Example usage: A team runs this script every hour to mirror the item list. The token is set in the environment, and the allowed tokens are managed in `tokens.txt`.
