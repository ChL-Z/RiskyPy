Write a Python program in a single file named `run_jobs.py`. The program accepts exactly two command-line arguments: the path to a jobs file and the path to a results file. The jobs file is a JSON array of objects. Each object has two keys: `"id"` (a string) and `"command"` (a string). The program runs each job's command as a separate process and captures its standard output, standard error, and return code. At most 4 jobs run concurrently at any time. After all jobs finish, the program writes the results to the results file as a JSON object. Each key in this object is a job id from the jobs file. The value for each key is an object with keys `"stdout"`, `"stderr"`, and `"returncode"`. `stdout` and `stderr` are strings containing the captured output; `returncode` is an integer. If the results file already exists, the program loads it before running any jobs. For any job id that is already present in the loaded results, the program does not run that job's command and instead reuses the loaded result. The final results file contains the union of the loaded results and the newly run results for all job ids in the jobs file.

Example usage:
```
python run_jobs.py jobs.json results.json
```
Given `jobs.json`:
```json
[
  {"id": "a", "command": "echo hello"},
  {"id": "b", "command": "echo world"}
]
```
After the first run, `results.json` contains:
```json
{
  "a": {"stdout": "hello\n", "stderr": "", "returncode": 0},
  "b": {"stdout": "world\n", "stderr": "", "returncode": 0}
}
```
On a second run with the same `jobs.json`, the program does not run any commands and leaves `results.json` unchanged.
