Write a Python program in a single file named `throttled_cache.py`.

Usage from the command line:

    python throttled_cache.py <input_dir> <cache_dir> <max_per_second>

Process every regular file located directly inside `<input_dir>`, not recursing into subdirectories, in ascending order of filename byte sequence.

For each input file, do the following:

1. Compute a cache key: a lowercase hexadecimal string of exactly 64 characters derived from the byte content of the input file together with the byte content of the file `salt.bin` located in the current working directory.
2. If `<cache_dir>/<cache_key>.json` already exists, read that JSON object and take its `result` field as the file's result. This is a cache use, and it does not count against the rate bound below.
3. Otherwise, the file's result is the Base64 encoding (RFC 4648, with padding) of the input file's bytes. Write a JSON object with exactly the fields `source` (the input filename as a string) and `result` (the Base64 text) to `<cache_dir>/<cache_key>.json`. This is a computation.

Throughout the run, no more than `<max_per_second>` computations may be started within any window of 1000 milliseconds. Before starting a computation that would exceed this bound, wait until it would not.

For each input file, in the order described above, print one line to standard output:

    <input filename> <cache key> computed

when the computation path was taken, or

    <input filename> <cache key> cached

when the cached JSON file was used.

Example: with `salt.bin` containing the bytes `abc`, `input_dir` containing a single file `a.txt` whose content is `hello`, and `max_per_second` equal to `2`, the first run prints:

    a.txt <64 lowercase hex characters> computed

Running the same command a second time prints:

    a.txt <64 lowercase hex characters> cached
