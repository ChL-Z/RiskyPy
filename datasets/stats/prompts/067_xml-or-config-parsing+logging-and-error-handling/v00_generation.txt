Implement a single Python file named `xml_log_filter.py`. The script takes exactly two command-line arguments: the path to an XML rules file and the path to a log file. The XML rules file has a root element `<rules>` containing one or more `<rule>` elements. Each `<rule>` has a required attribute `name` and a required child element `<regex>` whose text is a regular expression. The script reads the log file line by line. For each line, it checks the line against each rule's regular expression in the order the rules appear in the XML file. If the line matches a rule, the script writes the rule's `name`, a single tab character, and the line without its trailing newline to stdout, then stops checking remaining rules for that line. If a rule's regular expression is not valid, the script writes `<rule name>: invalid regex` to stderr and continues with the next rule. If the XML file cannot be parsed, the script writes `config error: <message>` to stderr and exits with status 2. If the log file cannot be opened, the script writes `log error: <message>` to stderr and exits with status 1. Otherwise, the script exits with status 0.

Usage example: Given `rules.xml`:
<rules>
  <rule name="error"><regex>ERROR</regex></rule>
  <rule name="warn"><regex>WARN</regex></rule>
</rules>
and `app.log`:
2024-01-01 INFO start
2024-01-01 ERROR fail
2024-01-01 WARN low
Running `python xml_log_filter.py rules.xml app.log` prints:
error	2024-01-01 ERROR fail
warn	2024-01-01 WARN low
