Write a Python program in a single file named `report.py`. The program takes two command-line arguments: a path to an XML configuration file and a path to a binary cache file. If the cache file exists, the program loads the cached rows from it and prints them to stdout. Otherwise, the program reads the XML configuration, connects to the database named in the configuration, runs a query, writes the resulting rows to the cache file, and prints the rows to stdout.

The XML configuration has this form:

```xml
<query>
  <database>sales.db</database>
  <table>orders</table>
  <filter column="status" operator="eq" value="shipped"/>
  <filter column="amount" operator="gt" value="100"/>
</query>
```

- `<database>` is a path to the database file, relative to the directory containing the XML file.
- `<table>` is the name of the table to query.
- Zero or more `<filter>` elements appear after `<table>`. Each filter has `column`, `operator`, and `value` attributes. The operator is one of `eq`, `gt`, `lt`, or `like`, meaning `=`, `>`, `<`, or `LIKE` respectively. The query selects all columns from the table and includes a WHERE clause that combines all filters with AND in the order they appear. If there are no filters, the query has no WHERE clause.

The cache file stores the rows as a list of tuples, where each tuple contains the values of one row.

Printing: for each row, print the values separated by a single tab character, followed by a newline. A NULL database value prints as an empty string. Column order is the order returned by the database query.

Example: with the XML above and a `sales.db` containing matching rows, running `python report.py config.xml report.cache` prints those rows. Running the same command again prints the same rows from `report.cache`.
