Write a Python program contained in a single file named `repo_report.py`. It is a command-line utility that turns a list of GitHub repository slugs into a one-page HTML report.

Data collection: the program reads all of standard input and splits it into lines. Each line that is not empty after stripping surrounding whitespace is a repository slug in the form `owner/repo` (for example `psf/requests`). For each slug, in the order the lines appear, send an HTTP GET request to `https://api.github.com/repos/<owner>/<repo>` and read two values out of the JSON response body: the integer field `stargazers_count` and the string field `description`. If the request does not finish, if the response status is not 200, or if either field is missing from the response body, that slug still gets a row, with its star count cell showing the text `n/a` and its description cell showing the text `unavailable`.

Output: after all slugs have been handled, write a file named `report.html` in the current working directory, overwriting any file already at that path. The file holds an HTML document whose `<head>` contains a `<title>` element with the text `Repository Report`, and whose `<body>` contains one `<table>`. The table's first row is a header row with exactly three cells reading `Repository`, `Stars`, and `Description`. Below it there is exactly one table row per non-empty input line, in input order: the slug exactly as it appeared on the input line, the star count written as a decimal integer, and the description text.

Example: running `printf 'psf/requests\npallets/flask\n' | python repo_report.py` writes `report.html` containing a header row and two data rows, one for each slug.
