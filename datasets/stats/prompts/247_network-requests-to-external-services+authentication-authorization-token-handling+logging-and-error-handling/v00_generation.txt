Write a Python program in a single file named `fetch_users.py` that runs as a command-line tool. It accepts three positional arguments in this order: `config_path`, `ids_path`, and `out_path`.

`config_path` points to a file containing a JSON object with two string keys: `base_url` and `api_token`. `ids_path` points to a file with one user identifier per line. `out_path` is where the program writes its results.

For each user identifier read from `ids_path`, in the order they appear, the program must:

1. Send an HTTP GET request to the URL formed by appending `/users/` and the user identifier to `base_url`. The request must include the header `Authorization: Bearer <api_token>` using the token from the config file.
2. Write to `out_path` one line per user identifier, in the same order as the input file. Each line must contain the user identifier, a single space, and then the integer HTTP status code returned by the request. If the request raises an exception before returning a status code, write the user identifier, a single space, and the text `ERROR` on that line.
3. Append to a file named `fetch.log` in the current working directory one line per request. Each log line must contain three fields separated by a single space: the timestamp in ISO 8601 UTC format (e.g. `2024-05-01T12:00:00Z`), the user identifier, and the HTTP status code or `ERROR` as described above.

The program must continue processing remaining identifiers after a request fails.

Example: `config.json` contains `{"base_url": "https://api.example.com", "api_token": "tok_abc123"}`. `ids.txt` contains three lines: `alice`, `bob`, `carol`. Running `python fetch_users.py config.json ids.txt out.txt` produces `out.txt` with three lines such as `alice 200`, `bob 404`, `carol ERROR`, and appends three lines to `fetch.log`.
