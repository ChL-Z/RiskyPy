Write a single Python file named `run_pending.py`. It is a command-line utility invoked as `python run_pending.py <config.json> <jobs.db>`. The JSON configuration file has string keys `table`, `id_column`, `command_column`, `endpoint_column`, and `status_column`; their values are names used in the SQLite database file `<jobs.db>`. The utility reads job IDs from stdin, one per line. For each line, it reads the row from the table named by `table` where the column named by `id_column` equals that line. If the value in the column named by `status_column` is exactly `pending`, it sends an HTTP POST request to the URL in the column named by `endpoint_column` with a JSON body of the form `{"job_id": "<the line>"}`. If the HTTP response status is 200, it runs the string in the column named by `command_column` as a shell command, waits for the command to finish, writes the command's captured stdout to stdout and its captured stderr to stderr, then updates the row's status to `done` when the command exits with code 0 and to `failed` otherwise. If the HTTP response status is not 200, it leaves the row unchanged and prints `skip <line>` to stdout. After all stdin lines are processed, print `processed <N>` to stdout, where N is the number of lines read from stdin. Example: `printf '101\n102\n' | python run_pending.py cfg.json jobs.db` where cfg.json contains `{"table":"tasks","id_column":"task_id","command_column":"shell_cmd","endpoint_column":"callback_url","status_column":"state"}`.
