Write a Python program in a single file named `cacher.py` that serves URL bodies through a small on-disk cache.

It is invoked as `python cacher.py <urls_file> <cache_file>`. `<urls_file>` is a UTF-8 text file with one URL per line; lines that are empty after stripping trailing whitespace are skipped. `<cache_file>` is the JSON cache described below, and its directory is where the log file is written.

Requirements:

1. **Handling each URL.** For each URL in the order it appears in `<urls_file>`:
   - If the cache holds an entry for that URL whose `retrieved_at` is at most 300 seconds before the current time, print that entry's `body` to stdout exactly as stored, followed by a single newline, and do not retrieve the URL again.
   - Otherwise retrieve the URL's content as text, print it to stdout followed by a single newline, and record the result in the cache.
   - If retrieving a URL does not produce a body, print no line for that URL, record the failure in the log, and continue with the remaining URLs. After all URLs are processed, exit with status 1 if at least one retrieval failed, otherwise exit with status 0.

2. **Cache file and throttling.**
   - The cache file is a JSON object mapping each URL string to an object with the keys `retrieved_at` (a number: the epoch time in seconds, as a float, at which the body was obtained) and `body` (a string). Entries for URLs whose `retrieved_at` is older than 300 seconds are replaced when those URLs are handled.
   - The cache file is written out after each URL is handled, so that it reflects every URL processed so far even if the program stops before reaching the end of the list. If the cache file does not exist, or exists but does not hold the JSON object described here, start from an empty cache.
   - No more than 2 retrievals happen per second: the time between the start of one retrieval and the start of the next retrieval is at least 0.5 seconds. Cache hits are not throttled.

3. **Log file.** Append one line to `cacher.log` in the same directory as `<cache_file>` after each URL is handled. Each line is a JSON object with the keys `url` (the URL string), `event` (`"cache_hit"`, `"fetched"`, or `"failed"`), `size` (the number of characters in the body printed for that URL, or 0 for a failure), and `seconds` (a float: the wall-clock seconds spent handling that URL, measured from reading its line to writing its log line). The file is appended to, not truncated, across runs.

Usage context: a developer runs this to pull a fixed list of URLs repeatedly while iterating, and uses `cacher.log` to see which URLs came from the cache and which were retrieved. A sample `urls.txt`:

```
https://example.com/a
https://example.com/b
https://example.com/a
```

Running `python cacher.py urls.txt data/cache.json` prints three body lines (the third one served from the cache), exits 0 if both retrievals succeeded, and appends three lines to `data/cacher.log` such as:

```
{"url": "https://example.com/a", "event": "fetched", "size": 1256, "seconds": 0.31}
{"url": "https://example.com/b", "event": "fetched", "size": 980, "seconds": 0.22}
{"url": "https://example.com/a", "event": "cache_hit", "size": 1256, "seconds": 0.00}
```
