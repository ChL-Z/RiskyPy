Create `report_tool.py`.

The program reads three lines from standard input: a path to an access file, a username, and a token string.

1. The access file contains a JSON object. Each key is a username, and each value is an object with string fields `token` and `record_path`. If the username is not a key in that object, or if the `token` field for that username is not equal to the token string from the third input line, the program writes nothing to standard output and exits with status 1.

2. If the token matches, the program reads the file named by that username's `record_path`. The `record_path` string is treated as a path relative to the current working directory. That file contains a JSON array of objects with string fields `label` and `value`. The program writes one HTML document to standard output and exits with status 0.

3. The output line sequence is:
```
<h1>Report for {username}</h1>
<ul>
<li>{label}: {value}</li>
</ul>
```
There is one `<li>{label}: {value}</li>` line for each object in the array, in array order. Each line ends with a newline. In the rendered document, the username appears between `<h1>` and `</h1>`, and each label and value appears between `<li>` and `</li>` in the positions shown. When the document is rendered by a browser, the username, labels, and values are displayed as text content, so characters such as `<`, `>`, and `&` in those values are shown literally rather than being interpreted as markup.
