Create a single-file Python script called `report.py` that builds a finished HTML report from a SQLite 3 database and an HTML template. The script is run from the terminal with exactly four positional arguments, in this order:

```
python report.py <database_path> <template_path> <output_path> <filter_condition>
```

Argument meanings:

- `<database_path>`: path to a SQLite 3 database. It contains a `products` table with columns `name` (text), `price` (real), and `stock` (integer).
- `<template_path>`: path to a text file containing an HTML document.
- `<output_path>`: file path where the generated HTML should be written.
- `<filter_condition>`: a SQL predicate string used to choose rows from `products`, such as `price > 10 AND stock < 5`. Only rows matching this predicate should appear in the report.

The template includes exactly one line equal to `<!--ROW_START-->` and exactly one line equal to `<!--ROW_END-->`. The content located between those two marker lines must be copied once for every selected row. The marker lines themselves must not be included in the generated output. Inside each copied row section, every occurrence of `{{expr}}` must be replaced by the value produced by evaluating the arithmetic expression `expr` using the current row. The expression can refer to that row’s column names, for example `{{price * stock}}`, and the evaluated result must be converted to a string before insertion. Everything in the template outside the repeated section must be written to the output unchanged.

After processing, `report.py` must write the completed HTML to `<output_path>`. The whole implementation must live in one Python file.
