Create a self-contained CPython 3.11 script named `tickets.py` that uses only standard-library imports. It must support two command modes chosen by `sys.argv[1]`: `issue` and `verify`.

## `issue` mode

Run it as:

```
python tickets.py issue <client_id> <resource_id> <ttl_seconds>
```

If issuance is permitted, the program writes exactly one line to stdout: a token consisting only of non-whitespace printable ASCII characters. It exits with code 0.

The token must contain everything needed for later validation. A subsequent `verify` run must be able to determine validity using only the token, the provided resource id, the current Unix time, and a constant that is embedded directly in the script. It must not depend on any file or database created during the issuance run.

If two `issue` calls happen with the same `client_id`, same `resource_id`, and same `ttl_seconds` during the same Unix epoch second, they must still result in two distinct token strings.

## `verify` mode

Run it as:

```
python tickets.py verify <resource_id> <token>
```

The program writes exactly one line to stdout, either `valid` or `invalid`, and exits with code 0 in either case.

A token is `valid` only when the resource id encoded inside it matches the `<resource_id>` argument and the current Unix epoch second is strictly less than the token's issuance epoch second plus the token's original `ttl_seconds`. Otherwise, it is `invalid`.

## Issuance rate limiting

For every `client_id`, no more than 5 tokens may be issued during any 60-second window that ends at the current Unix epoch second.

Issuance timestamps must be preserved across runs in a file named `issue_log.json` located in the current working directory. The file must be a JSON object mapping each `client_id` to a list of Unix epoch timestamps in seconds for that client's previous issuances. After each successful issuance, append the current timestamp to that client's list and rewrite the file.

If an `issue` attempt would become the 6th issuance for that `client_id` within the currently active 60-second window, the program must write exactly one line to stdout, `throttled`, must leave the log file unchanged, and must exit with code 1.

Example session:

```
$ python tickets.py issue alice report-42 300
Qm9ndXM-7f3a91c4e8b0
$ python tickets.py verify report-42 Qm9ndXM-7f3a91c4e8b0
valid
$ python tickets.py verify report-99 Qm9ndXM-7f3a91c4e8b0
invalid
$ python tickets.py issue bob report-42 300
Zm9vYmFy-1d77c0a45e92
```

The token strings shown above are only illustrative; your program may output different characters.
