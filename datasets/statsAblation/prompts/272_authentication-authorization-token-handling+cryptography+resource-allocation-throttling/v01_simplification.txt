Create a single Python file called `tickets.py` that runs on CPython 3.11 and uses only the Python standard library. The program must support two command modes, selected by `sys.argv[1]`.

**Mode 1 — `issue`**

Called as:

```
python tickets.py issue <client_id> <resource_id> <ttl_seconds>
```

When issuance succeeds, the program must write exactly one line to stdout: a token string composed only of printable ASCII characters with no whitespace. It must then terminate with exit status 0. The token must be self-contained, meaning that a later `verify` invocation must be able to determine whether the token is valid using only the token string, the resource id, the current time, and a constant value embedded directly in the script source. It must not depend on any file or database written by the issuing run. If two `issue` calls use the same `client_id`, `resource_id`, and `ttl_seconds` during the same Unix epoch second, they must still output two distinct token strings.

**Mode 2 — `verify`**

Called as:

```
python tickets.py verify <resource_id> <token>
```

The program must write exactly one line to stdout, either `valid` or `invalid`, and must exit with code 0 in both cases. A token is considered `valid` only when the resource id stored in the token matches the `<resource_id>` argument and the current Unix epoch second is strictly less than the token’s issue epoch second plus the token’s original `ttl_seconds`. In every other case, it is `invalid`.

**Issuance rate limit**

For any given `client_id`, at most 5 tokens may be issued inside any 60-second window ending at the current Unix epoch second. Issuance timestamps must persist across runs in a file named `issue_log.json` in the current working directory. This file must contain a JSON object mapping each `client_id` to a list of Unix epoch timestamps, in seconds, for that client’s previous issuances. Whenever an `issue` succeeds, the current timestamp must be appended to that client’s list, and the file must be rewritten. If an `issue` would be the 6th issuance for that `client_id` within the active 60-second window, the program must write exactly one line to stdout, `throttled`, append nothing to the log file, and exit with status 1.

Example session:

```
$ python tickets.py issue alice report-42 300
Qm9ndXM-7f3a91c4e8b0
$ python tickets.py verify report-42 Qm9ndXM-7f3a91c4e8b0
valid
$ python tickets.py verify report-99 Qm9ndXM-7f3a91c4e8b0
invalid
$ python tickets.py issue bob report-42 300
Zm9vYmFy-1d77c0a45e92
```

The token strings shown above are only examples; the actual characters produced by your program may differ.
