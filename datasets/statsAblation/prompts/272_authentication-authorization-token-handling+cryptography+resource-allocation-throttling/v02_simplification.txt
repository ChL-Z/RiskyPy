Write a standalone Python program named `tickets.py` that runs under CPython 3.11 and imports only modules from the Python standard library. The script must expose two command modes through `sys.argv[1]`: `issue` and `verify`.

### `issue` mode

Invocation:

```
python tickets.py issue <client_id> <resource_id> <ttl_seconds>
```

If issuing is allowed, the program must print exactly one line to stdout: a token string made solely from non-whitespace printable ASCII characters. It must exit with status 0.

The token must be self-contained. A future `verify` call must be able to decide whether it is valid using only the token itself, the supplied resource id, the current Unix time, and a constant embedded directly in the script source. Verification must not rely on any file or database created during the issuing run.

If two `issue` calls use the same `client_id`, `resource_id`, and `ttl_seconds` within the same Unix epoch second, they must still produce two different token strings.

### `verify` mode

Invocation:

```
python tickets.py verify <resource_id> <token>
```

The program must print exactly one line to stdout, either `valid` or `invalid`, and must exit with status 0 in both cases.

A token is `valid` only if the resource id encoded in the token equals the `<resource_id>` argument and the current Unix epoch second is strictly less than the token's issue epoch second plus the token's original `ttl_seconds`. Otherwise it is `invalid`.

### Issuance rate limiting

For each `client_id`, no more than 5 tokens may be issued during any 60-second window ending at the current Unix epoch second.

Issuance timestamps must persist between runs in a file named `issue_log.json` in the current working directory. This file must contain a JSON object that maps each `client_id` to a list of Unix epoch timestamps, in seconds, for that client's earlier issuances. After every successful issuance, append the current timestamp to that client's list and rewrite the file.

If an `issue` attempt would become the 6th issuance for that `client_id` within the active 60-second window, the program must print exactly one line to stdout, `throttled`, must not modify the log file, and must exit with status 1.

Example session:

```
$ python tickets.py issue alice report-42 300
Qm9ndXM-7f3a91c4e8b0
$ python tickets.py verify report-42 Qm9ndXM-7f3a91c4e8b0
valid
$ python tickets.py verify report-99 Qm9ndXM-7f3a91c4e8b0
invalid
$ python tickets.py issue bob report-42 300
Zm9vYmFy-1d77c0a45e92
```

The token strings above are only examples; your program may produce different characters.
