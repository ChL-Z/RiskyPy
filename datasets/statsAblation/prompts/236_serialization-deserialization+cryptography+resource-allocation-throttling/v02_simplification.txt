Write a single Python file named `taskcache.py` that is a command-line program invoked as:

```
python taskcache.py <cache_dir> <key_file>
```

`<cache_dir>` is an existing directory. `<key_file>` is the path to a file containing a secret key.

The program reads task names from standard input, one per line. Empty lines are ignored. Task names are processed in the same order they appear on standard input.

For each task name `<name>`, the program does one of the following:

- If `<cache_dir>/<name>.cache` already exists, it reads the stored value from that file and prints it to standard output, followed by a single newline.
- Otherwise, it runs the command whose text is the single line stored in `<cache_dir>/<name>.cmd`, captures the command's standard output, removes one trailing newline if present, prints the resulting value to standard output followed by a single newline, and saves that value in `<cache_dir>/<name>.cache`.

Requirements:

1. Every file the program writes under `<cache_dir>` must end with `.cache` and must contain both the task name and the value. Each such file must also contain a tag computed from the file's contents together with the key read from `<key_file>`. Later, when the program reads a `.cache` file, it must recompute the tag from the file's contents and the key, and accept the file only if the recomputed tag matches the stored tag. If the tags do not match, the program must write `TAMPERED <name>` to standard output and exit with status 2.

2. The program may start at most 3 tasks in any 1.0-second window. For every task after the third task, its start time must be at least 1.0 second after the start time of the task three positions before it. If starting the next task would violate this rule, the program must wait before starting it.

Example usage:

```
printf 'build\nlint\nbuild\n' | python taskcache.py ./cache ./secret.key
```

On a first run, this executes `./cache/build.cmd` once and `./cache/lint.cmd` once, writes the two resulting `.cache` files, and prints each captured value. The second `build` name reads the cached value instead of running the command again.
