Create a Python program in a single file named `batch_fetch.py`. It takes two command-line arguments: the path to a credentials file, and the URL of a token endpoint. The credentials file contains a JSON object with the string keys `client_id`, `client_secret`, and `refresh_token`.

Implement exactly these two behaviors:

1. Obtain an access token. Send an HTTP POST to the token endpoint given as the second argument. The request body is `application/x-www-form-urlencoded` and carries the form fields `grant_type` (the value `refresh_token`), `refresh_token`, `client_id`, and `client_secret`, the last three taken from the credentials file. The token endpoint replies with a JSON object containing the string key `access_token`.

2. Download a batch of files. Read newline-separated URLs from stdin until EOF, ignoring empty lines. For each URL, send an HTTP GET request to that URL with the request header `Authorization: Bearer <access_token>`, and write the response body to a file in the current working directory. The file name is the last path segment of the URL, or `index` if that segment is empty, with `.bin` appended. Print the resulting file name on its own line after the file is written. If the request fails or the response status code is anything other than 200, print the URL followed by a single space and the word `failed`, and do not create a file for that URL.

Example: the credentials file `creds.json` contains `{"client_id": "abc", "client_secret": "shh", "refresh_token": "r1"}` and the token endpoint is `https://auth.example.com/token`. Running

    printf 'https://api.example.com/data/report1\nhttps://api.example.com/data/report2\n' | python batch_fetch.py creds.json https://auth.example.com/token

prints `report1.bin` and then `report2.bin`, and leaves those two files in the working directory holding the bodies returned by the two GET requests.
