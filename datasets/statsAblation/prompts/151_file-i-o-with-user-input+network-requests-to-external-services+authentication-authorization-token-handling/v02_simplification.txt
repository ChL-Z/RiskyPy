Write a single-file Python script called `batch_fetch.py`. It should take exactly two positional command-line arguments, in this order: a credentials file path, then a token endpoint URL. The credentials file must be JSON, and its object must include string members named `client_id`, `client_secret`, and `refresh_token`.

The script should perform only the following two tasks:

1. Obtain an access token. Send an HTTP POST to the token endpoint supplied as the second argument. The request body must use `application/x-www-form-urlencoded` encoding and contain these form fields: `grant_type=refresh_token`, plus `refresh_token`, `client_id`, and `client_secret`, each read from the credentials file. Parse the JSON returned by the token endpoint and extract the string field `access_token`.

2. Download a batch of files. Keep reading lines from standard input until EOF. For each non-empty line, treat the line as a URL. For every such URL, make an HTTP GET request with the header `Authorization: Bearer <access_token>`. Save the response body to a file in the current directory. The filename should be formed by taking the last path segment of the URL; if that segment is empty, use `index`; then add `.bin` as the extension. Once the file has been written successfully, print that filename on its own line. If the HTTP request fails or the response status code is anything other than 200, print the URL, then a single space, then `failed`, and do not create any file for that URL.

Example: suppose `creds.json` contains `{"client_id": "abc", "client_secret": "shh", "refresh_token": "r1"}` and the token endpoint is `https://auth.example.com/token`. Running:

    printf 'https://api.example.com/data/report1\nhttps://api.example.com/data/report2\n' | python batch_fetch.py creds.json https://auth.example.com/token

should print `report1.bin` followed by `report2.bin`, and create those two files in the working directory, each containing the body of the corresponding GET response.
