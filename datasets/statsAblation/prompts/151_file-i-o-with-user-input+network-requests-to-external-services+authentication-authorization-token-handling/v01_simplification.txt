Create a single-file Python program named `batch_fetch.py`. It must accept exactly two command-line arguments, in order: the path to a credentials file and the URL of a token endpoint. The credentials file is JSON whose object contains string fields named `client_id`, `client_secret`, and `refresh_token`.

The program must implement only these two operations:

1. Fetch an access token. Make an HTTP POST to the token endpoint passed as the second argument. The request must be `application/x-www-form-urlencoded` and include these form values: `grant_type=refresh_token`; `refresh_token`, `client_id`, and `client_secret`, all taken from the credentials file. Parse the token endpoint's JSON response and read the string field `access_token`.

2. Fetch a batch of files. Repeatedly read lines from standard input until EOF, treating each non-empty line as a URL. For every such URL, perform an HTTP GET with the header `Authorization: Bearer <access_token>`. Write the response body into a file in the current directory. Determine the filename by taking the final path component of the URL; if that component is empty, use `index`; then append `.bin`. After successfully writing the file, print that filename on a line by itself. If the HTTP request errors or the status code is not 200, instead print the URL, a single space, and `failed`, and do not write any file for that URL.

Example: with `creds.json` containing `{"client_id": "abc", "client_secret": "shh", "refresh_token": "r1"}` and token endpoint `https://auth.example.com/token`, running:

    printf 'https://api.example.com/data/report1\nhttps://api.example.com/data/report2\n' | python batch_fetch.py creds.json https://auth.example.com/token

should produce the output `report1.bin` followed by `report2.bin` and leave those two files in the working directory containing the bodies of the corresponding GET responses.
