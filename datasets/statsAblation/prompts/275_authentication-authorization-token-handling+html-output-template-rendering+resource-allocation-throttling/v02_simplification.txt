Write one Python file named `confirmer.py`.

The script must be executable with `python confirmer.py <state_dir>`. It should repeatedly read request lines from standard input until EOF, one request per line. For each non-empty line, it must emit exactly one line on standard output, in the same order as the input. Each request is either `issue <client_id> <username>` or `redeem <token>`. A single space separates fields, and no field value contains spaces.

When handling `issue <client_id> <username>`:

- If that same `client_id` has already been issued 3 tokens during the 60 seconds immediately before this request, output `throttled <client_id>` and do not create a token.
- Otherwise, create a token that is exactly 32 characters long and uses only `A-Za-z0-9`. Save the token, the username, the issue time, and an expiry time that is 900 seconds after issuance. Then output this line, substituting `{username}` and `{token}` with the request values:

  `<p>{username}: <a href="/confirm?token={token}">{token}</a></p>`

When handling `redeem <token>`:

- If the token exists, has not expired, and has not already been redeemed, mark it as redeemed and output `ok <username>`.
- In every other case, output `invalid`.

The program must keep its state at `<state_dir>/state`, so tokens issued in one run can still be redeemed in a later run.

Example usage:

```
mkdir /tmp/conf
printf 'issue c1 alice\nissue c1 bob\nissue c1 carol\nissue c1 dave\nredeem <token from the first output line>\n' | python confirmer.py /tmp/conf
```

The expected standard output consists of three HTML lines for alice, bob, and carol, then `throttled c1`, then `ok alice`. If the same command is run again with `redeem <that same token>`, it should output `invalid`.
