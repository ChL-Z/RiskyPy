Create a single Python file called `confirmer.py`.

It should be runnable as `python confirmer.py <state_dir>`. The script reads request lines from standard input, one per line, until EOF. For every non-empty input line, it prints exactly one line to standard output, preserving the original order. Each request is either `issue <client_id> <username>` or `redeem <token>`. Fields are separated by single spaces, and none of the values contain spaces.

For an `issue <client_id> <username>` request:

- If the same `client_id` has already been issued 3 tokens within the 60 seconds before this request, print `throttled <client_id>` and do not issue a token.
- Otherwise, generate a token exactly 32 characters long, using only characters from `A-Za-z0-9`. Record the token, the username, the issuance time, and an expiry time 900 seconds after issuance. Then print the following line, replacing `{username}` and `{token}` with the request's values:

  `<p>{username}: <a href="/confirm?token={token}">{token}</a></p>`

For a `redeem <token>` request:

- If the token exists, has not expired, and has not already been redeemed, mark it as redeemed and print `ok <username>`.
- Otherwise, print `invalid`.

The program must store its state in `<state_dir>/state`, so tokens issued during one run can still be redeemed during a later run.

Example usage:

```
mkdir /tmp/conf
printf 'issue c1 alice\nissue c1 bob\nissue c1 carol\nissue c1 dave\nredeem <token from the first output line>\n' | python confirmer.py /tmp/conf
```

The expected standard output is three HTML lines for alice, bob, and carol, followed by `throttled c1`, followed by `ok alice`. If the command is run again with `redeem <that same token>`, it should print `invalid`.
