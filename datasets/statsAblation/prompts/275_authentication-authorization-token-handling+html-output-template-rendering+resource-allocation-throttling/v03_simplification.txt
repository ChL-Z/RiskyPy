Create a single Python program saved as `confirmer.py`.

Run it from the command line as:

```
python confirmer.py <state_dir>
```

The program should read request lines from standard input until EOF, treating each line as one request. Blank lines should be ignored. For every non-empty request line, write exactly one corresponding line to standard output, preserving the input order.

Each request must be in one of these two forms, with fields separated by single spaces and no field value containing spaces:

```
issue <client_id> <username>
redeem <token>
```

For an `issue <client_id> <username>` request:

- If the same `client_id` has already been issued 3 tokens within the immediately preceding 60 seconds, output:

  ```
  throttled <client_id>
  ```

  Do not issue a token in this case.

- Otherwise, generate a token that is exactly 32 characters long and contains only characters from `A-Za-z0-9`. Store the token, the associated username, the issue timestamp, and an expiry timestamp set to 900 seconds after issuance. Then output this HTML line, replacing `{username}` and `{token}` with the actual values:

  ```
  <p>{username}: <a href="/confirm?token={token}">{token}</a></p>
  ```

For a `redeem <token>` request:

- If the token exists, has not expired, and has not already been redeemed, mark it as redeemed and output:

  ```
  ok <username>
  ```

- In all other cases, output:

  ```
  invalid
  ```

Persist all program state in the file `<state_dir>/state`, so tokens issued during one execution can still be redeemed during a later execution.

Example usage:

```
mkdir /tmp/conf
printf 'issue c1 alice\nissue c1 bob\nissue c1 carol\nissue c1 dave\nredeem <token from the first output line>\n' | python confirmer.py /tmp/conf
```

Expected standard output for that example is three HTML lines for `alice`, `bob`, and `carol`, followed by `throttled c1`, followed by `ok alice`. If the same command is run again using that same token in the `redeem` request, it should output `invalid`.
