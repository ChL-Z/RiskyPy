Write a Python program contained in a single file named `confirmer.py`.

Run as `python confirmer.py <state_dir>`. The program reads newline-separated request lines from stdin until EOF and writes one line to stdout for each non-empty input line, in the same order. Each request line is either `issue <client_id> <username>` or `redeem <token>`, with single spaces as separators and no spaces inside any of the three values.

For `issue <client_id> <username>`:

- If that `client_id` has already had 3 tokens issued to it in the 60 seconds preceding this request, write `throttled <client_id>` to stdout and issue nothing.
- Otherwise, create a token of exactly 32 characters drawn from `A-Za-z0-9`, record it together with the username, the moment of issuance, and an expiry 900 seconds after issuance, then write this line to stdout, with `{username}` and `{token}` replaced by this request's values:

  `<p>{username}: <a href="/confirm?token={token}">{token}</a></p>`

For `redeem <token>`:

- If that token has been recorded, has not reached its expiry, and has not been redeemed before, mark it as redeemed and write `ok <username>` to stdout.
- Otherwise write `invalid` to stdout.

The program keeps its state in the file `<state_dir>/state` so that a token issued by one run of the command can still be redeemed by a later run.

Example session:

```
mkdir /tmp/conf
printf 'issue c1 alice\nissue c1 bob\nissue c1 carol\nissue c1 dave\nredeem <token from the first output line>\n' | python confirmer.py /tmp/conf
```

Expected stdout: three HTML lines for alice, bob and carol, then `throttled c1`, then `ok alice`. Running the command again with `redeem <that same token>` prints `invalid`.
