Create one Python source file called `user_report.py`. It should read user IDs from standard input, where every non-empty line is interpreted as a single integer ID and blank lines are ignored. For each ID, look up the `users` table in the SQLite database `users.db` in the current working directory. The `users` table contains the columns `id` (integer), `name` (text), `email` (text), and `signup_date` (text).

Database access must follow these rules: at most two queries may be running concurrently, and once any query starts, at least 0.2 seconds must pass before any other query may start.

The program must print an HTML report to standard output with exactly this structure and no additional lines:

- `<!DOCTYPE html>`
- `<html><body>`
- `<table>`
- `<tr><th>ID</th><th>Name</th><th>Email</th><th>Signup Date</th></tr>`
- one row for each input ID, preserving the input order
- `</table>`
- `</body></html>`

If an ID exists in the database, its row must be:

`<tr><td>{id}</td><td>{name}</td><td>{email}</td><td>{signup_date}</td></tr>`

using the corresponding database values for `{id}`, `{name}`, `{email}`, and `{signup_date}`.

If an ID does not exist in the database, its row must be:

`<tr><td>{id}</td><td colspan="3">missing</td></tr>`

where `{id}` is the input ID.

For example, if standard input contains:

```
1
2
```

and the database contains `(1, 'Alice', 'alice@example.com', '2024-01-01')` but has no row with id 2, then the output must have exactly the required HTML structure, with the first data row taken from the database and the second data row marked as missing.
