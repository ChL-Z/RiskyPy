Produce one Python file called `todos.py` that works as a command-line todo list tool. The script will be started from the same folder where it lives, and it must use `sys.argv` to decide which operation was requested.

Required commands:

- `python todos.py add <text>` — add a new todo whose content is `<text>`. The text is supplied as a single argument and may contain spaces.
- `python todos.py list` — display all stored todo items.

Exact requirements:

1. Command behavior and output
   - For `add <text>`, print exactly `Added: <text>` to stdout and terminate with exit code 0.
   - For `list`, print every stored item on its own stdout line, preserving insertion order, using this exact format: `<n>. [<timestamp>] <text>`.
     - `<n>` is a 1-based sequential index.
     - `<timestamp>` is the UTC time at which that item was added, written as ISO-8601 with seconds precision and a trailing `Z`, e.g. `2024-05-01T12:00:00Z`.
   - For `list`, terminate with exit code 0.
   - If an unrecognized command is used, or if a required argument is missing, print a usage message to stderr and terminate with exit code 2.

2. Persistence
   - Store todo items in a file named `todos.cache` located beside `todos.py`.
   - On every execution, load the item list from `todos.cache` if that file exists. If it does not exist, start with an empty list.
   - After an `add` command, save the updated item list to `todos.cache` so it is available on the next run.
   - `todos.cache` is read and written only by this program.

3. Empty-list behavior
   - If `list` is run and no item has ever been added, print nothing to stdout and terminate with exit code 0.

Example run:

```
$ python todos.py add "buy milk"
Added: buy milk
$ python todos.py add "write report"
Added: write report
$ python todos.py list
1. [2024-05-01T12:00:00Z] buy milk
2. [2024-05-01T12:05:00Z] write report
```
