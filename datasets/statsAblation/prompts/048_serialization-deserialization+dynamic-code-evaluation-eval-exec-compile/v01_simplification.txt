Create a single Python file called `render_cache.py` that implements the following behavior.

1. The script accepts exactly one command-line argument: a file path.
   - If this path exists, it must be readable as a JSON object with exactly these keys:
     - `"template"`: a string
     - `"vars"`: an object mapping variable names to integers
   - Variable names use only letters, digits, and underscores, and they cannot begin with a digit.
   - The script uses the `"template"` string and the `"vars"` mapping from that JSON file.
   - If the path does not exist, the script instead reads a template string from stdin and uses the variable mapping stored in a binary file named `cache.bin` in the current working directory. This `cache.bin` is the file that the script writes in requirement 3.

2. In the template, every occurrence of the form `{{expr}}` must be replaced by the decimal representation of the integer result of evaluating `expr`.
   - `expr` may contain integer literals, variable names from the mapping, whitespace, parentheses, and the operators `+`, `-` (both binary and unary), and `*`.
   - All other characters in the template are copied unchanged.
   - The script writes the rendered template to stdout, followed by exactly one newline.
   - For example, if the template is `"Items: {{count}}; total={{ price * count }}"` and `vars` is `{"count": 3, "price": 7}`, then stdout must be exactly:
     `Items: 3; total=21`

3. After writing the rendered output to stdout in the JSON-file case where the path exists, the script must write a binary file named `cache.bin` in the current working directory.
   - This file must contain the variable mapping from the JSON file in a representation that the same script can read back later in the fallback case from requirement 1.
   - The script must not write `cache.bin` when it is using the fallback case.

Example run:

```
$ python render_cache.py data.json
Items: 3; total=21
$ rm data.json
$ echo '{{count+1}}' | python render_cache.py data.json
4
```
