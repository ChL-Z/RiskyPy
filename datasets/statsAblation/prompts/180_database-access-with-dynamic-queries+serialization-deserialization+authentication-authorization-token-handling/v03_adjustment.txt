Develop a standalone Python 3 command-line utility in one file called `report_tool.py`. The program must use only modules available in a standard Python 3 installation and must be runnable directly from a single entry point.

It must implement the following behavior:

1. Authentication and database setup
   - Get the value of the environment variable `APP_TOKEN`.
   - Open the SQLite database file `reports.db` located in the current working directory.
   - The database is assumed to contain these tables:
     - `sessions(token TEXT PRIMARY KEY, username TEXT, expires_at INTEGER)`
     - `users(username TEXT PRIMARY KEY, role TEXT)`
     - `sales(id INTEGER, region TEXT, amount INTEGER)`
   - Access is authorized only if every one of these conditions is met:
     - A row in `sessions` exists whose `token` equals `APP_TOKEN`.
     - That session’s `expires_at` value is greater than the current Unix timestamp.
     - The corresponding user’s `role` in `users` is `admin`.
   - If authorization does not succeed, write exactly `denied` to stderr and terminate with exit code 2.
   - If authorization succeeds, continue running.

2. Command-line query interface
   - Accept the options `--table`, `--where`, `--order-by`, and `--limit`.
   - If any of these options is not supplied, write exactly `usage` to stderr and terminate with exit code 1.
   - Otherwise, run a SELECT query using:
     - the `--table` value as the table name,
     - the `--where` value as the WHERE clause,
     - the `--order-by` value as the ORDER BY clause,
     - the integer form of the `--limit` value as the row limit.
   - Write the selected rows to stdout as a JSON array. Every row must be represented as a JSON object whose keys are column names and whose values are the corresponding row values.
   - For example, if the `sales` table contains `(1, 'east', 80)` and `(2, 'west', 250)`, then the command:
     `APP_TOKEN=tok123 python report_tool.py --table sales --where "amount > 100" --order-by "amount DESC" --limit 10`
     must output:
     `[{"id": 2, "region": "west", "amount": 250}]`

3. Cache behavior
   - Before executing the SELECT query, check for a file named `cache.bin` in the current working directory.
   - The `cache.bin` file contains a dictionary with exactly two keys:
     - `args`: the four argument string values in this order: `--table`, `--where`, `--order-by`, `--limit`.
     - `rows`: the list of row dictionaries, where each dictionary maps column names to values.
   - If `cache.bin` exists and its `args` value exactly equals the current four argument string values, output its `rows` value as a JSON array and exit without running the SELECT query.
   - Otherwise, run the SELECT query, write a dictionary containing the current `args` and `rows` values to `cache.bin`, and then output those `rows` as a JSON array.
