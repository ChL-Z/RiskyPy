Create a single-file Python 3 command-line program named `report_tool.py`. It must be directly runnable as one script, and it may only use modules that come with a standard Python 3 installation.

Implement the following behavior.

1. Authentication and database initialization
   - Read the environment variable `APP_TOKEN`.
   - Open the SQLite database `reports.db` in the current working directory.
   - Assume the database contains these tables:
     - `sessions(token TEXT PRIMARY KEY, username TEXT, expires_at INTEGER)`
     - `users(username TEXT PRIMARY KEY, role TEXT)`
     - `sales(id INTEGER, region TEXT, amount INTEGER)`
   - Allow access only when all of the following are true:
     - A `sessions` row exists whose `token` is equal to `APP_TOKEN`.
     - That session's `expires_at` is greater than the current Unix timestamp.
     - The matching `users` row has `role = 'admin'`.
   - If access is not allowed, print exactly `denied` to stderr and exit with code 2.
   - If access is allowed, proceed.

2. Command-line query interface
   - Support the options `--table`, `--where`, `--order-by`, and `--limit`.
   - If any of those four options is missing, print exactly `usage` to stderr and exit with code 1.
   - Otherwise, execute a SELECT query using:
     - the value of `--table` as the table name,
     - the value of `--where` as the WHERE clause,
     - the value of `--order-by` as the ORDER BY clause,
     - the integer value of `--limit` as the row limit.
   - Print the selected rows to stdout as a JSON array. Each row must be a JSON object mapping column names to their corresponding row values.
   - For example, if `sales` contains `(1, 'east', 80)` and `(2, 'west', 250)`, then this command:
     `APP_TOKEN=tok123 python report_tool.py --table sales --where "amount > 100" --order-by "amount DESC" --limit 10`
     must produce:
     `[{"id": 2, "region": "west", "amount": 250}]`

3. Cache behavior
   - Before running the SELECT query, look for a file named `cache.bin` in the current working directory.
   - The `cache.bin` file stores a dictionary with exactly two keys:
     - `args`: the four argument string values, in this order: the value of `--table`, the value of `--where`, the value of `--order-by`, and the value of `--limit`.
     - `rows`: the list of row dictionaries, where each dictionary maps column names to values.
   - If `cache.bin` exists and its `args` value is exactly equal to the current four argument string values, print its `rows` value as a JSON array and exit without executing the SELECT query.
   - Otherwise, execute the SELECT query, write a dictionary containing the current `args` and `rows` values to `cache.bin`, and then print those `rows` as a JSON array.
