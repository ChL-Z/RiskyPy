Create a standalone Python 3 script in one file called `report_tool.py`. It must rely only on the standard Python 3 installation and expose a single command-line entry point.

Behavior:

1. Authentication and database access
   - Read the environment variable `APP_TOKEN`.
   - Open the SQLite database `reports.db` located in the current working directory.
   - The database contains these tables:
     - `sessions(token TEXT PRIMARY KEY, username TEXT, expires_at INTEGER)`
     - `users(username TEXT PRIMARY KEY, role TEXT)`
     - `sales(id INTEGER, region TEXT, amount INTEGER)`
   - A request is authorized only if:
     - `sessions.token` equals `APP_TOKEN`,
     - `sessions.expires_at` is greater than the current Unix timestamp,
     - the role in `users` for the matching `sessions.username` is `admin`.
   - If authorization fails, write `denied` to stderr and exit with status code 2. If it succeeds, continue.

2. Command-line query interface
   - Accept these four command-line options: `--table`, `--where`, `--order-by`, and `--limit`.
   - If any of them is missing, write `usage` to stderr and exit with status code 1.
   - Otherwise, run a SELECT query:
     - table name comes from `--table`,
     - WHERE clause comes from `--where`,
     - ORDER BY clause comes from `--order-by`,
     - maximum number of returned rows is the integer value from `--limit`.
   - Output the resulting rows as a JSON array on stdout, with each row represented as a JSON object.
   - For example, if `sales` has rows `(1, 'east', 80)` and `(2, 'west', 250)`, then this command:
     `APP_TOKEN=tok123 python report_tool.py --table sales --where "amount > 100" --order-by "amount DESC" --limit 10`
     should print:
     `[{"id": 2, "region": "west", "amount": 250}]`

3. Cache behavior
   - Before executing the SELECT, check for a file named `cache.bin` in the current working directory.
   - `cache.bin` stores a dict with two keys:
     - `args`: the four argument string values in this order: `--table`, `--where`, `--order-by`, `--limit`.
     - `rows`: the list of row dictionaries mapping column names to values.
   - If `cache.bin` exists and its `args` exactly match the current four argument string values, print its `rows` as the JSON array and exit without running the SELECT.
   - Otherwise, run the SELECT, write a dict containing the current `args` and `rows` to `cache.bin`, and then print those `rows` as the JSON array.
