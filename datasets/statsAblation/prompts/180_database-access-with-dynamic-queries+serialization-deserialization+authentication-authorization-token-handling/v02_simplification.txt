Write a self-contained Python 3 program in a single file named `report_tool.py`. It may use only modules included in a standard Python 3 installation and must be runnable directly as a command-line tool from one entry point.

Required behavior:

1. Authentication and database connection
   - Read the `APP_TOKEN` environment variable.
   - Open the SQLite database `reports.db` in the current working directory.
   - Assume the database has these tables:
     - `sessions(token TEXT PRIMARY KEY, username TEXT, expires_at INTEGER)`
     - `users(username TEXT PRIMARY KEY, role TEXT)`
     - `sales(id INTEGER, region TEXT, amount INTEGER)`
   - Authorization succeeds only when all of these are true:
     - the row in `sessions` whose `token` equals `APP_TOKEN` exists,
     - that session's `expires_at` is greater than the current Unix timestamp,
     - the matching user's `role` in `users` is `admin`.
   - If authorization fails, print exactly `denied` to stderr and exit with status code 2.
   - If authorization succeeds, continue.

2. Command-line query API
   - Support four command-line options: `--table`, `--where`, `--order-by`, and `--limit`.
   - If any option is omitted, print exactly `usage` to stderr and exit with status code 1.
   - Otherwise execute a SELECT query where:
     - the table name is the value of `--table`,
     - the WHERE clause is the value of `--where`,
     - the ORDER BY clause is the value of `--order-by`,
     - the row limit is the integer value of `--limit`.
   - Print the selected rows to stdout as a JSON array. Each row must be a JSON object mapping column names to values.
   - Example: if table `sales` contains `(1, 'east', 80)` and `(2, 'west', 250)`, then running:
     `APP_TOKEN=tok123 python report_tool.py --table sales --where "amount > 100" --order-by "amount DESC" --limit 10`
     must print:
     `[{"id": 2, "region": "west", "amount": 250}]`

3. Cache handling
   - Before running the SELECT, look for a file named `cache.bin` in the current working directory.
   - `cache.bin` stores a dictionary with exactly two keys:
     - `args`: the four argument string values in this order: `--table`, `--where`, `--order-by`, `--limit`.
     - `rows`: the list of row dictionaries, where each dictionary maps column names to values.
   - If `cache.bin` exists and its `args` value exactly matches the current four argument string values, print its `rows` value as the JSON array and exit without executing the SELECT.
   - Otherwise, execute the SELECT, write a dictionary containing the current `args` and `rows` to `cache.bin`, then print those `rows` as the JSON array.
