Write a standalone Python 3 command-line script called `report_tool.py`. It must be a single file that can be run directly, and it must rely only on modules available in a normal Python 3 standard library installation.

Implement the program as follows.

1. Authentication and database setup
   - Read the `APP_TOKEN` environment variable.
   - Open the SQLite database file `reports.db` located in the current working directory.
   - The database can be assumed to already contain these tables:
     - `sessions(token TEXT PRIMARY KEY, username TEXT, expires_at INTEGER)`
     - `users(username TEXT PRIMARY KEY, role TEXT)`
     - `sales(id INTEGER, region TEXT, amount INTEGER)`
   - Grant access only if all of these conditions hold:
     - There is a `sessions` row whose `token` equals `APP_TOKEN`.
     - That session has `expires_at` greater than the current Unix timestamp.
     - The corresponding `users` row has `role = 'admin'`.
   - If access is not granted, write exactly `denied` to stderr and terminate with exit code 2.
   - If access is granted, continue running.

2. Command-line query interface
   - Accept the options `--table`, `--where`, `--order-by`, and `--limit`.
   - If any one of these four options is absent, write exactly `usage` to stderr and terminate with exit code 1.
   - Otherwise, run a SELECT query using:
     - the provided `--table` value as the table name,
     - the provided `--where` value as the WHERE clause,
     - the provided `--order-by` value as the ORDER BY clause,
     - the integer value of `--limit` as the row limit.
   - Send the selected rows to stdout as a JSON array. Each row must be represented as a JSON object whose keys are column names and whose values are the row values.
   - For instance, if the `sales` table contains `(1, 'east', 80)` and `(2, 'west', 250)`, then this command:
     `APP_TOKEN=tok123 python report_tool.py --table sales --where "amount > 100" --order-by "amount DESC" --limit 10`
     must output:
     `[{"id": 2, "region": "west", "amount": 250}]`

3. Cache behavior
   - Before executing the SELECT query, check whether a file named `cache.bin` exists in the current working directory.
   - The `cache.bin` file holds a dictionary with exactly two keys:
     - `args`: the four argument string values in this order: `--table`, `--where`, `--order-by`, and `--limit`.
     - `rows`: the list of row dictionaries, where each dictionary maps column names to values.
   - If `cache.bin` exists and its `args` value exactly matches the current four argument string values, output its `rows` value as a JSON array and exit without running the SELECT query.
   - Otherwise, run the SELECT query, save a dictionary containing the current `args` and `rows` values to `cache.bin`, and then output those `rows` as a JSON array.
