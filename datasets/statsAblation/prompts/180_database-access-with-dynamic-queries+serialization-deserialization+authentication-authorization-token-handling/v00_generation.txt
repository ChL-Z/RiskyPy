Write a Python 3 program in a single file named `report_tool.py`. The program has one command-line entry point and must run with only the Python 3 installation on the machine.

Requirements:

1. The program reads a session token from the environment variable `APP_TOKEN` and opens the SQLite database file `reports.db` in the current working directory. The database has these tables:
   - `sessions(token TEXT PRIMARY KEY, username TEXT, expires_at INTEGER)`
   - `users(username TEXT PRIMARY KEY, role TEXT)`
   - `sales(id INTEGER, region TEXT, amount INTEGER)`

   The token is accepted only when `sessions.token` equals the value of `APP_TOKEN`, `sessions.expires_at` is greater than the current Unix timestamp, and the `users.role` for `sessions.username` is `admin`. If the token is not accepted, print `denied` to stderr and exit with status 2. If accepted, continue.

2. The program accepts four command-line arguments: `--table`, `--where`, `--order-by`, and `--limit`. If any is absent, print `usage` to stderr and exit with status 1. Otherwise, it runs a SELECT from the table named by `--table`, applies the expression given by `--where` as the WHERE clause, orders the result by the expression given by `--order-by`, and returns at most the integer given by `--limit` rows. Each row is printed as one JSON object inside a JSON array on stdout. For example, with `sales` containing rows `(1, 'east', 80)` and `(2, 'west', 250)`, the command:

   `APP_TOKEN=tok123 python report_tool.py --table sales --where "amount > 100" --order-by "amount DESC" --limit 10`

   prints:

   `[{"id": 2, "region": "west", "amount": 250}]`

   Before running the SELECT, the program looks for a file named `cache.bin` in the current working directory. The file stores a dict with two keys: `args`, the four argument string values in the order `--table`, `--where`, `--order-by`, `--limit`, and `rows`, the list of row dicts mapping column name to value. If `cache.bin` exists and its `args` equal the current four argument string values, the program prints its `rows` as the JSON array and exits without running the SELECT. Otherwise, after the SELECT, the program writes a dict with the current `args` and `rows` to `cache.bin`, then prints the `rows` as the JSON array.
