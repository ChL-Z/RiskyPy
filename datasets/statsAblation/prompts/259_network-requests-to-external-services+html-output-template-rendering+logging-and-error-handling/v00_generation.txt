Write a Python script in a single file named `status_report.py`. The script reads a JSON file named `services.json` from the current working directory. This file contains a JSON array of objects, each with a `name` key (string) and a `url` key (string). The script sends an HTTP GET request to each `url` with a 5-second timeout, measures the time from sending the request until the response headers are received, and records the HTTP status code. It then writes an HTML file named `report.html` containing an HTML table with the header row `<tr><th>Service</th><th>URL</th><th>Status</th><th>Time (ms)</th></tr>` followed by one data row per service, in the same order as in `services.json`. For a successful request, the data row cells contain: the service `name`, the `url`, the HTTP status code as an integer, and the measured time in milliseconds as an integer. For a failed request (timeout, connection error, or any other exception), the data row cells contain: the service `name`, the `url`, the string `ERROR`, and the exception message. For each failed request, the script also prints a line to standard error in the format `[ERROR] <name>: <message>` where `<name>` is the service name and `<message>` is the exception message. The script processes all services even if some fail. The script exits with status code 1 if at least one request failed, and 0 otherwise.

Example: if `services.json` contains `[{"name": "Example", "url": "https://example.com"}, {"name": "Python", "url": "https://python.org"}]`, then running `python status_report.py` produces `report.html` with a table containing two rows: one for Example with status 200 and a time in milliseconds, and one for Python with status 200 and a time in milliseconds. If `https://python.org` were unreachable, the Python row would show `ERROR` and the exception message, and stderr would show `[ERROR] Python: <message>`.
