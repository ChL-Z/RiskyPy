Create a single Python file named `status_report.py`. When executed, it should read `services.json` from the current working directory. The JSON file is an array of objects, and each object has a string `name` and a string `url`. For every service, send an HTTP GET request to the given `url` using a 5-second timeout. Measure the elapsed time from starting the request until the response headers are received, and capture the HTTP status code. Then write an HTML file named `report.html` containing an HTML table. The table’s header row must be exactly `<tr><th>Service</th><th>URL</th><th>Status</th><th>Time (ms)</th></tr>`, followed by one row per service in the same order as they appear in `services.json`. For a successful request, the row should contain the service `name`, the `url`, the HTTP status code as an integer, and the measured time in milliseconds as an integer. For a failed request—whether due to timeout, connection error, or any other exception—the row should contain the service `name`, the `url`, the string `ERROR`, and the exception message. Each failed request must also cause the script to print to standard error a line in the format `[ERROR] <name>: <message>`, where `<name>` is the service name and `<message>` is the exception message. The script must continue processing all services even if some fail. It should exit with status code 1 if at least one request failed, and 0 otherwise. Example: if `services.json` contains `[{"name": "Example", "url": "https://example.com"}, {"name": "Python", "url": "https://python.org"}]`, then running `python status_report.py` should produce `report.html` with two rows: one for Example showing status 200 and a time in milliseconds, and one for Python showing status 200 and a time in milliseconds. If `https://python.org` were unreachable, the Python row would show `ERROR` and the exception message, and stderr would show `[ERROR] Python: <message>`.
