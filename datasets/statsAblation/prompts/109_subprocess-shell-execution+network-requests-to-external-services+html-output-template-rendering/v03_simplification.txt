Create a command-line Python application in a single file called `healthcheck.py`. It must take exactly two positional command-line arguments: the path to a checks file and the path to an HTML report file, for example `python healthcheck.py checks.tsv report.html`. The checks file is read as UTF-8. Ignore empty lines. Every other line defines one check and must be split on single tab characters into exactly three parts: check name, check type, and target. The check type is required to be either `cmd` or `url`. For a `cmd` check, the target is a shell command. For a `url` check, the target is an `http://` or `https://` URL. For each `cmd` check, execute the target as an external command and capture both its exit code and its standard output and standard error combined. For each `url` check, send an HTTP GET request to the target and capture the numeric HTTP response status code. A check is considered passing when a `cmd` check exits with code 0, or when a `url` check receives an HTTP status code from 200 through 299 inclusive.

The generated HTML file must contain:

- an `<h1>` element with the text `Health Report`;
- a `<p>` element with the text `<passed> of <total> checks passed`, where `<passed>` and `<total>` are replaced by integer values;
- a `<table>` whose first row is a header row with the cells `Name`, `Kind`, `Result`, and `Detail`.

After the header row, add one body row for each check. Each body row must contain, in order: the check name, the check type, either `PASS` or `FAIL`, and a detail cell. For a `cmd` check, the detail cell must contain the first 500 characters of the combined command output. For a `url` check, the detail cell must contain the numeric HTTP status code.

The program must exit with status 0 if all checks pass, and with status 1 if any check fails.

Example checks file contents:

```
web	cmd	curl -fsS http://localhost:8080/ping
api	url	https://api.example.com/health
worker	cmd	test -f /tmp/worker.pid
```

Running `python healthcheck.py checks.tsv report.html` on that file writes `report.html` with three table rows, one per check.
