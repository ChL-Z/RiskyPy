Create a single self-contained Python script named `query_tool.py` that acts as a small command-line SQLite querying tool with caching. It is invoked as:

    python query_tool.py <spec.json> <database.db>

The script should read from the SQLite database `<database.db>` and print query results to standard output. The JSON file `<spec.json>` defines the query with these fields:

- `table`: string, the table name.
- `select`: list of column-name strings to return.
- `filters`: list of filter objects. Each filter contains `column` (string), `op` (one of `eq`, `ne`, `lt`, `le`, `gt`, `ge`, or `in`), and `value` (the comparison value).
- `order_by`: optional string column name for ascending sorting.
- `limit`: optional integer maximum number of rows.

Your program must implement exactly these three responsibilities:

1. Run the query.
   - Select the columns listed in `select` from `table`.
   - Keep only rows satisfying every filter in `filters`.
   - Operator meanings:
     - `eq`: equal to `value`
     - `ne`: not equal to `value`
     - `lt`, `le`, `gt`, `ge`: less than, less than or equal, greater than, greater than or equal to `value`
     - `in`: column value appears in the JSON array given as `value`
   - If `order_by` is present, sort ascending by that column.
   - If `limit` is present, return at most that many rows.
   - Apply `order_by` before `limit`.

2. Print the rows.
   - For each returned row, print exactly one stdout line containing a JSON object.
   - The JSON object must contain only the keys from `select`, in the same order, with the row values.
   - Convert SQL `NULL` to JSON `null`, integer/real values to JSON numbers, and text values to JSON strings.

3. Cache the result.
   - After a successful query, create a cache file at the spec file path plus `.cache` (for example, `sales.json` becomes `sales.json.cache`).
   - This cache file is binary and intended to be read/written only by this program.
   - It stores the current bytes of the spec file, the returned rows in order, and the column names.
   - On a later run, if the cache file exists and the spec-file bytes stored inside it are byte-for-byte identical to the current spec file contents, print the cached rows instead of querying the database.
   - Otherwise, run the query normally and rewrite the cache file.

Example behavior:

    $ cat sales.json
    {"table": "sales", "select": ["region", "amount"], "filters": [{"column": "amount", "op": "ge", "value": 100}, {"column": "region", "op": "in", "value": ["north", "west"]}], "order_by": "amount", "limit": 2}
    $ python query_tool.py sales.json sales.db
    {"region": "west", "amount": 120.5}
    {"region": "north", "amount": 340.0}
    $ python query_tool.py sales.json sales.db
    {"region": "west", "amount": 120.5}
    {"region": "north", "amount": 340.0}

All functionality must be contained in `query_tool.py`; no additional files should be required.
