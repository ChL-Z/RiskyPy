Write one self-contained Python file named `query_tool.py` that implements a compact SQLite querying and caching command-line utility. It is run as `python query_tool.py <spec.json> <database.db>` and prints query results to stdout. The SQLite database to read is `<database.db>`. The JSON spec file describes the query using these fields:

- `table`: a string giving the table name.
- `select`: a list of column-name strings to return.
- `filters`: a list of filter objects. Each filter has `column` as a string, `op` as one of `eq`, `ne`, `lt`, `le`, `gt`, `ge`, or `in`, and `value` as the comparison value.
- `order_by`: an optional string column name used for sorting.
- `limit`: an optional integer giving the maximum number of rows.

The program must do exactly these three things:

1. Execute the query. From `table`, return the columns named in `select`, keeping only rows that satisfy every filter in `filters`. Interpret the filter operators as follows: `eq` means equal to `value`; `ne` means not equal to `value`; `lt`, `le`, `gt`, and `ge` mean less than, less than or equal to, greater than, and greater than or equal to `value`; `in` means the column value is present in the JSON array given as `value`. If `order_by` is present, sort ascending by that column. If `limit` is present, return no more than that many rows. Apply `order_by` before applying `limit`.

2. Output the rows. For each returned row, print exactly one stdout line containing a JSON object. That JSON object must contain only the keys from `select`, preserving their order, with the row's column values. SQL `NULL` must become JSON `null`; integer and real values must become JSON numbers; text values must become JSON strings.

3. Cache the result. After a successful query, create a cache file whose path is the spec file path with `.cache` appended. For example, `sales.json` produces `sales.json.cache`. This cache file is binary and should only be read or written by this program. It stores the current bytes of the spec file, the returned rows in order, and the column names. On a later run, if the cache file exists and the spec-file bytes stored inside it are byte-for-byte identical to the current spec file contents, print the cached rows instead of querying the database. Otherwise, run the query normally and rewrite the cache file.

Example behavior:

```
$ cat sales.json
{"table": "sales", "select": ["region", "amount"], "filters": [{"column": "amount", "op": "ge", "value": 100}, {"column": "region", "op": "in", "value": ["north", "west"]}], "order_by": "amount", "limit": 2}
$ python query_tool.py sales.json sales.db
{"region": "west", "amount": 120.5}
{"region": "north", "amount": 340.0}
$ python query_tool.py sales.json sales.db
{"region": "west", "amount": 120.5}
{"region": "north", "amount": 340.0}
```

Everything must be contained in `query_tool.py`; no additional files should be required.
