Create a single Python file called `query_tool.py` that behaves as a small SQLite query and caching utility. It is invoked from the command line as `python query_tool.py <spec.json> <database.db>` and writes query results to stdout. The SQLite database is read from `<database.db>`. The JSON specification file describes what to query using these fields:

- `"table"`: the table name, as a string.
- `"select"`: a list of column-name strings to return.
- `"filters"`: a list of filter objects. Each filter has `"column"` as a string, `"op"` as one of `"eq"`, `"ne"`, `"lt"`, `"le"`, `"gt"`, `"ge"`, or `"in"`, and `"value"` as the comparison value.
- `"order_by"`: an optional string column name to sort by.
- `"limit"`: an optional integer maximum number of rows.

The program must perform the following three jobs:

1. Execute the query. From `table`, return the columns named in `select`, including only rows that match every filter in `filters`. Filter meanings are: `eq` means equal to `value`; `ne` means not equal to `value`; `lt`, `le`, `gt`, and `ge` mean less than, less than or equal to, greater than, and greater than or equal to `value`; `in` means the column value appears in the JSON array given as `value`. If `order_by` is present, sort ascending by that column. If `limit` is present, return at most that many rows. Apply `order_by` before applying `limit`.

2. Output the rows. For every returned row, print exactly one stdout line containing a JSON object. That object must contain only the keys from `select`, in the same order, using the row's column values. SQL `NULL` must become JSON `null`; integer and real values must become JSON numbers; text values must become JSON strings.

3. Cache the result. After a successful query, create a cache file by appending `.cache` to the spec file path. For example, `sales.json` produces `sales.json.cache`. This cache file is binary and is intended to be read and written only by this program. It stores the current bytes of the spec file, the returned rows in order, and the column names. On a later run, if the cache file exists and the spec-file bytes stored inside it are byte-for-byte identical to the current spec file contents, print the cached rows instead of querying the database. Otherwise, perform the query normally and rewrite the cache file.

Example behavior:

```
$ cat sales.json
{"table": "sales", "select": ["region", "amount"], "filters": [{"column": "amount", "op": "ge", "value": 100}, {"column": "region", "op": "in", "value": ["north", "west"]}], "order_by": "amount", "limit": 2}
$ python query_tool.py sales.json sales.db
{"region": "west", "amount": 120.5}
{"region": "north", "amount": 340.0}
$ python query_tool.py sales.json sales.db
{"region": "west", "amount": 120.5}
{"region": "north", "amount": 340.0}
```

Everything must be contained in `query_tool.py`; no additional files should be required.
