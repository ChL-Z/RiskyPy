Create a single-file Python command-line tool named `throttle_report.py`. It is run as:

```
python throttle_report.py requests.csv report.html out.html --capacity 5 --refill-per-second 2.5
```

The tool reads a UTF-8 CSV file `requests.csv`, uses a UTF-8 HTML template `report.html`, and writes the result to `out.html`, exiting with status 0.

## Input CSV

`requests.csv` has this exact first line:

```
worker,request_id,timestamp_ms
```

Each following line contains three comma-separated fields:

- worker name
- request identifier
- integer timestamp in milliseconds

Rows are already ordered by non-decreasing `timestamp_ms`.

## HTML template

`report.html` is UTF-8 and contains these literal placeholders:

```
{{batch_id}}
{{total}}
{{accepted}}
{{rejected}}
{{rows}}
```

## Required behavior

### 1. Per-worker throttling

Maintain a separate token bucket for every distinct worker name.

- When a worker is first encountered, its bucket starts with `--capacity` tokens.
- Each bucket refills at `--refill-per-second` tokens per second and never exceeds `--capacity`.
- Process input rows in file order.
- Before processing a row for a worker at timestamp `t`, refill that worker’s bucket by:

```
(t - last_ms) * refill_per_second / 1000
```

capped at `--capacity`, where `last_ms` is the most recent timestamp previously processed for that same worker.

- For the first row belonging to a worker, treat `last_ms` as that row’s `t`, and treat the bucket as full before the refill calculation.
- After refilling, if the bucket has at least 1 token:
  - mark the row `accepted`
  - subtract 1 token
  - set the row’s `wait_ms` to `0`
- Otherwise:
  - mark the row `rejected`
  - leave the token count unchanged
  - set `wait_ms` to the smallest integer `m >= 0` such that refilling the bucket for `m` milliseconds at `--refill-per-second`, capped at `--capacity`, would bring the bucket to at least 1 token.

Example: with `--capacity 1` and `--refill-per-second 1`, two rows from the same worker at `t = 0` and `t = 500` produce the first row as `accepted` with `wait_ms = 0`, and the second row as `rejected` with `wait_ms = 500`.

### 2. Generated report

When writing `out.html`, replace every occurrence of each placeholder:

- `{{batch_id}}`: a lowercase hexadecimal string of exactly 64 characters computed from the raw bytes of `requests.csv`.
- `{{total}}`: decimal count of all input rows.
- `{{accepted}}`: decimal count of accepted rows.
- `{{rejected}}`: decimal count of rejected rows.
- `{{rows}}`: concatenation, in input file order, of one line per row in the form:

```
<tr><td>{worker}</td><td>{request_id}</td><td>{timestamp_ms}</td><td>{status}</td><td>{wait_ms}</td></tr>
```

followed by a newline. Here `{status}` is either `accepted` or `rejected`, and `{timestamp_ms}` and `{wait_ms}` are decimal integers.

Every other character from the template must be copied to the output unchanged.
