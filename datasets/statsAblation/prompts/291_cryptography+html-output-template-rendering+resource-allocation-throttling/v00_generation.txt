Write a Python program contained in a single file named `throttle_report.py`. It is a command-line utility invoked like this:

```
python throttle_report.py requests.csv report.html out.html --capacity 5 --refill-per-second 2.5
```

`requests.csv` is a UTF-8 CSV file. Its first line is exactly `worker,request_id,timestamp_ms`. Every later line has three comma-separated fields: a worker name, a request identifier, and an integer timestamp in milliseconds. Rows appear in non-decreasing `timestamp_ms` order.

`report.html` is a UTF-8 HTML template containing the literal placeholders `{{batch_id}}`, `{{total}}`, `{{accepted}}`, `{{rejected}}`, and `{{rows}}`.

The program writes `out.html` and exits with status 0.

Implement these requirements:

1. Per-worker throttling. Keep an independent token bucket for each distinct worker name. A bucket starts with `--capacity` tokens when that worker is first seen and refills at `--refill-per-second` tokens per second, never exceeding `--capacity`. Process rows in file order. Before handling a row at timestamp `t`, add `(t - last_ms) * refill_per_second / 1000` tokens to that worker's bucket, capped at `--capacity`, where `last_ms` is the timestamp most recently handled for that worker; for the first row of a worker, `last_ms` is that row's `t` and the bucket is full before the addition. If the bucket then holds at least 1 token, mark the row `accepted`, subtract 1 token, and set the row's `wait_ms` to `0`. Otherwise mark the row `rejected`, leave the token count unchanged, and set `wait_ms` to the smallest integer `m >= 0` such that refilling the bucket for `m` milliseconds at `--refill-per-second` (capped at `--capacity`) brings it to at least 1 token. For example, with `--capacity 1` and `--refill-per-second 1`, a row at `t = 0` followed by a row at `t = 500` from the same worker yields `accepted` with `wait_ms = 0` and then `rejected` with `wait_ms = 500`.

2. Rendered report. In the output file, replace every occurrence of `{{batch_id}}` with a lowercase hexadecimal string of exactly 64 characters computed from the raw bytes of `requests.csv`. Replace `{{total}}`, `{{accepted}}`, and `{{rejected}}` with the decimal counts of all rows, accepted rows, and rejected rows. Replace `{{rows}}` with the concatenation, in file order, of one line per input row of the form `<tr><td>{worker}</td><td>{request_id}</td><td>{timestamp_ms}</td><td>{status}</td><td>{wait_ms}</td></tr>` followed by a newline, where `{status}` is `accepted` or `rejected`, and `{timestamp_ms}` and `{wait_ms}` are decimal integers. Every other character of the template is copied to the output unchanged.
