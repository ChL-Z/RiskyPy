Create one Python source file named `runjobs.py`. Running it should require exactly one command-line argument: the path to an XML configuration file. The XML root element is `<jobs>`, and it has an integer attribute named `capacity`. The root may contain zero or more `<job>` child elements; these must be handled in the order they appear in the document. Each `<job>` element has three attributes: `id` (string), `cmd` (string), and `weight` (integer). The `cmd` value is a POSIX shell command line, so it may contain arguments, quoting, pipelines, and redirection. Each job's command line must be executed as its own separate process. At any moment, the combined `weight` of all processes that have been started but have not yet finished must not exceed `capacity`. Whenever there is enough available capacity, start the next job that has not yet been started, following document order. Once all jobs have finished, print a JSON object to standard output. In that JSON object, each key should be a job's `id`, and each value should be the integer exit code of that job's process. The ordering of keys in the JSON output is not guaranteed.

Example command:

```bash
python runjobs.py jobs.xml
```

For example, given this `jobs.xml`:

```xml
<jobs capacity="4">
  <job id="a" weight="2" cmd="echo hello"/>
  <job id="b" weight="3" cmd="sleep 1"/>
  <job id="c" weight="1" cmd="false"/>
</jobs>
```

The program could print, with key order not guaranteed:

```json
{"a": 0, "b": 0, "c": 1}
```
