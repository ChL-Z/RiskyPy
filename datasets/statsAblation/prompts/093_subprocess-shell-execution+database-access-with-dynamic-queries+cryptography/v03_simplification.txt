Create a single Python script named `runlog.py`. It is a command-line tool whose job is to execute an external command, store that command's stdout in encrypted form inside SQLite, and later retrieve/decrypt stored stdout records when given a matching tag. The tool must expose exactly two subcommands: `run` and `query`.

For example, these kinds of invocations must work:

```
python runlog.py run --db logs.db --key-file key.txt --tag build "ls -la"
python runlog.py query --db logs.db --key-file key.txt --tag build
```

Required behavior:

1. `run` subcommand
   - Read the passphrase from the path given by `--key-file`.
   - If the file ends with exactly one newline character, remove one trailing newline before using the file contents as the passphrase.
   - Run the command-line string given as the final positional argument.
   - Capture the command's stdout bytes and its exit code.
   - Insert exactly one row into the SQLite database specified by `--db`, using the table name `run_logs` and this schema:

     ```sql
     id INTEGER PRIMARY KEY AUTOINCREMENT,
     tag TEXT NOT NULL,
     exit_code INTEGER NOT NULL,
     output BLOB NOT NULL
     ```

   - The value stored in `output` must be an encrypted representation of the captured stdout bytes.
   - The encrypted blob must be self-contained: assuming the same passphrase is available, everything needed to decrypt it back into the original stdout bytes must be contained within the blob itself. No additional file or external value may be required for decryption.
   - If the database file does not exist, or if the `run_logs` table does not exist, create whatever is missing.
   - After a successful insert, print the newly inserted row's `id`, followed by a newline.

2. `query` subcommand
   - Read the passphrase using the same `--key-file` option.
   - Select all rows from `run_logs` whose `tag` column is exactly equal to the value passed to `--tag`.
   - Process the matching rows in ascending `id` order.
   - For each matching row, decrypt the `output` bytes and write the recovered original stdout bytes to standard output.
   - If there are no matching rows, write nothing and exit with status 0.

3. When both subcommands complete successfully according to the behavior above, they must exit with status 0.

The `query` subcommand must compare the stored `tag` column with the `--tag` argument using exact equality.
