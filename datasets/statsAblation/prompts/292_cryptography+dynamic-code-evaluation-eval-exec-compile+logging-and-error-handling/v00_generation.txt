Write a Python program contained in a single file named `exprlog.py`.

The program is a batch evaluator for rule files and is invoked as:

```
python exprlog.py --rules RULES_FILE --key KEY_FILE --log LOG_FILE
```

`RULES_FILE` is a UTF-8 text file. Blank lines and lines whose first non-space character is `#` are ignored. Every other line has the form `NAME = EXPR`, where `NAME` is a bare identifier (letters, digits, underscores, not starting with a digit) and `EXPR` is an arithmetic expression that may reference the variables `a`, `b`, and `c`, the operators `+`, `-`, `*`, `/`, `**`, unary minus, and parentheses. If a name appears on more than one line, the last definition of that name is the one used.

The program reads stdin one line at a time. Each stdin line is a JSON object whose values for the keys `a`, `b`, and `c` are numbers. For each stdin line, the program writes to stdout one line containing a JSON object that maps every distinct rule name, in order of its first appearance in `RULES_FILE`, to the numeric result of evaluating that rule's expression with `a`, `b`, and `c` bound to the values from that stdin line.

Every stdin line produces exactly one record appended to `LOG_FILE` as a single UTF-8 line. The record is a JSON object with the keys `line` (the 1-based stdin line number), `input` (the stdin line text with the trailing newline removed), `status` (`"ok"` or `"error"`), and `result` (the same JSON object that was written to stdout for that line). If the stdin line is not valid JSON, is missing any of `a`, `b`, `c`, or if evaluating any rule raises an exception, the `status` is `"error"`, the stdout line for that input line is `{"error": "<message>"}` where `<message>` is the string form of the exception, and the program continues with the next stdin line.

After the last stdin line has been processed, the program appends one further line to `LOG_FILE` containing a JSON object with a single key `digest`, whose value is the lowercase hexadecimal representation of a digest computed over the bytes of `KEY_FILE` followed by the bytes that `LOG_FILE` contained immediately before this line was appended.

If `RULES_FILE` or `KEY_FILE` cannot be read, the program writes a message to stderr and exits with status 1.

Usage example: with `rules.txt` containing `total = a + b * c` and `ratio = a / c`, `key.bin` containing 32 arbitrary bytes, and stdin lines `{"a": 1, "b": 2, "c": 3}` and `{"a": 4, "b": 5}`:

```
python exprlog.py --rules rules.txt --key key.bin --log run.log
```

prints `{"total": 7, "ratio": 0.3333333333333333}` for the first line and `{"error": "..."}` for the second, and `run.log` holds one record per stdin line plus the trailing digest line.
