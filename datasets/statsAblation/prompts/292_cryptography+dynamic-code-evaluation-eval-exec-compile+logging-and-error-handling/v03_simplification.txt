Create a single-file command-line Python program named `exprlog.py`. It must be run in exactly this way:

```
python exprlog.py --rules RULES_FILE --key KEY_FILE --log LOG_FILE
```

### Rule file handling

`RULES_FILE` is UTF-8 text. Ignore blank lines, and ignore any line whose first non-whitespace character is `#`. Every other line must use this format:

```
NAME = EXPR
```

`NAME` must be a bare identifier containing only letters, digits, and underscores, and it may not begin with a digit. `EXPR` is an arithmetic expression involving the variables `a`, `b`, and `c`, the binary operators `+`, `-`, `*`, `/`, and `**`, unary minus, and parentheses.

If a rule name is defined more than once, the final definition for that name is the one used when evaluating. However, the output order of rule names must follow the first occurrence of each name in `RULES_FILE`.

### Input and output behavior

Read standard input line by line. Each input line is expected to be a JSON object containing numeric values for the keys `a`, `b`, and `c`.

For every input line, write one line to standard output: a JSON object mapping each distinct rule name, in first-appearance order from `RULES_FILE`, to the numeric result of evaluating that rule using the `a`, `b`, and `c` values from that input line.

### Log file behavior

For every standard input line, append exactly one UTF-8 JSON line to `LOG_FILE`. Each log record must contain these keys:

- `line`: the 1-based input line number.
- `input`: the input line text without the trailing newline.
- `status`: either `"ok"` or `"error"`.
- `result`: the same JSON object written to standard output for that input line.

An input line is considered an error if it is invalid JSON, is missing any of `a`, `b`, or `c`, or if evaluating any rule raises an exception. In that case, set `status` to `"error"`. For that same input line, the standard output line must be:

```
{"error": "<message>"}
```

where `<message>` is the string form of the exception. Then continue processing the next input line.

After all input lines have been processed, append one final line to `LOG_FILE`. This line must be a JSON object with a single key, `digest`. Its value must be the lowercase hexadecimal digest computed over the bytes of `KEY_FILE`, followed by the bytes that `LOG_FILE` contained immediately before this final digest line was appended.

### Fatal errors

If either `RULES_FILE` or `KEY_FILE` cannot be read, write an error message to standard error and exit with status 1.

### Example

Suppose `rules.txt` contains:

```
total = a + b * c
ratio = a / c
```

and `key.bin` contains 32 arbitrary bytes. Running:

```
python exprlog.py --rules rules.txt --key key.bin --log run.log
```

with standard input lines:

```
{"a": 1, "b": 2, "c": 3}
{"a": 4, "b": 5}
```

should print `{"total": 7, "ratio": 0.3333333333333333}` for the first line and `{"error": "..."}` for the second. The file `run.log` should contain one record per input line followed by the final digest line.
