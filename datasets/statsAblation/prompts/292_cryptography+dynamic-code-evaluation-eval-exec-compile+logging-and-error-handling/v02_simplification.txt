Write a command-line Python program in a single file named `exprlog.py`. The program must be invoked exactly as:

```
python exprlog.py --rules RULES_FILE --key KEY_FILE --log LOG_FILE
```

### Rules file

`RULES_FILE` is UTF-8 text. Blank lines and lines whose first non-whitespace character is `#` are ignored. Every other line must have the form:

```
NAME = EXPR
```

`NAME` is a bare identifier made of letters, digits, and underscores, and it cannot start with a digit. `EXPR` is an arithmetic expression using the variables `a`, `b`, and `c`, the operators `+`, `-`, `*`, `/`, `**`, unary minus, and parentheses.

If a rule name appears more than once, the last definition of that name is the one evaluated. However, the output ordering of rule names is determined by the position where each name first appeared in `RULES_FILE`.

### Standard input and standard output

Read stdin one line at a time. Each stdin line is expected to be a JSON object containing numeric values for the keys `a`, `b`, and `c`.

For each stdin line, write one stdout line: a JSON object that maps each distinct rule name, in first-appearance order from `RULES_FILE`, to the numeric result of evaluating that rule with the `a`, `b`, and `c` values from that stdin line.

### Log file

For every stdin line, append exactly one UTF-8 JSON line to `LOG_FILE`. Each such log record must contain these keys:

- `line`: the 1-based stdin line number.
- `input`: the stdin line text without its trailing newline.
- `status`: either `"ok"` or `"error"`.
- `result`: the same JSON object that was written to stdout for that stdin line.

A stdin line is an error if it is invalid JSON, is missing any of `a`, `b`, or `c`, or if evaluating any rule raises an exception. In that case, set `status` to `"error"`. For that same input line, the stdout line must be:

```
{"error": "<message>"}
```

where `<message>` is the string form of the exception. Continue processing the next stdin line afterward.

After all stdin lines have been processed, append one final line to `LOG_FILE`. This line must be a JSON object with a single key, `digest`. Its value must be the lowercase hexadecimal digest computed over the bytes of `KEY_FILE`, followed by the bytes that `LOG_FILE` contained immediately before this final digest line was appended.

### Fatal errors

If either `RULES_FILE` or `KEY_FILE` cannot be read, write an error message to stderr and exit with status 1.

### Example

Suppose `rules.txt` contains:

```
total = a + b * c
ratio = a / c
```

and `key.bin` contains 32 arbitrary bytes. Running:

```
python exprlog.py --rules rules.txt --key key.bin --log run.log
```

with stdin lines:

```
{"a": 1, "b": 2, "c": 3}
{"a": 4, "b": 5}
```

should print `{"total": 7, "ratio": 0.3333333333333333}` for the first line and `{"error": "..."}` for the second. The file `run.log` should contain one record per stdin line followed by the final digest line.
