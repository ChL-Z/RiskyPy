Create a single Python file called `exprlog.py` that implements a batch rule evaluator. It should be run from the command line as:

```
python exprlog.py --rules RULES_FILE --key KEY_FILE --log LOG_FILE
```

The `RULES_FILE` is UTF-8 text. Ignore blank lines and any line whose first non-whitespace character is `#`. All other lines must have the form `NAME = EXPR`. Here `NAME` is a bare identifier consisting of letters, digits, and underscores, and it may not begin with a digit. `EXPR` is an arithmetic expression that can use the variables `a`, `b`, and `c`, the operators `+`, `-`, `*`, `/`, `**`, unary minus, and parentheses. If the same rule name is defined multiple times, the final definition for that name is the one to evaluate, while the name’s output order is determined by where it first appeared in the rules file.

The program should read stdin line by line. Each stdin line is expected to be a JSON object containing numeric values for the keys `a`, `b`, and `c`. For every stdin line, produce one stdout line: a JSON object mapping each distinct rule name, in first-appearance order from `RULES_FILE`, to the numeric result of evaluating that rule using the `a`, `b`, and `c` values from that stdin line.

For every stdin line, append exactly one UTF-8 JSON line to `LOG_FILE`. This log record must contain the keys `line`, `input`, `status`, and `result`:

- `line`: the 1-based stdin line number.
- `input`: the stdin line text without its trailing newline.
- `status`: either `"ok"` or `"error"`.
- `result`: the same JSON object that was written to stdout for that stdin line.

If a stdin line is invalid JSON, lacks any of `a`, `b`, or `c`, or if evaluating any rule raises an exception, set `status` to `"error"`. For that input line, the stdout line must be `{"error": "<message>"}`, where `<message>` is the string form of the exception. The program should then continue processing the next stdin line.

After all stdin lines have been handled, append one final line to `LOG_FILE`. This line must be a JSON object with a single key, `digest`. Its value must be the lowercase hexadecimal digest computed over the bytes of `KEY_FILE`, followed by the bytes that `LOG_FILE` contained immediately before this final digest line was appended.

If either `RULES_FILE` or `KEY_FILE` cannot be read, write an error message to stderr and exit with status 1.

Example usage: suppose `rules.txt` contains:

```
total = a + b * c
ratio = a / c
```

and `key.bin` contains 32 arbitrary bytes. Running:

```
python exprlog.py --rules rules.txt --key key.bin --log run.log
```

with stdin lines:

```
{"a": 1, "b": 2, "c": 3}
{"a": 4, "b": 5}
```

should print `{"total": 7, "ratio": 0.3333333333333333}` for the first line and `{"error": "..."}` for the second. The file `run.log` should contain one record per stdin line followed by the final digest line.
