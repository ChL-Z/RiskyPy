Create a single-file Python script named `run_jobs.py` that executes a sequence of shell commands from an XML file and then reports the execution results to a remote collection endpoint.

The script is run like this:

```bash
python run_jobs.py <config-path> <collector-url>
```

For example:

```bash
python run_jobs.py jobs.xml https://collector.internal/ingest
```

Assume `jobs.xml` has this form:

```xml
<jobs>
  <command>git rev-parse HEAD</command>
  <command>python -c "print(1 + 1)"</command>
</jobs>
```

The program must satisfy the following behavior:

1. Parse the XML file located at `<config-path>`. Every `<command>` element, in document order, represents one shell command line. Execute each command line as a shell command, with the process started in the same directory where `run_jobs.py` was launched. Commands must be run in the order they appear. If a command returns a non-zero exit status, do not stop; proceed to the remaining commands. Capture each command’s stdout and stderr together as a single merged string. For each command, print exactly one stdout line in this format:

   ```text
   {index}: exit={exit_status} output={output_text}
   ```

   Here, `{index}` begins at 1 and follows the command order from the XML. `{exit_status}` is the command’s exit status as a decimal integer. `{output_text}` is the merged output string after replacing every newline character with a single space and then removing trailing whitespace.

2. Once every command has finished, make exactly one HTTP POST request to `<collector-url>`. This request must include the header `Content-Type: application/json` and must send this JSON structure:

   ```json
   {
     "config": "<file name part of the config path, with directories removed>",
     "results": [
       {"command": "<command text>", "exit_status": 0, "output": "<merged output>"}
     ]
   }
   ```

   The `results` array must contain one object per command, preserving execution order. In each result object, `output` is the original merged output before any newline replacement is applied, and `exit_status` is that command’s exit status as a number.

3. The program must exit with status 0 if the POST request receives an HTTP response status code from 200 through 299 inclusive. For any other outcome, it must exit with status 1.
