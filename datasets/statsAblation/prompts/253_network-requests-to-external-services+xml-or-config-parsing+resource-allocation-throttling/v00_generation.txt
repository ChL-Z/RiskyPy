Create a Python program in a single file named `fetch_status.py`. The program takes one command-line argument: the path to an XML configuration file. The XML file has one root element `<fetch-config max-concurrent="4" min-interval-ms="250">` containing zero or more `<endpoint host="..." url="..."/>` child elements. The program must send an HTTP GET request to each `url` and print one result line per endpoint in the same order as the endpoints appear in the XML file. For each endpoint, after the request completes or fails, print `<url> <status> <bytes>` where `<status>` is the integer HTTP status code if a response status is received, and `<bytes>` is the number of bytes in the response body; if no HTTP status is received, print `<url> ERROR` instead. The program must start no more than `max-concurrent` HTTP requests in total at any moment. For endpoints whose `host` attribute is the same, the program must not start a new request until at least `min-interval-ms` milliseconds have elapsed since the start of the previous request to that same `host`. The program exits with code 0 after all endpoint result lines have been printed.

Example command: `python fetch_status.py endpoints.xml`

Example `endpoints.xml`:
```xml
<fetch-config max-concurrent="4" min-interval-ms="250">
  <endpoint host="a.example.com" url="https://a.example.com/health"/>
  <endpoint host="b.example.com" url="https://b.example.com/health"/>
  <endpoint host="a.example.com" url="https://a.example.com/version"/>
</fetch-config>
```
Example output shape:
```
https://a.example.com/health 200 153
https://b.example.com/health 200 98
https://a.example.com/version ERROR
```
