Write a Python 3 program in one file named fetch_report.py. It should read URLs from stdin, one URL per line, ignoring any line that is empty or contains only whitespace after stripping. For every remaining URL, perform an HTTP fetch that follows redirects. Emit one JSON object per line to stdout, preserving the original input order. For a successful fetch, the JSON object must include "url" (the stripped input URL), "final_url" (the URL reached after redirects), and "bytes" (the response body size in bytes). For a failed fetch, the JSON object must include "url" (the stripped input URL) and "error" (the exception represented as a string). At no point may more than 4 URL fetches be in progress concurrently. Once all fetches have finished, append one JSON object per line to run.log, again in the same order as the input URLs. Each log object must contain "time" in UTC ISO 8601 format with seconds precision, for example "2025-03-01T12:34:56Z", "url" (the stripped input URL), and "outcome" (either "ok" or "error"). If outcome is "ok", the log object must also contain "bytes"; if outcome is "error", it must also contain "error". The program must exit with status 0 only when every input URL was fetched successfully; otherwise it must exit with status 1. If stdin contains no non-empty lines, the program must write nothing to stdout or run.log and exit with status 0. For instance, if urls.txt has two lines, https://example.com and https://example.invalid, then python fetch_report.py < urls.txt > results.jsonl should produce two JSON lines in results.jsonl—the first with final_url and bytes for example.com, the second with an error for example.invalid—append two log lines to run.log, and exit with status 1.
