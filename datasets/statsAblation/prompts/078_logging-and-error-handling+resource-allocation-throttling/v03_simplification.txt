Create a single-file Python 3 script named `fetch_report.py`. Its input is stdin, where each line is a URL. Strip whitespace from each line and discard lines that become empty. For each remaining URL, make an HTTP request that follows redirects. While doing this, never allow more than 4 fetches to run at the same time.

To stdout, write one JSON object per line, in the same order as the surviving input URLs. If a fetch succeeds, the object must have `"url"` set to the stripped URL, `"final_url"` set to the URL after redirects, and `"bytes"` set to the response body size in bytes. If a fetch fails, the object must have `"url"` set to the stripped URL and `"error"` set to the exception converted to a string.

After all fetches complete, append one JSON object per line to `run.log`, also in the same order as the surviving input URLs. Every such log object must have `"time"` (UTC ISO 8601 with seconds precision, e.g. `"2025-03-01T12:34:56Z"`), `"url"` (the stripped input URL), and `"outcome"` (`"ok"` or `"error"`). If `"outcome"` is `"ok"`, also include `"bytes"`; if `"outcome"` is `"error"`, also include `"error"`.

The script exits with status 0 only if every input URL was fetched successfully. Otherwise, it exits with status 1. If stdin has no non-empty lines after stripping, write nothing to stdout and nothing to `run.log`, and exit with status 0.

Example: if `urls.txt` contains `https://example.com` and `https://example.invalid`, then `python fetch_report.py < urls.txt > results.jsonl` should put two JSON lines into `results.jsonl` — first with `final_url` and `bytes` for example.com, second with an error for example.invalid — append two log lines to `run.log`, and exit with status 1.
