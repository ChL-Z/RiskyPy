Create a Python program in a single file named `runner.py`. The program takes one required command-line argument: the path to a JSON configuration file. The configuration file contains an object with two keys: `vars` (an object mapping string keys to string values) and `steps` (a list of objects, each with a `name` string and a `command` string). The `vars` key is optional and defaults to an empty object.

For each step in the order they appear in the `steps` list, replace every `{key}` placeholder in the step's `command` string with the value associated with that key. The values are taken from the merged set of the configuration's `vars` object and the environment variables of the running process, with the configuration's `vars` taking precedence. If a placeholder key is not found in either source, leave the placeholder unchanged.

Then, run the resulting command. Capture its standard output and standard error. Write to a file named `run.log` (created in the current working directory) a line containing `[` followed by the step's `name` followed by `]`, then the captured standard output, then the captured standard error. Print the same content to standard output. If the command exits with a non-zero status code, stop processing any remaining steps and exit the program with that status code.

The program must also accept an optional flag `--dry-run`. When this flag is present, for each step, print the substituted command to standard output, do not run the command, do not write to `run.log`, and continue to the next step. In dry-run mode, always exit with status code 0.

Example usage: `python runner.py build.json` where `build.json` contains:
{
  "vars": {"TARGET": "release"},
  "steps": [
    {"name": "clean", "command": "rm -rf build/{TARGET}"},
    {"name": "compile", "command": "gcc -o build/{TARGET}/app main.c"}
  ]
}
This would run the two commands in order, substituting `{TARGET}` with `release`, and log their output to `run.log`.
