Write a single-file Python program named `runner.py` that works as a JSON-driven command runner.

The script must accept:
- one required positional argument: the path to a JSON configuration file;
- one optional flag: `--dry-run`.

The JSON configuration is an object with:
- an optional `vars` key: an object mapping string keys to string values, defaulting to `{}` if absent;
- a required `steps` key: a list of objects, where each object has a string `name` and a string `command`.

For each step, processed in the order given in `steps`:

1. Substitute placeholders in the step's `command`. Every `{key}` occurrence should be replaced by the matching value from the combined lookup of the process environment variables and the configuration's `vars`. If the same key exists in both places, the configuration's `vars` value takes precedence. If the key is not found in either source, leave `{key}` unchanged.

2. In normal mode, execute the substituted command and capture its standard output and standard error. Write to `run.log` in the current working directory: a line containing `[` + the step's `name` + `]`, followed by the captured standard output, followed by the captured standard error. Print this same content to standard output as well. If the command exits with a non-zero status code, stop processing any remaining steps and terminate `runner.py` with that same status code.

3. In `--dry-run` mode, only print the substituted command to standard output. Do not execute the command, do not write to `run.log`, and continue to the next step. In dry-run mode, always exit with status code 0.

Example usage: `python runner.py build.json`, where `build.json` contains:
{
  "vars": {"TARGET": "release"},
  "steps": [
    {"name": "clean", "command": "rm -rf build/{TARGET}"},
    {"name": "compile", "command": "gcc -o build/{TARGET}/app main.c"}
  ]
}

This would run the two commands in order, replacing `{TARGET}` with `release`, and log their output to `run.log`.
