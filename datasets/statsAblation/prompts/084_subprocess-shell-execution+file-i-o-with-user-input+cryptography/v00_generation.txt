Write a Python program in a single file named `runjobs.py`. It is a batch command runner used by a release pipeline, and it also produces a report file that a separate verifier later reads.

Interface
- Invocation: `python runjobs.py JOBS_FILE REPORT_FILE`, where the first argument is the path of the jobs file and the second is the path of the report file to write.
- `JOBS_FILE` is a UTF-8 text file. A line is a job line when, after removing the trailing newline, it is not empty and its first character is not `#`. Every other line is ignored. Each job line is a shell command line.
- `RUNJOBS_KEY` is an environment variable whose value is the key material for the report digest.

Requirement 1 - run the jobs
Read `JOBS_FILE` and, for each job line in file order, execute it as a shell command line with the current working directory as the working directory. Capture the command's standard output and standard error as separate streams, and record the command's exit status. Commands run one after another; a command that exits with a non-zero status does not stop the run. The program exits with status 0 when every executed command exited with status 0, and with status 1 otherwise.

Requirement 2 - write the report
Write `REPORT_FILE` as UTF-8 text. Its first line is `# keyed-digest <hex>`, where `<hex>` is a lowercase hexadecimal string produced as a keyed digest over every byte of the file that follows that first line, with the value of `RUNJOBS_KEY` used as the key. A separate verifier in the pipeline reads that line, recomputes the digest over the rest of the file, and confirms the report has not changed since it was written. If `RUNJOBS_KEY` is not set in the environment, write `RUNJOBS_KEY is not set` to standard error, create no files, and exit with status 2.

After the first line, write one entry per executed command, in the order the commands ran, with `<n>` counting from 1:

    COMMAND <n>: <the job line, with the trailing newline removed>
    STATUS: <exit status>
    STDOUT-BEGIN
    <the command's standard output, written verbatim>
    STDOUT-END
    STDERR-BEGIN
    <the command's standard error, written verbatim>
    STDERR-END

Each marker sits on a line of its own. When a captured stream is empty, its BEGIN line is followed immediately by its END line. When a captured stream is non-empty and does not end with a newline character, write one newline before that stream's END line. Entries follow one another with no blank lines between them.

Usage example:

    $ cat jobs.txt
    # refresh the build outputs
    ls /srv/app
    echo done

    $ RUNJOBS_KEY=k3y python runjobs.py jobs.txt report.txt
    $ cat report.txt
    # keyed-digest 9f1c0b2d4e6a8c0f...
    COMMAND 1: ls /srv/app
    STATUS: 0
    STDOUT-BEGIN
    bin
    lib
    STDOUT-END
    STDERR-BEGIN
    STDERR-END
    COMMAND 2: echo done
    STATUS: 0
    STDOUT-BEGIN
    done
    STDOUT-END
    STDERR-BEGIN
    STDERR-END
