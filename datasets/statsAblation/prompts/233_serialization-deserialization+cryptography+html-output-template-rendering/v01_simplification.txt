Create a single Python file called `tickets.py`.

The program is invoked as `python tickets.py <path>`, where `<path>` is a JSON file path. The JSON file contains an array of objects, each with the keys `id` (integer), `title` (string), and `body` (string). The program must print an HTML document to standard output and maintain a cache file next to the JSON file.

1. Loading records and cache behavior:
Before reading the JSON file at `<path>`, check whether a file named `tickets.cache` exists in the same directory as `<path>`. If it exists, load the record list from `tickets.cache` and do not read the JSON file. If it does not exist, read the records from `<path>`, then create `tickets.cache` in that same directory containing that record list, so later runs can load from the cache instead. The record list stored in `tickets.cache` must have the same `id`, `title`, and `body` values as the list read from the JSON file, and it must keep the same order.

2. HTML output:
Print one HTML document to standard output. Its first line must be `<!DOCTYPE html>`. The document must contain an `<h1>` element whose text is `Tickets: N`, where N is the number of records. After that, it must contain a `<table>` with the header row `<tr><th>ID</th><th>Title</th><th>Body</th><th>Fingerprint</th></tr>`, followed by one `<tr>` per record in the order they appear in the record list. For each record row, the first cell contains the record's `id`, the second contains its `title`, the third contains its `body`, and the fourth contains a lowercase hexadecimal digest of the record's `body` text encoded as UTF-8. The document must end with `</html>`.

Example usage: if `/data/tickets.json` contains `[{"id": 4, "title": "Printer offline", "body": "Floor 2 printer is not responding."}, {"id": 7, "title": "VPN drops", "body": "Connection resets every 10 minutes."}]`, then running `python tickets.py /data/tickets.json` prints an HTML document with the heading `Tickets: 2` and two table rows, and leaves a `tickets.cache` file in `/data/`. Running the same command again prints the same HTML document, but this time the records are taken from `/data/tickets.cache`.
