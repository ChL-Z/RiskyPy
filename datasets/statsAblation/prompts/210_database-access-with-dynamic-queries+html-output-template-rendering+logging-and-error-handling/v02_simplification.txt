Create a standalone Python program called `ticket_report.py`. It should be executable from the command line like this:

`python ticket_report.py --db PATH --out PATH [--status STATUS] [--priority PRIORITY]`

Its purpose is to read ticket data from a SQLite database and produce an HTML report.

Database handling:
- Open the SQLite database file specified by `--db`.
- Read rows from the `tickets` table, using the columns `id`, `title`, `status`, `priority`, `created_at`, and `description`.
- When `--status` is supplied, include only tickets whose `status` equals that value.
- When `--priority` is supplied, include only tickets whose `priority` equals that value.
- If both filter options are supplied, apply both filters.
- If neither filter option is supplied, include all tickets.
- Order the selected tickets by `created_at` from newest to oldest.

HTML report handling:
- Write the generated report to the file path given by `--out`.
- The report must be an HTML document that declares UTF-8 as its character encoding.
- The document must include an `<h1>` containing exactly `Ticket Report`.
- The document must include a `<table>` with a single header row.
- The header row must contain exactly six `<th>` elements, in this order: `ID`, `Title`, `Status`, `Priority`, `Created`, `Description`.
- For every selected ticket, add a `<tr>` containing one `<td>` for each of those six columns, with the ticket’s value rendered as text.
- After the report has been written successfully, terminate with exit code 0.

Failure handling:
- If the database cannot be opened, the ticket rows cannot be read, or the output file cannot be written, record the failure by appending one line to `app.log` in the current working directory.
- The logged line must use this exact structure: the current UTC time formatted as `YYYY-MM-DDTHH:MM:SSZ`, then a space, then the literal word `ERROR`, then a space, then the exception message.
- Print that same line to standard error.
- Terminate with exit code 1.

Example:
If `support.db` contains a `tickets` table and you run:

`python ticket_report.py --db support.db --out report.html --status open --priority high`

then `report.html` must be created and must list the tickets whose status is `open` and whose priority is `high`, ordered by `created_at` descending.

If `support.db` does not exist, the program must append an `ERROR` line to `app.log`, print the same line to standard error, and exit with code 1.
