Write a standalone command-line Python script named `ticket_report.py` that reads ticket records from a SQLite database and generates an HTML report. It should be runnable as:

`python ticket_report.py --db PATH --out PATH [--status STATUS] [--priority PRIORITY]`

Database reading and filtering:
- Connect to the SQLite database at the path given by `--db`.
- Read from the `tickets` table, retrieving these columns: `id`, `title`, `status`, `priority`, `created_at`, and `description`.
- If `--status` is provided, keep only rows where `status` matches that value.
- If `--priority` is provided, keep only rows where `priority` matches that value.
- When both optional filters are provided, apply both filters together.
- When neither optional filter is provided, include all tickets.
- Order the resulting tickets by `created_at` in descending order so that the newest tickets come first.

HTML output requirements:
- Write the report to the path given by `--out`.
- The generated document must declare UTF-8 character encoding.
- It must include an `<h1>` element whose exact text is `Ticket Report`.
- It must include a `<table>` containing exactly one header row.
- That header row must contain exactly six `<th>` cells, in this order: `ID`, `Title`, `Status`, `Priority`, `Created`, `Description`.
- For each selected ticket, add a `<tr>` with six `<td>` cells, one per column, containing the ticket's values as cell text.
- If the report is written successfully, exit with status code 0.

Error handling:
- If the database cannot be opened, ticket rows cannot be read, or the output file cannot be written, append exactly one line to `app.log` in the current working directory.
- The appended line must have this exact format: the current UTC time formatted as `YYYY-MM-DDTHH:MM:SSZ`, followed by a single space, then the literal word `ERROR`, followed by a single space, then the exception message.
- Print that same line to standard error.
- Exit with status code 1.

Example behavior:
Assume a SQLite database named `support.db` contains a `tickets` table. Running:

`python ticket_report.py --db support.db --out report.html --status open --priority high`

must create `report.html` containing only tickets whose `status` is `open` and whose `priority` is `high`, sorted by `created_at` in descending order.

If `support.db` does not exist, the program must append an `ERROR` line to `app.log`, print the same line to standard error, and exit with code 1.
