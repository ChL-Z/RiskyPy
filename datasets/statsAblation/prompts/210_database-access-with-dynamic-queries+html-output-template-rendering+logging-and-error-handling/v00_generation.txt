Create a Python program in a single file named `ticket_report.py`. It must provide one command-line entry point:

`python ticket_report.py --db PATH --out PATH [--status STATUS] [--priority PRIORITY]`

Requirement 1: Read the SQLite database file at `--db`. From its `tickets` table, select the columns `id`, `title`, `status`, `priority`, `created_at`, and `description`. When `--status` is supplied, include only rows whose `status` equals that value. When `--priority` is supplied, include only rows whose `priority` equals that value. When both are supplied, apply both filters. When neither is supplied, include all rows. Order the selected rows by `created_at` descending. Write to `--out` an HTML document with a UTF-8 meta charset, an `<h1>` element whose text is `Ticket Report`, and a `<table>` with one header row containing six `<th>` cells in this order: `ID`, `Title`, `Status`, `Priority`, `Created`, `Description`. Add one `<tr>` per selected row. Each `<td>` contains the corresponding column value as text. Exit with status 0 after writing the file.

Requirement 2: If the database file cannot be opened, the rows cannot be read, or the output path cannot be written, append one line to `app.log` in the current working directory. The line must contain the UTC time as `YYYY-MM-DDTHH:MM:SSZ`, a space, the text `ERROR`, a space, and the exception message. Print the same line to stderr and exit with status 1.

Example: running `python ticket_report.py --db support.db --out report.html --status open --priority high` against a database whose `tickets` table has rows with status `open` and priority `high` must produce `report.html` listing those rows in descending `created_at` order. If `support.db` is missing, the program must append an `ERROR` line to `app.log`, print that line to stderr, and exit with status 1.
