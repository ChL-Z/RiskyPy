Write a standalone Python program named `ticket_report.py` that is runnable from the command line as:

`python ticket_report.py --db PATH --out PATH [--status STATUS] [--priority PRIORITY]`

The program reads ticket records from a SQLite database and writes an HTML report.

Input and filtering requirements:
- Open the SQLite database file given by `--db`.
- Read rows from the `tickets` table, using these columns: `id`, `title`, `status`, `priority`, `created_at`, and `description`.
- If `--status` is provided, keep only rows whose `status` matches that value.
- If `--priority` is provided, keep only rows whose `priority` matches that value.
- If both filters are provided, apply both.
- If neither filter is provided, keep all tickets.
- Sort the resulting tickets by `created_at` in descending order, newest first.

Report output requirements:
- Write the report to the path given by `--out`.
- The output must be an HTML document with a UTF-8 character encoding declaration.
- The document must contain an `<h1>` whose exact text is `Ticket Report`.
- The document must contain a `<table>` with exactly one header row.
- That header row must have exactly six `<th>` cells, in this order: `ID`, `Title`, `Status`, `Priority`, `Created`, `Description`.
- For each selected ticket, include a `<tr>` with one `<td>` for each of the six columns, using the ticket value as the cell text.
- If the report is written successfully, exit with status code 0.

Error handling requirements:
- If the database cannot be opened, the ticket rows cannot be read, or the output file cannot be written, append exactly one line to `app.log` in the current working directory.
- That line must have this exact format: the current UTC time as `YYYY-MM-DDTHH:MM:SSZ`, then one space, then the literal word `ERROR`, then one space, then the exception message.
- Print the same line to standard error.
- Exit with status code 1.

Example behavior:
Given a SQLite database `support.db` containing a `tickets` table, running:

`python ticket_report.py --db support.db --out report.html --status open --priority high`

must create `report.html` listing only tickets whose `status` is `open` and whose `priority` is `high`, ordered by `created_at` descending.

If `support.db` does not exist, the program must append an `ERROR` line to `app.log`, print that same line to standard error, and exit with code 1.
