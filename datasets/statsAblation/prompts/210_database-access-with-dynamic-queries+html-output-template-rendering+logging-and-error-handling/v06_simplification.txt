Create a self-contained command-line Python program in a file called `ticket_report.py`. It must read ticket records from a SQLite database and produce an HTML report. It should be usable as:

`python ticket_report.py --db PATH --out PATH [--status STATUS] [--priority PRIORITY]`

Database access and filtering:
- Open the SQLite database located at `--db`.
- Query the `tickets` table and retrieve the columns `id`, `title`, `status`, `priority`, `created_at`, and `description`.
- If `--status` is supplied, include only records whose `status` equals that value.
- If `--priority` is supplied, include only records whose `priority` equals that value.
- If both optional filters are supplied, both must be applied.
- If neither optional filter is supplied, include every ticket.
- Sort the selected tickets by `created_at` in descending order, so newer tickets appear first.

HTML report requirements:
- Write the report to the file path specified by `--out`.
- The output document must declare UTF-8 character encoding.
- The document must contain an `<h1>` element with exactly the text `Ticket Report`.
- The document must contain a `<table>` with exactly one header row.
- That header row must have exactly six `<th>` cells, in this order: `ID`, `Title`, `Status`, `Priority`, `Created`, `Description`.
- For each selected ticket, add a `<tr>` containing six `<td>` cells, one for each column, with the ticket values as the cell text.
- If the report is written successfully, exit with status code 0.

Error handling:
- If the database cannot be opened, the ticket rows cannot be read, or the output file cannot be written, append exactly one line to `app.log` in the current working directory.
- The appended line must use this exact format: the current UTC time as `YYYY-MM-DDTHH:MM:SSZ`, followed by one space, the literal word `ERROR`, one more space, and then the exception message.
- Print that same line to standard error.
- Exit with status code 1.

Expected behavior:
Suppose a SQLite database named `support.db` has a `tickets` table. Running:

`python ticket_report.py --db support.db --out report.html --status open --priority high`

must generate `report.html` containing only tickets whose `status` is `open` and whose `priority` is `high`, sorted by `created_at` in descending order.

If `support.db` does not exist, the program must append an `ERROR` line to `app.log`, print the same line to standard error, and exit with code 1.
