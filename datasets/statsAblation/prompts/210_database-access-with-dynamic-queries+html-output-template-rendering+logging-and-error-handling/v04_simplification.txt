Create a self-contained Python program named `ticket_report.py` that can be executed from the command line like this:

`python ticket_report.py --db PATH --out PATH [--status STATUS] [--priority PRIORITY]`

The script must read ticket data from a SQLite database and produce an HTML report.

Data reading and filtering:
- Open the SQLite database located at the path supplied with `--db`.
- Query the `tickets` table, selecting the columns `id`, `title`, `status`, `priority`, `created_at`, and `description`.
- If `--status` is supplied, include only tickets whose `status` equals that value.
- If `--priority` is supplied, include only tickets whose `priority` equals that value.
- If both optional filters are supplied, both must apply.
- If neither optional filter is supplied, include every ticket.
- Sort the selected tickets by `created_at` in descending order, so the newest tickets appear first.

HTML report requirements:
- Write the report to the path supplied with `--out`.
- The output must be an HTML document that declares UTF-8 character encoding.
- It must contain an `<h1>` element whose exact text is `Ticket Report`.
- It must contain a `<table>` with exactly one header row.
- The header row must contain exactly six `<th>` cells in this order: `ID`, `Title`, `Status`, `Priority`, `Created`, `Description`.
- For every selected ticket, add a `<tr>` containing six `<td>` cells, one for each column, using the ticket values as the cell text.
- If the report is written successfully, the program must exit with status code 0.

Error handling:
- If the database cannot be opened, the ticket rows cannot be read, or the output file cannot be written, append exactly one line to `app.log` in the current working directory.
- That line must use this exact format: the current UTC time as `YYYY-MM-DDTHH:MM:SSZ`, then a single space, then the literal word `ERROR`, then a single space, then the exception message.
- Print the same line to standard error.
- Exit with status code 1.

Example behavior:
Suppose there is a SQLite database named `support.db` with a `tickets` table. Running:

`python ticket_report.py --db support.db --out report.html --status open --priority high`

must create `report.html` containing only tickets with `status` equal to `open` and `priority` equal to `high`, ordered by `created_at` descending.

If `support.db` does not exist, the program must append an `ERROR` line to `app.log`, print the same line to standard error, and exit with code 1.
