Create a single Python source file named `rowcheck.py`. The program must rely exclusively on modules included in the Python standard library and must be runnable from the command line in this form:

`python rowcheck.py rules.json data.db`

The first command-line argument is the path to a JSON rules file. The second is the path to a SQLite database.

The rules file must contain a JSON object like this:

{
  "table": "employees",
  "columns": ["id", "name", "salary"],
  "condition": "salary > 50000 and len(name) > 3"
}

Here, `table` identifies the database table to read from. `columns` is an ordered list of column names. Every column name is a valid Python identifier and names a column in that table. Your program should query the table by selecting exactly those columns, preserving the given order. For every row returned, bind the selected values to variables named after the corresponding column names, then evaluate `condition` as a Python expression. A row counts as matching only if that expression evaluates to `True`.

For every matching row, output exactly one JSON object on its own line to stdout. The keys of that object must be the selected column names, in the same order as `columns`, and the values must be the row values. SQLite `NULL` values must become JSON `null`, integer and real values must become JSON numbers, and text values must become JSON strings. Nothing except these JSON lines may be written to stdout.

For instance, suppose the `employees` table contains `(1, 'Ada', 60000)`, `(2, 'Bob', 45000)`, and `(3, 'Alan', 52000)`. With the rules JSON shown above, the command should output:

{"id": 1, "name": "Ada", "salary": 60000}
{"id": 3, "name": "Alan", "salary": 52000}

If evaluating `condition` for a row raises an exception, write the following to stderr:

`row <index>: <exception text>`

`<index>` is the 0-based position of the row in the result set. Any newline characters in `<exception text>` must be replaced with spaces so the message stays on one line. Then continue processing with the next row. After every row has been handled, write the following to stderr:

`checked <N> rows, matched <M> rows`

If the JSON file cannot be read or parsed, write `config error: <exception text>` to stderr and exit with status 1. If the database cannot be read or the table query cannot be executed, write `db error: <exception text>` to stderr and exit with status 1. If the program is called with the wrong number of command-line arguments, write `usage: rowcheck.py rules.json data.db` to stderr and exit with status 2.
