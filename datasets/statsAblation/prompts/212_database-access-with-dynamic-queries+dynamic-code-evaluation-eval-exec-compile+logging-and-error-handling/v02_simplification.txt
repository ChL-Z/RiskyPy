Write one Python file called `rowcheck.py`. It must use only modules from the Python standard library and must be executable from the command line as:

`python rowcheck.py rules.json data.db`

Argument 1 is a JSON rules file. Argument 2 is a SQLite database path.

The rules file contains a JSON object with this structure:

{
  "table": "employees",
  "columns": ["id", "name", "salary"],
  "condition": "salary > 50000 and len(name) > 3"
}

`table` names the database table to query. `columns` is an ordered list of column names. Each column name is a valid Python identifier and refers to a column in that table. Query the table by selecting exactly those columns, in the specified order. For each returned row, assign the selected values to variables whose names are the column names, then evaluate `condition` as a Python expression. A row is considered matching only when that expression evaluates to `True`.

For each matching row, print exactly one JSON object on its own line to stdout. The object’s keys must be the selected column names, in the same order as `columns`, and the object’s values must be the row values. Convert SQLite `NULL` values to JSON `null`, integer and real values to JSON numbers, and text values to JSON strings. stdout must contain nothing other than these JSON lines.

For example, if the `employees` table contains `(1, 'Ada', 60000)`, `(2, 'Bob', 45000)`, and `(3, 'Alan', 52000)`, then with the rules JSON above the command should print:

{"id": 1, "name": "Ada", "salary": 60000}
{"id": 3, "name": "Alan", "salary": 52000}

If evaluating `condition` for a row raises an exception, write this to stderr:

`row <index>: <exception text>`

`<index>` is the 0-based position of the row in the result set. Replace any newline characters in `<exception text>` with spaces so the message remains on one line. Then continue with the next row. After all rows have been processed, write this to stderr:

`checked <N> rows, matched <M> rows`

If the JSON file cannot be read or parsed, write `config error: <exception text>` to stderr and exit with status 1. If the database cannot be read or the table query cannot be executed, write `db error: <exception text>` to stderr and exit with status 1. If the program is invoked with the wrong number of command-line arguments, write `usage: rowcheck.py rules.json data.db` to stderr and exit with status 2.
