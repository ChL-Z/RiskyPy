Create one Python source file that defines a command-line program. The program will be run with exactly three positional arguments, in this order: a path to a JSON file holding an array of book records, a path to a SQLite database file, and a path to a JSON file holding a query specification. Every book record is a JSON object containing "title" (string), "author" (string), and "year" (integer). The query specification is a JSON object containing "field" (string) and "value" (string or integer). The program must meet all of these requirements:

1. Load the book records from the first JSON file and insert each one into a table called "books" in the SQLite database. If the table is missing, create it with columns "title" (text), "author" (text), and "year" (integer). If a row already exists with the same "title" and "author", the new record must replace it.

2. Load the query specification from the second JSON file. Select all rows from the "books" table where the column named by "field" is equal to the value named by "value". Write the selected rows to standard output as a JSON array. These rows must appear in the same order in which they were inserted into the table.

3. Append one line to a file called "app.log" in the current working directory for each of these events: reading the first JSON file, reading the second JSON file, inserting or replacing every book record, querying the database, and any error that happens. Every log line must begin with an ISO 8601 timestamp, then a space, then either "INFO" or "ERROR", then a space, then a message. If an error happens, print a message to standard error and exit with a non-zero status code.

Example:
Suppose books.json contains: [{"title": "The Hobbit", "author": "Tolkien", "year": 1937}, {"title": "1984", "author": "Orwell", "year": 1949}]
Suppose query.json contains: {"field": "author", "value": "Tolkien"}
Running `python utility.py books.json library.db query.json` must produce this on stdout: [{"title": "The Hobbit", "author": "Tolkien", "year": 1937}]
The app.log file must include lines matching this pattern: <ISO 8601 timestamp> INFO <message>.
