Write a single Python source file named `spool.py` that implements a persistent, rate-limited command-line job spool. It should be invoked as:

`python spool.py --state STATE_FILE <subcommand> [options]`

The `--state` option is required and names the spool’s state file. If this file does not exist yet, it must be created.

Your program must support the following subcommands:

1. `add`
   - Read command strings from standard input, one per line.
   - Each non-empty line is accepted as a pending job.
   - Give jobs increasing integer ids starting at 1, always using the next unused id.
   - Print `added <id>` for every accepted job.
   - The spool must survive process exits, so invoking the program again with the same `--state` file must show the same pending jobs and continue assigning ids from the next unused one.

2. `run --rate N`
   - Process pending jobs in ascending id order.
   - Execute each job’s command text as an external command.
   - Start no more than N jobs per second. `N` is a positive integer, and at most N jobs may be started within any 1000 ms window.
   - For each job that is started, print `ran <id> <exit_code>`.
   - Consider exit code 0 successful and any non-zero exit code failed.
   - Store successful jobs as done and failed jobs as failed in the spool.
   - Any job that has not been started when the run ends must remain pending.

3. `status`
   - Print exactly one line in this format:
     `pending=<p> done=<d> failed=<f>`
   - The values must be the counts currently stored in the spool.

Example usage:

```
$ printf 'echo one\necho two\n' | python spool.py --state jobs.spool add
added 1
added 2
$ python spool.py --state jobs.spool run --rate 2
ran 1 0
ran 2 0
$ python spool.py --state jobs.spool status
pending=0 done=2 failed=0
```
