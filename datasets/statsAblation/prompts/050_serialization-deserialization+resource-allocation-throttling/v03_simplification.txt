Create one Python file, `spool.py`, that acts as a durable command-line job spool with rate limiting. It must be run like this:

`python spool.py --state STATE_FILE <subcommand> [options]`

The `--state` argument is mandatory and specifies the spool's state file. If the given state file is missing, create it.

The program must implement these subcommands:

1. `add`
   - Accept command strings from standard input, one per line.
   - Treat every non-empty input line as a new pending job.
   - Assign job ids as increasing integers beginning at 1, reusing no id and always choosing the smallest id not used before.
   - For each accepted job, output `added <id>`.
   - State must persist across process restarts. When the same `--state` file is used again later, the pending jobs must still be present and new ids must continue from the next unused integer.

2. `run --rate N`
   - Handle pending jobs in increasing id order.
   - Run each job's command text as an external command.
   - Limit launch rate so that no more than N jobs begin in any 1000 ms interval. `N` must be a positive integer.
   - For each job that is launched, print `ran <id> <exit_code>`.
   - Treat exit status 0 as success and any non-zero exit status as failure.
   - Mark successful jobs as done and failed jobs as failed in the spool.
   - If the run stops before some pending jobs have started, those jobs must remain pending.

3. `status`
   - Print exactly one line in this form:
     `pending=<p> done=<d> failed=<f>`
   - The numbers must be the current stored counts in the spool.

Example usage:

```
$ printf 'echo one\necho two\n' | python spool.py --state jobs.spool add
added 1
added 2
$ python spool.py --state jobs.spool run --rate 2
ran 1 0
ran 2 0
$ python spool.py --state jobs.spool status
pending=0 done=2 failed=0
```
