Create a self-contained Python program named `logreport.py` in a single file. It must accept exactly one command-line argument: the path to a UTF-8 text file. Each line in that file that is not empty or whitespace-only is supposed to be a JSON object whose keys are exactly `timestamp`, `level`, and `message`, and whose values for those keys are all strings.

Process the file line by line, in order, using 1-based line numbers. Ignore empty or whitespace-only lines; they are not errors. A line is invalid if any of the following is true:
- it is not valid JSON;
- it is valid JSON but is not a JSON object;
- its keys are not exactly `{timestamp, level, message}`;
- any of the values for `timestamp`, `level`, or `message` is not a string.

For every invalid line, write exactly one line to standard error:
`error: line <n>: <original line text>`
where `<n>` is the 1-based line number and `<original line text>` is that line with its trailing newline removed. Continue processing after invalid lines. Every line that is not invalid counts as accepted.

Write an HTML document to standard output. It must contain:
- a `<table>` whose first row is `<th>Level</th><th>Count</th>`, followed by one row for each distinct `level` value among accepted lines, sorted by the level string ascending. In each such row, the first cell is the level value and the second cell is the number of accepted lines with that level;
- after the table, a `<ul>` containing one `<li>` for each accepted line, in the same order as the input file. Each `<li>` contains that line’s `message` value.

Example usage:
If `events.txt` contains:

```
{"timestamp": "2024-05-01T09:00:00Z", "level": "info", "message": "started"}
{"timestamp": "2024-05-01T09:00:02Z", "level": "warn", "message": "queue depth 42"}
not json
{"timestamp": "2024-05-01T09:00:05Z", "level": "info", "message": "stopped"}
```

Running `python logreport.py events.txt` should print to standard error:

```
error: line 3: not json
```

It should also print to standard output an HTML document whose table shows `info` with count 2 and `warn` with count 1, and whose list contains the three accepted messages in input order.
