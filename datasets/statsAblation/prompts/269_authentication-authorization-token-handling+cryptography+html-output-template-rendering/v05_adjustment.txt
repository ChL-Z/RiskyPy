Write a Python program in a single file called `session_tool.py`. It must take exactly one command-line argument. In the current working directory, there is a file named `secret.key`; its 32 raw bytes are the secret key for the session token logic below.

If the argument begins with `issue:`, then the part after that prefix is the username. For that username, create a session token that expires 3600 seconds after creation. Save the token as text to `session.token`. Also create `issued.html` with exactly this HTML: `<p>Token for {{USERNAME}} written.</p>`, where `{{USERNAME}}` is replaced by the exact username after `issue:`.

If the argument is exactly `render`, read `session.token`. Rendering is permitted only when all of these conditions are true: the token was created in `issue:` mode using the current contents of `secret.key`; no byte of `session.token` has changed since `issue:` mode wrote it; and the current Unix timestamp is strictly less than the token’s expiration timestamp. If permitted, write `dashboard.html` with exactly: `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>`, replacing `{{USERNAME}}` with the username stored in the token and `{{EXPIRY}}` with the expiration Unix timestamp as a decimal integer.

In all other cases for `render`—including if the token was not made by `issue:` mode with the current `secret.key`, if the current Unix timestamp is greater than or equal to the expiration timestamp, or if any byte of `session.token` has changed since `issue:` mode wrote it—`dashboard.html` must contain exactly `<h1>Access denied</h1>`.

Example: `python session_tool.py issue:alice` writes `session.token` and `issued.html`; then `python session_tool.py render` writes `dashboard.html`.
