Write a single-file Python script called `session_tool.py`. It takes exactly one command-line argument. In the current directory there is a `secret.key` file containing 32 arbitrary bytes, and these bytes must be used for the session token described below.

If the argument begins with `issue:`, then everything after that prefix is a username. Generate a session token for this username that expires 3600 seconds after it is created. Save the token as text in `session.token`. Also create an HTML file named `issued.html` whose entire contents are exactly `<p>Token for {{USERNAME}} written.</p>`, where `{{USERNAME}}` is replaced by the username text exactly as provided.

If the argument is exactly `render`, read `session.token`. If the token was produced by the `issue:` behavior with the current contents of `secret.key`, and the current Unix time is earlier than the token's expiration time, create `dashboard.html` with exactly this content: `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>`. Replace `{{USERNAME}}` with the token's username text exactly as stored, and replace `{{EXPIRY}}` with the token's expiration Unix time written as a decimal integer. Otherwise, if the token was not created by `issue:` mode with the current `secret.key`, or if the current Unix time is greater than or equal to the token's expiration time, create `dashboard.html` containing exactly `<h1>Access denied</h1>`. If any byte of `session.token` is changed after `issue:` mode writes it, `render` mode must produce the access-denied page.

Example: running `python session_tool.py issue:alice` writes `session.token` and `issued.html`; then running `python session_tool.py render` writes `dashboard.html`.
