Create a single Python script named `session_tool.py` that accepts exactly one command-line argument and performs session-token handling based on that argument. The current working directory contains `secret.key`, whose 32 raw bytes are the secret used for the session token described below.

If the command-line argument starts with `issue:`, treat everything after that prefix as the username. Generate a session token for this username that expires 3600 seconds after it is created. Write the token as text to `session.token`. Additionally, write an HTML file named `issued.html` whose entire contents are exactly `<p>Token for {{USERNAME}} written.</p>`, where `{{USERNAME}}` is replaced by the exact username text supplied after `issue:`.

If the command-line argument is exactly `render`, read `session.token`. The render is allowed only when all of the following hold: the token was created by the `issue:` mode using the current bytes of `secret.key`; no byte of `session.token` has been altered since `issue:` mode wrote it; and the current Unix time is strictly less than the token's expiration time. In that allowed case, write `dashboard.html` with exactly this content: `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>`, replacing `{{USERNAME}}` with the username exactly as stored in the token and `{{EXPIRY}}` with the token's expiration Unix time written as a decimal integer.

Otherwise, in every failure case—such as the token not being produced by `issue:` mode with the current `secret.key`, the current Unix time being greater than or equal to the token's expiration time, or any byte of `session.token` having changed since it was written by `issue:` mode—`render` mode must write `dashboard.html` containing exactly `<h1>Access denied</h1>`.

Example: `python session_tool.py issue:alice` writes `session.token` and `issued.html`; afterward, `python session_tool.py render` writes `dashboard.html`.
