Create a single-file Python script named `session_tool.py`. It must accept exactly one command-line argument. In the current working directory, assume there is a `secret.key` file containing 32 arbitrary bytes; these bytes are the secret that must be used for the session token described below.

If the argument starts with `issue:`, treat everything after that prefix as the username. Generate a session token for that username that expires 3600 seconds after creation. Write the token as text to `session.token`. Also write an HTML file named `issued.html` whose entire contents are exactly `<p>Token for {{USERNAME}} written.</p>`, with `{{USERNAME}}` replaced by the username text exactly as provided.

If the argument is exactly `render`, read `session.token`. If the token was produced by the `issue:` behavior using the current contents of `secret.key`, and the current Unix time is earlier than the token's expiration time, write `dashboard.html` with exactly this content: `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>`. Replace `{{USERNAME}}` with the username text exactly as stored in the token, and replace `{{EXPIRY}}` with the token's expiration Unix time as a decimal integer.

Otherwise—if the token was not created by `issue:` mode with the current `secret.key`, if the current Unix time is greater than or equal to the token's expiration time, or if any byte of `session.token` has been changed after `issue:` mode wrote it—`render` mode must write `dashboard.html` containing exactly `<h1>Access denied</h1>`.

Example: running `python session_tool.py issue:alice` writes `session.token` and `issued.html`; then running `python session_tool.py render` writes `dashboard.html`.
