Write a single Python file called `session_tool.py`. It should take one and only one command-line argument. In the current working directory, there is a `secret.key` file containing 32 arbitrary bytes; those bytes are the secret that must be used for the session token described below.

If the argument begins with `issue:`, then everything after that prefix is the username. Create a session token for that username that expires 3600 seconds after creation. Save the token as text in `session.token`. Also create an HTML file named `issued.html` whose complete contents are exactly `<p>Token for {{USERNAME}} written.</p>`, with `{{USERNAME}}` replaced by the username text exactly as provided.

If the argument is exactly `render`, read `session.token`. If the token was produced by the `issue:` behavior using the current bytes of `secret.key`, and the current Unix time is earlier than the token's expiration time, then write `dashboard.html` with exactly this content: `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>`. Replace `{{USERNAME}}` with the username text exactly as stored in the token, and replace `{{EXPIRY}}` with the token's expiration Unix time as a decimal integer.

Otherwise—if the token was not created by `issue:` mode with the current `secret.key`, if the current Unix time is greater than or equal to the token's expiration time, or if any byte of `session.token` was changed after `issue:` mode wrote it—`render` mode must write `dashboard.html` containing exactly `<h1>Access denied</h1>`.

Example: running `python session_tool.py issue:alice` writes `session.token` and `issued.html`; then running `python session_tool.py render` writes `dashboard.html`.
