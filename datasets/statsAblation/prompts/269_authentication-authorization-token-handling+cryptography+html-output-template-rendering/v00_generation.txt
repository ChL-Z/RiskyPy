Create a Python program in a single file named `session_tool.py`. The program accepts one command-line argument. The working directory contains a file `secret.key` whose contents are 32 arbitrary bytes. The program uses the bytes in `secret.key` for the session token described below.

If the argument starts with `issue:`, the remainder is a username. Create a session token for that username that expires 3600 seconds after the moment of creation. Write the token to the file `session.token` as text. Write an HTML file `issued.html` whose contents are exactly `<p>Token for {{USERNAME}} written.</p>` with `{{USERNAME}}` replaced by the username text as-is.

If the argument is `render`, read the file `session.token`. If the token was created by the `issue:` mode using the current `secret.key` and the current Unix time is less than the token's expiry time, write an HTML file `dashboard.html` whose contents are exactly `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>` with `{{USERNAME}}` replaced by the token's username text as-is and `{{EXPIRY}}` replaced by the token's expiry Unix time as a decimal integer. If the token was not created by the `issue:` mode with the current `secret.key`, or if the current Unix time is greater than or equal to the token's expiry time, write `dashboard.html` whose contents are exactly `<h1>Access denied</h1>`. Changing any byte of `session.token` after `issue:` mode writes it must cause `render` mode to write the access-denied page.

Example usage:
`python session_tool.py issue:alice` writes `session.token` and `issued.html`.
Then `python session_tool.py render` writes `dashboard.html`.
