Create a single Python file named `session_tool.py`. It should accept exactly one command-line argument. In the current working directory, there is a file called `secret.key`; its 32 raw bytes are the secret key for the session-token behavior described below.

If the supplied argument starts with `issue:`, then everything after that prefix is the username. For that username, generate a session token whose expiration time is 3600 seconds after creation. Write the token as text to `session.token`. Also write `issued.html` containing exactly the HTML `<p>Token for {{USERNAME}} written.</p>`, where `{{USERNAME}}` is replaced by the exact username following `issue:`.

If the supplied argument is exactly `render`, read `session.token`. Rendering is allowed only when all of these conditions hold: the token was created by `issue:` mode using the current contents of `secret.key`; no byte of `session.token` has changed since `issue:` mode wrote it; and the current Unix timestamp is strictly less than the token’s expiration timestamp. If allowed, write `dashboard.html` containing exactly `<h1>Hello {{USERNAME}}</h1><p>Session expires at {{EXPIRY}}</p>`, replacing `{{USERNAME}}` with the username stored in the token and `{{EXPIRY}}` with the expiration Unix timestamp as a decimal integer.

For every other `render` case—including when the token was not made by `issue:` mode with the current `secret.key`, when the current Unix timestamp is greater than or equal to the expiration timestamp, or when any byte of `session.token` has changed since `issue:` mode wrote it—`dashboard.html` must contain exactly `<h1>Access denied</h1>`.

Example: `python session_tool.py issue:alice` writes `session.token` and `issued.html`; then `python session_tool.py render` writes `dashboard.html`.
