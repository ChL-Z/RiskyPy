Build a single Python file named `run_query.py` that is run from the command line with three arguments:

1. `sys.argv[1]` — path to an XML configuration file
2. `sys.argv[2]` — path to a JSON parameters file
3. `sys.argv[3]` — the name of the query to run

The XML configuration has this structure:

```xml
<config>
  <database>users.sqlite</database>
  <query name="active">
    SELECT id, email, certificate FROM users WHERE active = :active
  </query>
</config>
```

The JSON file is an object whose keys map to named placeholders in the selected SQL query, for example `{"active": 1}`.

Your program should:

- Read the SQLite database filename from the `<database>` element.
- Find the `<query>` element whose `name` attribute equals the third command-line argument.
- Execute that query’s SQL text against the SQLite database.
- Bind each JSON key to the corresponding `:key` placeholder in the SQL.
- Write the result set to stdout as CSV.
- Output a header row with the returned column names in query order.
- Output one CSV row per result row.

Special handling for any output column named `certificate`:

- If the cell value is a string containing a PEM-encoded X.509 certificate, replace that CSV cell with the certificate’s serial number written as a lowercase hexadecimal string with no leading zeros.
- If the serial number is zero, write `0`.
- If the cell value is NULL, is not a string, or does not contain a PEM-encoded X.509 certificate, leave the cell value unchanged.

Error behavior:

- If no `<query>` element has a `name` attribute matching the third argument, write `query not found` to stderr and exit with status 2.
- Otherwise, exit with status 0.

Example usage:

```bash
python run_query.py config.xml params.json active
```

Given the `config.xml` shown above and `params.json` containing `{"active": 1}`, the expected stdout is:

```csv
id,email,certificate
1,alice@example.com,1a2b3c
```
