Create a self-contained Python script named `endpoint_probe.py` that is run from the command line as `python endpoint_probe.py path/to/endpoints.json`. The first command-line argument is the path to a JSON file. That file contains an array of objects, and each object has a string `name` and a string `url`. For example:

```json
[
  {"name": "api", "url": "https://example.com/health"},
  {"name": "docs", "url": "https://example.org/status"}
]
```

Visit the objects in the original array order. For each object, make an HTTP GET request to its `url` with a 5-second timeout.

Stdout must consist exactly of one newline-delimited JSON object per input object, emitted in the same order as the input. Each stdout object must include these keys:

- `name`: the input object's name
- `url`: the input object's URL
- `status`: the integer HTTP response status code if the request received an HTTP response; otherwise `null`
- `body_bytes`: the number of bytes in the response body if the request received an HTTP response; otherwise `0`
- `error`: `null` if the request received an HTTP response; otherwise a string made of the exception class name, then `": "`, then the exception message

While performing the requests, enforce both of these limits:

- No more than 4 HTTP requests may be in progress at the same time.
- In any 1.0-second interval, no more than 5 request starts may occur.

Also write newline-delimited JSON diagnostics to stderr. Log a diagnostic for every request start, every request completion, and every request failure. Each stderr diagnostic must include these keys:

- `time`: Unix epoch seconds as a float
- `level`: `"INFO"` for request start and request completion, `"ERROR"` for request failure
- `name`: the request's name
- `url`: the request's URL
- `message`: exactly one of `"request started"`, `"request completed"`, or `"request failed"`

Example stderr diagnostic:

```json
{"time": 1710000000.123, "level": "INFO", "name": "api", "url": "https://example.com/health", "message": "request started"}
```
