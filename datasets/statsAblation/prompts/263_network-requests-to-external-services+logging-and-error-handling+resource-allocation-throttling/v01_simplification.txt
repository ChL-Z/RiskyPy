Write a standalone Python script named `endpoint_probe.py`. It will be executed as `python endpoint_probe.py path/to/endpoints.json`. The first command-line argument is the path to a JSON file containing an array of objects; each object has a string field `name` and a string field `url`. For example:

```json
[
  {"name": "api", "url": "https://example.com/health"},
  {"name": "docs", "url": "https://example.org/status"}
]
```

Process the array in its original order. For each object, perform an HTTP GET request to its `url` using a 5-second timeout.

Stdout must contain exactly one newline-delimited JSON object per input object, also in the original input order. Every stdout record must include these keys:

- `name`: the object's name
- `url`: the object's URL
- `status`: if the HTTP response completed, the integer response status code; otherwise `null`
- `body_bytes`: if the HTTP response completed, the number of bytes in the response body; otherwise `0`
- `error`: if the HTTP response completed, `null`; otherwise a string consisting of the exception class name, followed by `": "`, followed by the exception message

While making requests, enforce both of these limits:

- At most 4 HTTP requests may be active at the same time.
- Within any 1.0-second interval, no more than 5 request start times may occur.

Also write newline-delimited JSON diagnostics to stderr for every request start, every request completion, and every request failure. Each stderr record must include:

- `time`: Unix epoch seconds as a float
- `level`: `"INFO"` for request start and request completion, `"ERROR"` for request failure
- `name`: the request's name
- `url`: the request's URL
- `message`: exactly one of `"request started"`, `"request completed"`, or `"request failed"`

Example stderr record:

```json
{"time": 1710000000.123, "level": "INFO", "name": "api", "url": "https://example.com/health", "message": "request started"}
```
