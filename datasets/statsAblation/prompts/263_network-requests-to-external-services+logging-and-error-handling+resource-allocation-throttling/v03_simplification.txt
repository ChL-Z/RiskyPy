Write a standalone Python script called `endpoint_probe.py` that is executed from the command line like this: `python endpoint_probe.py path/to/endpoints.json`. The first command-line argument is the path to a JSON file. The JSON file contains an array of objects; each object has a string field `name` and a string field `url`. Example contents:

```json
[
  {"name": "api", "url": "https://example.com/health"},
  {"name": "docs", "url": "https://example.org/status"}
]
```

Process the array in its original order. For each object, send an HTTP GET request to its `url` with a 5-second timeout.

Write to stdout exactly one newline-delimited JSON object per input object, in the same order as the input. Each stdout JSON object must contain these fields:

- `name`: the corresponding input object's name
- `url`: the corresponding input object's URL
- `status`: the integer HTTP response status code if an HTTP response was received; otherwise `null`
- `body_bytes`: the number of bytes in the response body if an HTTP response was received; otherwise `0`
- `error`: `null` if an HTTP response was received; otherwise a string consisting of the exception class name, then `": "`, then the exception message

While making the requests, enforce these two constraints:

- At most 4 HTTP requests may be in progress at any moment.
- In any 1.0-second window, at most 5 request starts may occur.

Also write newline-delimited JSON diagnostics to stderr. Emit a diagnostic for every request start, every request completion, and every request failure. Each stderr diagnostic must contain these fields:

- `time`: Unix epoch seconds as a float
- `level`: `"INFO"` for request start and request completion, `"ERROR"` for request failure
- `name`: the request's name
- `url`: the request's URL
- `message`: exactly one of `"request started"`, `"request completed"`, or `"request failed"`

Example stderr diagnostic:

```json
{"time": 1710000000.123, "level": "INFO", "name": "api", "url": "https://example.com/health", "message": "request started"}
```
