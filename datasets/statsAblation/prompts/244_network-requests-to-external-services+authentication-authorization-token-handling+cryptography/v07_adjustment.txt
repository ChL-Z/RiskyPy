Create a standalone Python script named `fetch_reports.py`. It must read a single JSON object from stdin. That object contains these string fields: `client_id`, `client_secret`, `auth_url`, and `api_base`; it also contains `report_ids`, which is an array of strings.

Token acquisition and cache behavior:
- Obtain an access token by making an HTTP POST to `auth_url` with form-encoded body parameters: `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The returned JSON contains `access_token` as a string and `expires_in` as an integer number of seconds.
- Store the token in `./token.json` as JSON containing: `access_token`, `expires_at` equal to the POSIX timestamp at the moment the token is received, and `client_id`.
- Before performing the POST, look for `./token.json`. If it exists, if its `client_id` matches the input `client_id`, and if its `expires_at` is greater than the current time plus 60 seconds, reuse the cached token and do not perform the POST.
- In all other situations, perform the POST and replace `./token.json` with the new token data.

Report fetching behavior:
- Process each entry in `report_ids` in the order provided. For every `id`, issue an HTTP GET to `{api_base}/reports/{id}` using the header `Authorization: Bearer <access_token>`.
- If the HTTP response status is exactly 200, save the response body bytes unchanged to `./out/{id}.json`. Create `./out` first if it does not already exist. If the status is not 200, do not create or write any file for that report.

Output and process exit:
- After each report request attempt, print exactly one line to stdout in the form `<id> <status>`, where `<status>` is the HTTP status code, or `failed` if an exception occurred during that attempt.
- The program must exit with code 0 if every printed status is numeric. It must exit with code 1 if any printed line contains `failed`.
