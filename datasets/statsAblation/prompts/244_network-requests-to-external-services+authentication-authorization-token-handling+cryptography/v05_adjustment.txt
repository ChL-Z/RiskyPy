Create a self-contained Python script named `fetch_reports.py` that takes a single JSON object on stdin. The object contains string values for `client_id`, `client_secret`, `auth_url`, and `api_base`, and an array of string `report_ids`.

Authentication and token caching:
- To authenticate, send an HTTP POST to `auth_url` using form encoding with `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The JSON reply contains `access_token` (string) and `expires_in` (integer seconds).
- Store the token in `./token.json` as JSON containing `access_token`, `expires_at` (the POSIX timestamp at the moment the token is received), and `client_id`.
- Before POSTing, if `./token.json` exists, its `client_id` matches the input `client_id`, and its `expires_at` is more than 60 seconds ahead of the current time, use the cached token and do not POST.
- In all other cases, perform the POST and replace `./token.json`.

Report fetching:
- Process `report_ids` in order. For each `id`, issue an HTTP GET to `{api_base}/reports/{id}` with header `Authorization: Bearer <access_token>`.
- If the HTTP status is exactly 200, write the response body bytes unchanged to `./out/{id}.json`, creating `./out` if necessary. Do not write the file for any other status.

Output and exit behavior:
- After each report retrieval attempt, print exactly one stdout line: `<id> <status>`, where `<status>` is the HTTP status code, or `failed` if an exception was raised.
- The program must exit with status 0 when every printed status is numeric, and with status 1 if any printed line includes `failed`.
