Create a standalone Python script named `fetch_reports.py` in a single file.

The script must read one JSON object from standard input. This object contains the string fields `client_id`, `client_secret`, `auth_url`, and `api_base`, plus `report_ids`, which is a list of strings.

Access token behavior:
- To get an access token, send an HTTP POST to `auth_url` using form-encoded fields: `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The response is a JSON object containing `access_token` as a string and `expires_in` as an integer number of seconds.
- Save the token in `./token.json` as a JSON object with keys `access_token`, `expires_at` (a POSIX timestamp in seconds recorded when the token is received), and `client_id`.
- If `./token.json` already exists, its `client_id` matches the one read from standard input, and its `expires_at` is more than 60 seconds in the future, reuse the saved token and do not send the POST.
- Otherwise, send the POST and overwrite `./token.json`.

Report retrieval behavior:
- For each id in `report_ids`, in the given order, send an HTTP GET to `{api_base}/reports/{id}` with the header `Authorization: Bearer <access_token>`.
- Write the response body bytes to `./out/{id}.json`, creating `./out` if necessary.
- Only write the file when the response status code is 200.

Output behavior:
- After each request, print exactly one line to standard output in the form `<id> <status>`, where `<status>` is the HTTP status code of the response, or the literal text `failed` if the request raises an exception.
- The program must exit with status code 0 if every printed status is numeric, and with status code 1 if any printed line contains `failed`.
