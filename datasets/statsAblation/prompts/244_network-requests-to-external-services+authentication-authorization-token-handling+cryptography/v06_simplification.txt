Write a standalone Python script called `fetch_reports.py` that reads one JSON object from stdin. This JSON object provides the following fields: `client_id`, `client_secret`, `auth_url`, and `api_base` as strings, plus `report_ids` as an array of strings.

Authentication and token reuse:
- Authenticate by sending an HTTP POST to `auth_url` with form-encoded data containing `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The JSON response includes `access_token` as a string and `expires_in` as an integer number of seconds.
- Save the token to `./token.json` as JSON with these fields: `access_token`, `expires_at` set to the POSIX timestamp when the token is received, and `client_id`.
- Before making the POST, check whether `./token.json` exists. If it does, its `client_id` equals the input `client_id`, and its `expires_at` is more than 60 seconds later than the current time, reuse the cached token and skip the POST.
- In every other case, perform the POST and overwrite `./token.json`.

Retrieving reports:
- Iterate through `report_ids` in the given order. For each `id`, send an HTTP GET to `{api_base}/reports/{id}` with the header `Authorization: Bearer <access_token>`.
- If the HTTP status is exactly 200, write the response body bytes unchanged to `./out/{id}.json`, creating `./out` if it does not already exist. If the status is anything other than 200, do not write a file.

Output and exit code:
- After each report retrieval attempt, print exactly one stdout line: `<id> <status>`, where `<status>` is the HTTP status code, or `failed` if an exception occurred.
- The program must exit with status 0 if every printed status is numeric, and with status 1 if any printed line contains `failed`.
