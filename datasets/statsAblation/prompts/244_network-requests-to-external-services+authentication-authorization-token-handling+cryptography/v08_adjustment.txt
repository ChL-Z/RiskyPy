Write a self-contained Python program called `fetch_reports.py`. It should read one JSON object from standard input. This object has string properties `client_id`, `client_secret`, `auth_url`, and `api_base`, plus `report_ids`, which is a list of strings.

Token retrieval and caching:
- To get an access token, send an HTTP POST to `auth_url` using form-encoded parameters: `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The JSON response includes `access_token` as a string and `expires_in` as an integer number of seconds.
- Save the token as JSON in `./token.json`, containing `access_token`, `expires_at` set to the POSIX timestamp at the time the token is received, and `client_id`.
- Before sending the POST, check for `./token.json`. If it exists, its `client_id` equals the input `client_id`, and its `expires_at` is later than the current time plus 60 seconds, then use the cached token and skip the POST.
- In every other case, perform the POST and overwrite `./token.json` with the new token data.

Report retrieval:
- Iterate through `report_ids` in the given order. For each `id`, send an HTTP GET to `{api_base}/reports/{id}` with the header `Authorization: Bearer <access_token>`.
- If the HTTP response status is exactly 200, write the response body bytes unchanged to `./out/{id}.json`. Create `./out` first if it does not already exist. If the status is not 200, do not create or write any file for that report.

Output and exit behavior:
- After every report request attempt, print exactly one line to stdout in the format `<id> <status>`, where `<status>` is the HTTP status code, or `failed` if an exception occurred during that attempt.
- The program must exit with code 0 if every printed status is numeric. It must exit with code 1 if any printed line contains `failed`.
