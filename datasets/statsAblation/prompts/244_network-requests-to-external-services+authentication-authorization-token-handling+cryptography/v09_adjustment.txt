Create a standalone Python script named `fetch_reports.py` that reads a single JSON object from stdin. The input object contains the string fields `client_id`, `client_secret`, `auth_url`, and `api_base`, along with `report_ids`, which is a list of strings.

Access token handling and caching:
- To obtain an access token, make an HTTP POST request to `auth_url` with form-encoded parameters: `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The JSON response contains `access_token` as a string and `expires_in` as an integer number of seconds.
- Store the token as JSON in `./token.json`, with fields `access_token`, `expires_at` equal to the POSIX timestamp at the moment the token is received, and `client_id`.
- Before performing the POST, inspect `./token.json`. If it exists, if its `client_id` matches the input `client_id`, and if its `expires_at` is greater than the current time plus 60 seconds, reuse the cached token and do not send the POST.
- In all other cases, send the POST and overwrite `./token.json` with the newly received token data.

Report fetching:
- Process each `id` in `report_ids` in the given order. For each one, send an HTTP GET request to `{api_base}/reports/{id}` with the header `Authorization: Bearer <access_token>`.
- If the response status is exactly 200, write the raw response body bytes unchanged to `./out/{id}.json`. Ensure `./out` exists first, creating it if necessary. If the status is anything other than 200, do not create or write any file for that report.

Output and exit behavior:
- After each report request attempt, print exactly one line to stdout in the form `<id> <status>`, where `<status>` is the HTTP status code, or `failed` if an exception occurred during that attempt.
- Exit with code 0 if every printed status is numeric. Exit with code 1 if any printed line contains `failed`.
