Build a single-file Python program named `fetch_reports.py`. The program reads exactly one JSON object from stdin. That object provides string values for `client_id`, `client_secret`, `auth_url`, and `api_base`, plus `report_ids`, which is a list of strings.

Tokenizer/token access logic:
- Obtain an access token by sending an HTTP POST to `auth_url`, using form-encoded fields: `grant_type=client_credentials`, `client_id`, and `client_secret`.
- The JSON response includes `access_token` as a string and `expires_in` as an integer number of seconds.
- Persist the token in `./token.json` as JSON with keys `access_token`, `expires_at` (a POSIX timestamp in seconds captured when the token is received), and `client_id`.
- If `./token.json` is already present, its `client_id` equals the stdin `client_id`, and its `expires_at` is more than 60 seconds in the future, reuse the stored token and skip the POST.
- In all other cases, perform the POST and overwrite `./token.json`.

Report-fetching logic:
- Process each id in `report_ids` in the original order. For every id, send an HTTP GET to `{api_base}/reports/{id}` with header `Authorization: Bearer <access_token>`.
- Save the response body bytes to `./out/{id}.json`, creating `./out` first if needed.
- Write the file only when the response status code is exactly 200.

Output and exit behavior:
- After each request, print exactly one stdout line as `<id> <status>`, where `<status>` is the HTTP status code, or the literal word `failed` if the request raises an exception.
- The process must return exit code 0 when every printed status is numeric, and exit code 1 if any printed line contains `failed`.
