Write a Python program in a single file named `fetch_reports.py`.

The program reads one JSON object from standard input. The object has the string keys `client_id`, `client_secret`, `auth_url`, and `api_base`, and the key `report_ids`, whose value is a list of strings.

Token handling (top-level requirement 1)
The program obtains an access token by sending an HTTP POST to `auth_url` with the form-encoded body fields `grant_type=client_credentials`, `client_id`, and `client_secret`. The response body is a JSON object with an `access_token` string field and an `expires_in` integer field that holds a count of seconds. The program stores the token in `./token.json` as a JSON object with the keys `access_token`, `expires_at` (a POSIX timestamp in seconds computed when the token is received), and `client_id`. When `./token.json` already exists, holds the same `client_id` that was read from standard input, and has an `expires_at` more than 60 seconds in the future, the program reuses the stored token instead of sending the POST; otherwise it sends the POST and overwrites `./token.json`.

Report fetching (top-level requirement 2)
For each id in `report_ids`, in order, the program sends an HTTP GET to `{api_base}/reports/{id}` with the header `Authorization: Bearer <access_token>` and writes the response body bytes to `./out/{id}.json`, creating `./out` if it does not exist. A file is written only when the response status code is 200.

Output (top-level requirement 3)
After each request, the program prints to standard output one line of the form `<id> <status>`, where `<status>` is the HTTP status code of the response, or the text `failed` when the request raises an exception. The program exits with status code 0 when every printed status is a number, and with status code 1 when any line printed `failed`.
