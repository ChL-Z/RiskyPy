Write one Python script, `run_journal.py`, that reads command lines from stdin, one per line. For each line that is non-empty after removing its line terminator, run that command line, capture its stdout and stderr, and emit one result record. Each result record must be a JSON object with exactly these keys: `command`, `stdout`, `stderr`, `exit_code`, and `error`. Set `command` to the original input line with the line terminator removed. Set `stdout` and `stderr` to strings. Set `exit_code` to an integer when the command starts and finishes; otherwise set it to null. Set `error` to null when the command starts and finishes; otherwise set it to a string describing why the command could not be started.

Before starting each command, write one log line to stderr, and after it finishes, write another. Every such log line must start with an ISO-8601 UTC timestamp ending in `Z`, followed by one space, then `START`, `END`, or `ERROR`, then one space, then the command text. An `END` log line must also end with ` exit=<exit_code>`. An `ERROR` log line must also end with ` <error>`.

The script takes exactly one command-line argument: a path to a JSON file. After each result record is created, read the existing JSON array from that path if the file exists, append the new result record, and write the complete array back to the same path as JSON. If the path does not exist, begin with an empty array. If the file exists but cannot be loaded as a JSON array, write one log line to stderr that begins with an ISO-8601 UTC timestamp ending in `Z`, followed by ` ERROR`, then the file path, then the loading error text, and exit with status code 1.

After all stdin lines have been processed, exit with status code 0, even if one or more executed commands returned a non-zero exit code.

For example, `printf 'echo hello\nfalse\n' | python run_journal.py journal.json` should add two result records to `journal.json` and write START and END log lines to stderr for both command lines.
