Write a standalone command-line Python program named `render_releases.py`. It should be invoked with two positional arguments, in this order: the input XML file path and the output HTML file path, for example:

    python render_releases.py releases.xml index.html

The XML file has a `<releases>` root element containing any number of `<release>` child elements. Every `<release>` has `version` and `date` attributes. Each `<release>` contains exactly one `<title>` element, immediately followed by exactly one `<notes>` element. The `<notes>` element contains one or more `<note>` elements, and each `<note>` holds the text of one release note. For example:

    <releases>
      <release version="1.4.0" date="2024-05-01">
        <title>Spring update</title>
        <notes>
          <note>Fixed the login redirect loop.</note>
          <note>Added CSV export to the reports page.</note>
        </notes>
      </release>
      <release version="1.3.2" date="2024-03-18">
        <title>Maintenance release</title>
        <notes>
          <note>Updated timezone data.</note>
        </notes>
      </release>
    </releases>

The program must generate a full HTML document and write it to the second command-line argument. The document must begin with `<!DOCTYPE html>`. Its root `<html>` element must contain a `<head>` with a `<title>` whose text is `Releases`, followed by a `<body>`.

For each XML `<release>`, in the same order as they appear in the XML, the body must contain one section element:

    <section class="release" data-version="V" data-date="D">

where `V` and `D` are that release’s `version` and `date` attribute values. Inside that section, place an `<h2>` containing the release’s `<title>` text, followed by a `<ul>`. The `<ul>` must have exactly one `<li>` for each `<note>` in that release’s `<notes>` element, and each `<li>` must contain the corresponding note text.

All text and attribute data taken from the XML must remain recoverable exactly as it was when an HTML parser reads the generated file. In particular, title and note text must be treated by a browser as plain text, not as HTML markup. Apply any necessary HTML escaping.

After all release sections, the `<body>` must end with:

    <p id="build-id">IDENTIFIER</p>

`IDENTIFIER` must be exactly 32 characters long and may contain only lowercase ASCII letters (`a`–`z`) and digits (`0`–`9`). A new random identifier must be produced each time the program runs.
