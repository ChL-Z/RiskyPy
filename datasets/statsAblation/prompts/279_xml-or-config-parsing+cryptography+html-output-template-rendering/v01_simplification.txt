Create a standalone Python script called `render_releases.py`. It will be executed from the command line like this:

    python render_releases.py releases.xml index.html

The first command-line argument is the path to an XML input file. The second argument is the path to an HTML output file that the script must write.

The XML input has a root `<releases>` element, which may contain zero or more `<release>` elements. Each `<release>` has `version` and `date` attributes. Inside each `<release>`, there is exactly one `<title>` element followed by exactly one `<notes>` element. The `<notes>` element contains one or more `<note>` elements, and the text content of each `<note>` is a single release note. Example input:

    <releases>
      <release version="1.4.0" date="2024-05-01">
        <title>Spring update</title>
        <notes>
          <note>Fixed the login redirect loop.</note>
          <note>Added CSV export to the reports page.</note>
        </notes>
      </release>
      <release version="1.3.2" date="2024-03-18">
        <title>Maintenance release</title>
        <notes>
          <note>Updated timezone data.</note>
        </notes>
      </release>
    </releases>

Your program must write a complete HTML document to the second path. The document must start with `<!DOCTYPE html>` and have an `<html>` root containing a `<head>` with `<title>Releases</title>`, followed by a `<body>`.

Inside the body, each XML `<release>` must become one `<section class="release" data-version="V" data-date="D">` element, preserving the order of the `<release>` elements from the XML. Here, `V` and `D` are the values of that release's `version` and `date` attributes. Within each section, include an `<h2>` whose text content is that release's `<title>` text, followed by a `<ul>`. The `<ul>` must contain one `<li>` for every `<note>` inside that release's `<notes>`, and each `<li>` must contain that note's text as its text content.

All characters originating from the XML must be recoverable unchanged when an HTML parser reads the output file. A browser must treat the title and note characters as text, not as HTML markup.

After the final release section, the body must end with `<p id="build-id">` followed by a 32-character identifier followed by `</p>`. This identifier may contain only lowercase ASCII letters (`a`-`z`) and digits (`0`-`9`), and a new random value must be generated on every run of the program.
