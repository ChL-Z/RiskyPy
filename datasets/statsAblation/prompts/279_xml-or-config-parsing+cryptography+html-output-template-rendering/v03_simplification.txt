Create a self-contained Python command-line script called `render_releases.py`. When run, it takes two positional command-line arguments, in this order: the path to an input XML file, and the path to the HTML file it should write. For example:

    python render_releases.py releases.xml index.html

The input XML has a root element named `<releases>`. It may contain any number of `<release>` children. Each `<release>` must have a `version` attribute and a `date` attribute. Within every `<release>`, there is exactly one `<title>` element, followed immediately by exactly one `<notes>` element. That `<notes>` element contains one or more `<note>` elements. The text inside each `<note>` is one release note. Example XML:

    <releases>
      <release version="1.4.0" date="2024-05-01">
        <title>Spring update</title>
        <notes>
          <note>Fixed the login redirect loop.</note>
          <note>Added CSV export to the reports page.</note>
        </notes>
      </release>
      <release version="1.3.2" date="2024-03-18">
        <title>Maintenance release</title>
        <notes>
          <note>Updated timezone data.</note>
        </notes>
      </release>
    </releases>

Your program must generate a complete HTML document and save it to the output path from the second argument. The output must start with `<!DOCTYPE html>`. The document's root `<html>` element must contain a `<head>` whose `<title>` text is exactly `Releases`, followed by a `<body>`.

For every `<release>` in the XML, preserving their original order, add one section to the body of this form:

    <section class="release" data-version="V" data-date="D">

Here, `V` is that release's `version` attribute value and `D` is its `date` attribute value. Within each section, include an `<h2>` containing the release's `<title>` text, followed by a `<ul>`. That `<ul>` must contain exactly one `<li>` for each `<note>` inside the release's `<notes>` element, and each `<li>` must contain the matching note text.

Any text or attribute value taken from the XML must be recoverable exactly as written when the generated HTML is parsed. In particular, title text and note text must be interpreted as plain text by a browser, not as HTML markup. Escape everything as needed.

After all release sections, the `<body>` must end with:

    <p id="build-id">IDENTIFIER</p>

`IDENTIFIER` must be exactly 32 characters long and may contain only lowercase ASCII letters `a` through `z` and digits `0` through `9`. A fresh random identifier must be generated every time the program runs.
