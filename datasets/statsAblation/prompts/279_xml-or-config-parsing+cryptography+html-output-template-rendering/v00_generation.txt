Write a Python program in a single file named `render_releases.py`.

The program is invoked from the command line as:

    python render_releases.py releases.xml index.html

The first argument is the path of an XML file. The second argument is the path of an HTML file the program writes.

The input XML has a root element `<releases>` containing zero or more `<release>` elements. Every `<release>` element carries a `version` attribute and a `date` attribute, and contains one `<title>` element followed by one `<notes>` element. Within `<notes>` there is one or more `<note>` elements; the text content of a `<note>` is a single release note. An input file looks like:

    <releases>
      <release version="1.4.0" date="2024-05-01">
        <title>Spring update</title>
        <notes>
          <note>Fixed the login redirect loop.</note>
          <note>Added CSV export to the reports page.</note>
        </notes>
      </release>
      <release version="1.3.2" date="2024-03-18">
        <title>Maintenance release</title>
        <notes>
          <note>Updated timezone data.</note>
        </notes>
      </release>
    </releases>

1. The program writes a full HTML document to the second path. The document begins with `<!DOCTYPE html>` and has an `<html>` root containing a `<head>` with `<title>Releases</title>`, and a `<body>`. Inside the body, each `<release>` from the XML file produces one `<section class="release" data-version="V" data-date="D">` element, in the same order the `<release>` elements appear in the XML, where V and D are that element's `version` and `date` attribute values. Inside each section is an `<h2>` whose text content is the release's `<title>` text, then a `<ul>` containing one `<li>` per `<note>` element inside that release's `<notes>`, where each `<li>`'s text content is the text of that note. Every character that came from the XML must be recoverable unchanged by an HTML parser reading the written file, and a browser must display the note and title characters as text rather than as markup.

2. After the last release section, the body ends with `<p id="build-id">` followed by a 32-character identifier followed by `</p>`. The identifier consists only of lowercase ASCII letters (`a`-`z`) and digits (`0`-`9`), and is derived from a new random value on each run of the program.
