Write a Python program contained in a single file named `inventory.py`.

The program is invoked as:

```
python inventory.py settings.xml < paths.txt
```

It takes exactly one command-line argument: the path to an XML settings file. It reads file paths from standard input, one path per line, until end of input.

**Settings file format.** The settings file is an XML document whose root element is `<inventory>`, containing:

- exactly one `<output>` element with a `path` attribute naming the file that results are written to,
- exactly one `<log>` element with a `path` attribute naming the file that log messages are written to,
- zero or more `<rule>` elements, each with an `extension` attribute (for example `".txt"`) and a `category` attribute,
- zero or one `<default>` element with a `category` attribute.

**Requirement 1 — results.** For each line read from standard input, strip the trailing newline and any leading or trailing whitespace; skip lines that are empty after stripping. For each remaining line, determine the path's extension as the substring starting at the last `.` character in the final `/`-separated segment of the line. If that segment contains no `.`, the path has no extension. The category is the `category` attribute of the first `<rule>` element whose `extension` attribute equals the path's extension (compared case-sensitively). If no `<rule>` matches, the category is the `category` attribute of the `<default>` element when that element is present, and `unclassified` otherwise. For each path whose file exists on disk, append one line to the output file, creating that file if it does not exist: the path, a single tab character, the category, then a newline.

**Requirement 2 — logging.** Append one line per input path, in the order the paths were read, to the log file, creating that file if it does not exist. Each line has the form `LEVEL: message`, where `LEVEL` is followed by a colon and one space. For a path whose file exists on disk, the line is `INFO: classified <path> as <category>` with `<path>` and `<category>` replaced by the path from standard input and the category determined above. For a path whose file does not exist, the line is `ERROR: missing <path>` and no line is appended to the output file for that path.

**Requirement 3 — settings failures.** If the settings file cannot be read, or its contents cannot be parsed as XML, write one line to standard error containing the settings file path and exit with status code 1. If the contents parse as XML but the document has no `<output>` element or no `<log>` element, write one line to standard error containing the settings file path and exit with status code 1.

**Example.** With `settings.xml` containing:

```xml
<inventory>
  <output path="results.tsv"/>
  <log path="inventory.log"/>
  <rule extension=".txt" category="text"/>
  <rule extension=".png" category="image"/>
  <default category="other"/>
</inventory>
```

and standard input consisting of the four lines `notes.txt`, `photos/cover.png`, `readme`, `missing.pdf`, where `notes.txt`, `photos/cover.png` and `readme` exist on disk and `missing.pdf` does not, `results.tsv` receives three lines (`notes.txt` and `text`, `photos/cover.png` and `image`, `readme` and `other`, each pair separated by a tab), and `inventory.log` receives four lines in this order:

```
INFO: classified notes.txt as text
INFO: classified photos/cover.png as image
INFO: classified readme as other
ERROR: missing missing.pdf
```
