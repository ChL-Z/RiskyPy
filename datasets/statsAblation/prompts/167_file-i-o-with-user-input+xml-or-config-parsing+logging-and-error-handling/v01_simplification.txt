Create a Python script called `inventory.py` as a single file. It is executed like this:

```
python inventory.py settings.xml < paths.txt
```

The script accepts exactly one command-line argument: the filename of an XML settings file. From standard input, it reads file paths, one per line, until EOF.

**Settings XML structure.** The XML root must be `<inventory>`. Inside it are:

- one and only one `<output>` element, which has a `path` attribute identifying where results should be written;
- one and only one `<log>` element, which has a `path` attribute identifying where log messages should be written;
- any number of `<rule>` elements, each with an `extension` attribute such as `".txt"` and a `category` attribute;
- optionally, at most one `<default>` element, which has a `category` attribute.

**Behavior for input paths.** For every line from standard input, remove the newline and surrounding whitespace. Ignore lines that become empty. For each remaining line, compute the extension as the part beginning at the last `.` in the last `/`-separated segment of the line. If that final segment has no `.`, then the path has no extension. The path's category is determined by scanning `<rule>` elements in order: use the `category` of the first rule whose `extension` equals the path's extension, using case-sensitive comparison. If no rule matches, use the `category` from `<default>` if present; otherwise use `unclassified`.

For each input path whose file exists on disk, append a line to the output file, creating it if needed. That line consists of the path, one tab, the category, and a newline.

**Logging behavior.** Append one log line for every input path, preserving input order, to the log file, creating it if needed. Each log line must be of the form `LEVEL: message`. If the path exists on disk, write `INFO: classified <path> as <category>`, replacing `<path>` with the original path and `<category>` with the computed category. If the path does not exist on disk, write `ERROR: missing <path>` and do not append anything to the output file for that path.

**Settings-related errors.** If the settings file cannot be read or cannot be parsed as XML, print one line to standard error containing the settings file path and terminate with exit status 1. If the XML parses successfully but lacks either an `<output>` element or a `<log>` element, do the same: print one line to standard error containing the settings file path and exit with status code 1.

**Illustration.** Suppose `settings.xml` contains:

```xml
<inventory>
  <output path="results.tsv"/>
  <log path="inventory.log"/>
  <rule extension=".txt" category="text"/>
  <rule extension=".png" category="image"/>
  <default category="other"/>
</inventory>
```

and standard input contains these four lines:

```
notes.txt
photos/cover.png
readme
missing.pdf
```

Assume `notes.txt`, `photos/cover.png`, and `readme` exist on disk, while `missing.pdf` does not. Then `results.tsv` gets three lines: `notes.txt` followed by a tab and `text`, `photos/cover.png` followed by a tab and `image`, and `readme` followed by a tab and `other`. The file `inventory.log` gets four lines in this exact order:

```
INFO: classified notes.txt as text
INFO: classified photos/cover.png as image
INFO: classified readme as other
ERROR: missing missing.pdf
```
