Write a single-file Python program named `inventory.py`. It is run from the command line as:

```
python inventory.py settings.xml < paths.txt
```

The program takes exactly one command-line argument: the path to an XML settings file. It reads file paths from standard input, one per line, until EOF.

### XML settings file

The XML document's root element must be `<inventory>`. It contains:

- Exactly one `<output>` element, with a `path` attribute indicating the file where results are written.
- Exactly one `<log>` element, with a `path` attribute indicating the file where log messages are written.
- Zero or more `<rule>` elements. Each `<rule>` has an `extension` attribute, such as `".txt"`, and a `category` attribute.
- Optionally, at most one `<default>` element, with a `category` attribute.

### Processing input paths

For each line read from standard input:

1. Remove the newline and any surrounding whitespace.
2. Discard the line if it becomes empty.
3. Determine the path's extension as follows: take the last `/`-separated segment of the path, then take the portion starting at the last `.` in that segment. If the final segment contains no `.`, the path has no extension.
4. Determine the path's category by checking `<rule>` elements in their given order. Use the `category` of the first rule whose `extension` exactly matches the path's extension, using case-sensitive comparison. If no rule matches, use the `category` from `<default>` if it exists; otherwise use `unclassified`.

For every input path whose file exists on disk, append a line to the output file, creating the output file if necessary. The appended line must contain the path, a tab character, the category, and a newline.

### Logging

Append one log line for every input path, preserving the original input order, to the log file, creating the log file if necessary. Each log line must have the form `LEVEL: message`.

- If the path exists on disk, write:

```
INFO: classified <path> as <category>
```

where `<path>` is the original path and `<category>` is the computed category.

- If the path does not exist on disk, write:

```
ERROR: missing <path>
```

and do not append anything to the output file for that path.

### Settings-related failures

If the settings file cannot be read or cannot be parsed as XML, print one line to standard error containing the settings file path and terminate with exit status `1`.

If the XML parses successfully but does not contain either an `<output>` element or a `<log>` element, do the same: print one line to standard error containing the settings file path and exit with status code `1`.

### Example

Suppose `settings.xml` contains:

```xml
<inventory>
  <output path="results.tsv"/>
  <log path="inventory.log"/>
  <rule extension=".txt" category="text"/>
  <rule extension=".png" category="image"/>
  <default category="other"/>
</inventory>
```

and standard input contains:

```
notes.txt
photos/cover.png
readme
missing.pdf
```

Assume `notes.txt`, `photos/cover.png`, and `readme` exist on disk, while `missing.pdf` does not. Then `results.tsv` receives three lines:

```
notes.txt	text
photos/cover.png	image
readme	other
```

where `\t` represents a tab character. The file `inventory.log` receives four lines in this exact order:

```
INFO: classified notes.txt as text
INFO: classified photos/cover.png as image
INFO: classified readme as other
ERROR: missing missing.pdf
```
