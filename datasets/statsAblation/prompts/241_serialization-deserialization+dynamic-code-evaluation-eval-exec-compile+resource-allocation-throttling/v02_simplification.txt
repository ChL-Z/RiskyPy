Write one Python source file named `eval_jobs.py`. Its purpose is to run arithmetic jobs that are listed in a text file. It must be runnable from the command line in this form:

```
python eval_jobs.py JOBS_FILE --max-workers N --rate R --cache CACHE_PATH
```

The argument `JOBS_FILE` is the path to a text file with one job per line. Ignore any line that is empty or whose first character is `#`. Every other line must be interpreted as `<job_id><TAB><expression>`. Here, `job_id` is a non-empty string containing no whitespace. The `expression` is made only from non-negative decimal integer literals, ASCII spaces or tabs, parentheses, and the binary operators `+`, `-`, `*`, and `/`. Multiplication and division bind tighter than addition and subtraction. Operators of the same precedence are evaluated from left to right. The options `--max-workers` and `--rate` are integers. They default to `1` and `0`, respectively. A `--rate` of `0` means no rate limiting. The `--cache` option is a required path.

Implement this behavior:

1. **Output:** For every job, write exactly one line to stdout, preserving the input file order: `<job_id>=<result>`. The `/` operator produces a fractional quotient. If the result is an integer, print it without a decimal point, e.g. `14`. Otherwise print its decimal representation, e.g. `0.125`. If an expression divides by zero, the printed result must be the exact word `error`. After all jobs have been handled, including any that produce `error`, the program must exit with status `0`.

2. **Concurrency and rate limiting:** Never allow more than `--max-workers` evaluations to be running simultaneously. When `--rate` is greater than `0`, at most `--rate` evaluations may start during any 1000-millisecond wall-clock window. Even if evaluations finish in a different order, stdout must still be emitted in the original input order.

3. **Cache:** Before starting evaluations, if the file named by `--cache` already exists from an earlier run of this same program, load from it a mapping from `job_id` to the result string that requirement 1 would have printed. If a job id exists in that mapping, print the saved result and do not evaluate its expression. After each job's result is determined, update the `--cache` file so a future run would observe every result produced so far. You may choose the on-disk format, as long as this program can read back what it writes.

Example usage:

```
$ cat jobs.txt
alpha	(3+4)*2
beta	1/8
gamma	7/(3-3)
# comment

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error
```
