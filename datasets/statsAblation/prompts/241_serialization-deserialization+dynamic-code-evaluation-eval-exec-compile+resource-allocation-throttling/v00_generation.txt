Write a Python program in a single file named `eval_jobs.py`.

The program is a batch job runner that evaluates arithmetic jobs listed in a text file. It is invoked as:

```
python eval_jobs.py JOBS_FILE --max-workers N --rate R --cache CACHE_PATH
```

`JOBS_FILE` is a path to a text file with one job per line. Each line that is neither empty nor starting with `#` has the form `<job_id><TAB><expression>`, where `job_id` is a non-empty string containing no whitespace, and `expression` is an arithmetic expression built from non-negative decimal integer literals, ASCII spaces or tabs, parentheses, and the binary operators `+`, `-`, `*`, `/`. In that expression, `*` and `/` bind tighter than `+` and `-`, and operators of the same precedence are evaluated left to right. `--max-workers` (default `1`) and `--rate` (default `0`) are integers; `--rate 0` means no rate cap. `--cache` is a required path.

Implement these three requirements:

1. Output. For each job, in the order jobs appear in `JOBS_FILE`, print exactly one line to stdout: `<job_id>=<result>`. The `/` operator produces the fractional quotient. If the result is a whole number, print it with no decimal point (for example `14`). Otherwise print its decimal representation (for example `0.125`). If an expression divides by zero, print the literal text `error` as its result. The program exits with status 0 after processing every job, including jobs whose result is `error`.

2. Throttling. At no moment may more than `--max-workers` job evaluations be in progress at the same time. When `--rate` is greater than 0, no more than `--rate` job evaluations may begin within any 1000-millisecond window measured by wall-clock time. Results must still be printed in input order regardless of the order in which the evaluations finish.

3. Cache. Before starting evaluations, if a file already exists at `--cache` from a previous run of this same program, load from it the mapping of `job_id` to the result string that requirement 1 would have printed. If a job's id is present in the loaded mapping, print its stored result and do not evaluate its expression. After each job's result is determined, update the file at `--cache` so that a subsequent run observes every result produced so far. The on-disk representation is chosen by your implementation; the only constraint is that this program reads back what it wrote.

Example run:

```
$ cat jobs.txt
alpha	(3+4)*2
beta	1/8
gamma	7/(3-3)
# comment

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error
```
