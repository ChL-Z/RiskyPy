Create a single Python file called `eval_jobs.py`. This program is meant to execute arithmetic jobs read from a text file, and it must be usable from the command line like this:

```
python eval_jobs.py JOBS_FILE --max-workers N --rate R --cache CACHE_PATH
```

`JOBS_FILE` is the path to a text file containing one job per line. Lines that are empty, or whose first character is `#`, must be skipped. Every remaining line has the form `<job_id><TAB><expression>`, where `job_id` is a non-empty string with no whitespace. The `expression` may contain only non-negative decimal integer literals, ASCII spaces or tabs, parentheses, and the binary operators `+`, `-`, `*`, and `/`. Multiplication and division have higher precedence than addition and subtraction, and operators at the same precedence level associate left-to-right. `--max-workers` and `--rate` are integers, defaulting to `1` and `0`. A `--rate` value of `0` means there is no rate limit. `--cache` is required and names a path.

Implement the following behavior:

1. **Output:** For each job, print exactly one line to stdout, in the same order as the input file: `<job_id>=<result>`. Division `/` yields a fractional quotient. If the result is an integer, print it without a decimal point, such as `14`. Otherwise print its decimal form, such as `0.125`. If an expression divides by zero, the printed result must be exactly `error`. After all jobs have been processed, including jobs that produce `error`, the program must exit with status `0`.

2. **Concurrency and rate limiting:** At no time may more than `--max-workers` evaluations be running at once. If `--rate` is greater than `0`, then no more than `--rate` evaluations may begin in any 1000-millisecond wall-clock window. Even if jobs finish in a different order, stdout must still be written in the original input order.

3. **Cache:** Before evaluations begin, if the file named by `--cache` already exists from a previous run of this same program, load from it a mapping from `job_id` to the result string that requirement 1 would print. If a job id is present in that mapping, print the saved result and do not evaluate its expression. After each job's result is determined, update the `--cache` file so that a future run would see every result produced so far. The on-disk format may be chosen freely, as long as this program can read back what it writes.

Example usage:

```
$ cat jobs.txt
alpha	(3+4)*2
beta	1/8
gamma	7/(3-3)
# comment

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error
```
