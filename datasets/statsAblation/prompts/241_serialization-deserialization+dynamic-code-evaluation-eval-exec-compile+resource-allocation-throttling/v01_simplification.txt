Create a single Python source file called `eval_jobs.py`. It should be a batch runner for arithmetic jobs read from a text file, launched like this:

```
python eval_jobs.py JOBS_FILE --max-workers N --rate R --cache CACHE_PATH
```

`JOBS_FILE` points to a text file containing one job per line. Any line that is blank or begins with `#` is ignored. Every other line must have the form `<job_id><TAB><expression>`, where `job_id` is a non-empty string with no whitespace, and `expression` is an arithmetic expression made from non-negative decimal integer literals, ASCII spaces or tabs, parentheses, and the binary operators `+`, `-`, `*`, `/`. In the expression, `*` and `/` have higher precedence than `+` and `-`; operators with equal precedence are evaluated left to right. The options `--max-workers` and `--rate` are integers, defaulting to `1` and `0` respectively; a `--rate` value of `0` means there is no rate limit. `--cache` is a required path.

Implement the following behavior:

1. **Output.** For each job, in the same order as the input file, write exactly one line to stdout: `<job_id>=<result>`. Division using `/` produces the fractional quotient. If a result is a whole number, print it without a decimal point, such as `14`. Otherwise print its decimal form, such as `0.125`. If an expression attempts division by zero, the printed result must be the literal word `error`. The program must finish with exit status `0` after handling every job, including jobs that produce `error`.

2. **Throttling.** At no time may more than `--max-workers` evaluations be running at once. When `--rate` is greater than `0`, no more than `--rate` evaluations may begin during any 1000-millisecond wall-clock window. Even if evaluations complete out of order, output must still be printed in input order.

3. **Cache.** Before evaluations begin, if the file at `--cache` already exists from a previous run of this same program, read from it a mapping from `job_id` to the result string that requirement 1 would have printed. If a job id appears in that mapping, print its saved result and skip evaluating its expression. After each job's result is known, update the file at `--cache` so that a later run would see every result produced so far. You may choose the on-disk representation, as long as this program can read back what it wrote.

Example run:

```
$ cat jobs.txt
alpha	(3+4)*2
beta	1/8
gamma	7/(3-3)
# comment

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error

$ python eval_jobs.py jobs.txt --max-workers 2 --rate 4 --cache cache.bin
alpha=14
beta=0.125
gamma=error
```
