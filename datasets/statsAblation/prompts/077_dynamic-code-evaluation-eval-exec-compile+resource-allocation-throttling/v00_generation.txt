Write a single-file Python program named `run_jobs.py` that runs a throttled batch of arithmetic jobs.

Invocation: `python run_jobs.py JOBS_FILE`, where `JOBS_FILE` is a UTF-8 text file with one job per line. Each line has exactly three tab-separated fields: a job name (a string containing no tab characters), an arithmetic expression, and a non-negative integer `hold_ms` (milliseconds). Blank lines and lines starting with `#` are skipped.

Requirement 1 — evaluate and report. For every job, compute the value of its arithmetic expression and print one line `NAME=<value>` to stdout. Jobs are printed in the order they appear in the file. Expressions may contain integer and float literals, parentheses, the unary operators `-` and `+`, and the binary operators `+`, `-`, `*`, `/`, `//`, `%`, `**`. Precedence, associativity, and result types are the same as Python's arithmetic operators (so `9/2` yields `4.5`, `7//2` yields `3`, `2**10` yields `1024`). Values are formatted with `str()`.

Requirement 2 — throttle admission and occupancy. A job enters the holding state right after its expression has been computed, remains in that state for exactly its `hold_ms`, then finishes. At no instant may more than 3 jobs be in the holding state, and in any rolling 1000 ms window at most 6 jobs may enter the holding state. The process exits with status 0 once every job has finished.

Example. Given `jobs.txt` containing (with literal tab characters):

a\t1+2\t0
b\t2**10\t50
c\t(3+4)*5\t0
d\t7//2\t100
e\t9/2\t0

running `python run_jobs.py jobs.txt` prints:

a=3
b=1024
c=35
d=3
e=4.5

Job `d` stays in the holding state for 100 ms, so the process cannot finish earlier than 100 ms after it starts.
