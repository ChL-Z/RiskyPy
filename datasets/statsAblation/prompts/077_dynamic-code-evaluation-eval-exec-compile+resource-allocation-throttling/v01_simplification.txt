Create a standalone Python script called `run_jobs.py` that processes a constrained batch of arithmetic tasks.

The script is executed as:

`python run_jobs.py JOBS_FILE`

`JOBS_FILE` is a UTF-8 text file containing one job per line. Each job line must have exactly three fields separated by tab characters:

1. a job name string that contains no tab characters,
2. an arithmetic expression,
3. a non-negative integer `hold_ms` measured in milliseconds.

Empty lines and lines beginning with `#` must be ignored.

Task 1 — compute and output results. For each job, evaluate its arithmetic expression and write a single stdout line in the form `NAME=<value>`. Output jobs in the same order they appear in the input file. Expressions can include integer and float literals, parentheses, unary `-` and `+`, and the binary operators `+`, `-`, `*`, `/`, `//`, `%`, and `**`. Operator precedence, associativity, and result values/types must match Python arithmetic, e.g. `9/2` gives `4.5`, `7//2` gives `3`, and `2**10` gives `1024`. Convert each computed value to text with `str()`.

Task 2 — enforce holding limits. Immediately after a job's expression has been computed, that job enters the holding state. It stays in that state for exactly `hold_ms` milliseconds and then finishes. At no moment may more than 3 jobs be simultaneously in the holding state. Also, during any sliding 1000 ms interval, at most 6 jobs may enter the holding state. After every job has finished, the process must exit with status 0.

Example. Suppose `jobs.txt` contains the following lines, where each `\t` denotes a literal tab character:

a\t1+2\t0
b\t2**10\t50
c\t(3+4)*5\t0
d\t7//2\t100
e\t9/2\t0

Then `python run_jobs.py jobs.txt` prints:

a=3
b=1024
c=35
d=3
e=4.5

Because job `d` remains in the holding state for 100 ms, the process cannot complete earlier than 100 ms after it starts.
