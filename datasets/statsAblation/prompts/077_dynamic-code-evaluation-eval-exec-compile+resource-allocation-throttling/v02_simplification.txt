Write a standalone Python script named `run_jobs.py` that handles a limited batch of arithmetic jobs.

The script is run like this:

`python run_jobs.py JOBS_FILE`

`JOBS_FILE` is a UTF-8 text file with one job per line. Every job line must contain exactly three tab-separated fields:

1. a job name with no tab characters in it,
2. an arithmetic expression,
3. a non-negative integer `hold_ms`, in milliseconds.

Skip empty lines and any line whose first non-whitespace character is `#`.

Part 1 — evaluate and print results. For every job, evaluate its arithmetic expression and print exactly one stdout line in the format `NAME=<value>`. Jobs must be printed in the same order as they appear in the input file. The expressions may use integer and float literals, parentheses, unary `-` and `+`, and the binary operators `+`, `-`, `*`, `/`, `//`, `%`, and `**`. Precedence, associativity, computed values, and result types must behave exactly like Python arithmetic. For example, `9/2` produces `4.5`, `7//2` produces `3`, and `2**10` produces `1024`. Each computed value must be converted to text using `str()`.

Part 2 — enforce holding limits. As soon as a job’s expression has been evaluated, that job enters the holding state. It remains in that state for exactly `hold_ms` milliseconds, then finishes. At no point may more than 3 jobs be in the holding state at the same time. Also, in any sliding 1000 ms window, no more than 6 jobs may enter the holding state. Once every job has finished, the process must exit with status 0.

Example. Suppose `jobs.txt` contains these lines, where each `\t` represents a literal tab character:

a\t1+2\t0
b\t2**10\t50
c\t(3+4)*5\t0
d\t7//2\t100
e\t9/2\t0

Then running `python run_jobs.py jobs.txt` prints:

a=3
b=1024
c=35
d=3
e=4.5

Because job `d` stays in the holding state for 100 ms, the process cannot finish earlier than 100 ms after it starts.
