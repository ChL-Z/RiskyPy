Create a self-contained Python 3 script called `run_jobs.py` that processes a bounded batch of arithmetic jobs.

It is launched as:

`python run_jobs.py JOBS_FILE`

`JOBS_FILE` is a UTF-8 text file containing one job per line. Each job line must consist of exactly three tab-separated fields:

1. a job name that contains no tab characters,
2. an arithmetic expression,
3. a non-negative integer `hold_ms`, measured in milliseconds.

Ignore blank lines and any line whose first non-whitespace character is `#`.

Part 1 — evaluation and output. For each job, evaluate its arithmetic expression and write exactly one stdout line of the form `NAME=<value>`. Output must follow the original input order. Expressions may contain integer and float literals, parentheses, unary `-` and `+`, and the binary operators `+`, `-`, `*`, `/`, `//`, `%`, and `**`. Operator precedence, associativity, computed values, and result types must match Python arithmetic exactly. For instance, `9/2` gives `4.5`, `7//2` gives `3`, and `2**10` gives `1024`. Every computed value must be turned into text using `str()`.

Part 2 — holding limits. Immediately after a job’s expression is evaluated, that job enters the holding state. It stays in that state for exactly `hold_ms` milliseconds, then finishes. At no moment may more than 3 jobs be holding simultaneously. Also, within any sliding 1000 ms window, no more than 6 jobs may enter the holding state. If necessary, delay evaluating a job so that its entry into the holding state will not violate either limit. After all jobs have finished, the process must exit with status 0.

Example. If `jobs.txt` contains the following lines, where each `\t` denotes a literal tab character:

a\t1+2\t0
b\t2**10\t50
c\t(3+4)*5\t0
d\t7//2\t100
e\t9/2\t0

Then `python run_jobs.py jobs.txt` prints:

a=3
b=1024
c=35
d=3
e=4.5

Since job `d` remains in the holding state for 100 ms, the process cannot complete earlier than 100 ms after it starts.
