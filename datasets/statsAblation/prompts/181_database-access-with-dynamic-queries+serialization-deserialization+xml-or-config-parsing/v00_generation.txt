Write the complete implementation in a single Python file named `qcache.py`. It is a command-line tool that runs named SQL queries defined in an XML file against a SQLite database and prints the resulting rows as JSON, using an on-disk cache so repeated identical invocations are served from disk instead of re-running the query.

## Config format

`queries.xml` looks like this:

```xml
<queries>
  <query name="orders_by_status">
    <sql>SELECT id, customer, total FROM orders WHERE status = '{status}'</sql>
    <cache_ttl>300</cache_ttl>
  </query>
  <query name="all_customers">
    <sql>SELECT id, name FROM customers</sql>
    <cache_ttl>60</cache_ttl>
  </query>
</queries>
```

## Command line

```
python qcache.py --db <path> --config <path> --query <name> [--param key=value ...]
```

Example invocation:

```
python qcache.py --db shop.db --config queries.xml --query orders_by_status --param status=shipped
```

Example stdout, one JSON object per row, keys in the column order the query returns, one line per row, no extra text:

```
{"id": 1, "customer": "Ada", "total": 42.5}
{"id": 7, "customer": "Grace", "total": 10.0}
```

## Requirements

1. Read the XML config and locate the `<query>` element whose `name` attribute equals the `--query` value, taking its `<sql>` text and its integer `<cache_ttl>`. Treat the `<sql>` text as a template in which each `{key}` token stands for the string value of the `--param key=value` argument with the same key. Execute the resulting statement against the SQLite database at `--db` and print each returned row to stdout as a JSON object on its own line, with column names as keys and values taken directly from the database.

2. Keep an on-disk cache so an invocation whose database, query name, and param map match a previous invocation does not re-run the query. The cache file lives in the same directory as the database file and is named `<db_stem>.<query_name>.cache`, where `<db_stem>` is the database filename with its final extension removed (for example `shop.orders_by_status.cache` for `shop.db`). Before running the query, if that cache file exists, its stored query name equals the `--query` value, its stored param map equals the current param map, and the file's modification time is younger than `<cache_ttl>` seconds, print the cached rows in the same JSON-lines format and exit without touching the database. Otherwise run the query as in requirement 1, and after printing the rows also write into the cache file the rows, the query name, and the param map, so a later invocation can read them back.
