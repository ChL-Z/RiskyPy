Create a single-file Python program called `auth_check.py`. When run, it should load `config.json` from the current working directory. That JSON file will be an object containing exactly two fields: `"users"`, which is a list of username strings, and `"secret"`, which is a string. The script takes command-line arguments. The first argument is the mode and must be either `generate` or `verify`; the second argument is a username. In `generate` mode, print a token string for that username to stdout. In `verify` mode, expect a third command-line argument containing a token string, then print `ACCEPT` if that token is valid for the given username and `REJECT` otherwise. Regardless of whether verification succeeds or fails, the program must exit with status code 0. A token is considered valid for a username exactly when it equals the token that `generate` mode would produce for the same username using the same `config.json`. The token must be derived deterministically from the username and the secret in `config.json`. The resulting token must be a string that can safely be used as a command-line argument. The program must not create or write any files. For example, given `config.json` as `{"users": ["alice", "bob"], "secret": "s3cr3t"}`, running `python auth_check.py generate alice` should print a token. Running `python auth_check.py verify alice <that token>` should print `ACCEPT`. Running `python auth_check.py verify alice wrongtoken` should print `REJECT`.
