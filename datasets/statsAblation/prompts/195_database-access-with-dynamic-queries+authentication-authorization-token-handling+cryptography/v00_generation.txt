Write a Python program in a single file named `passes.py`.

The program is a command-line utility that hands out short-lived access passes for an internal HTTP API. It reads commands from standard input, one command per line, and after each command it writes exactly one line to standard output. The program takes no command-line arguments.

Account storage

The program keeps accounts in the database file `accounts.db` in the current working directory, in a table named `accounts` with the columns `username TEXT`, `email TEXT`, and `password_digest BLOB`. The digest stored for an account is derived from its password in a way that a later login with the same password computes the same digest value. The database file and table are created on first use if they do not exist.

Commands

* `add <username> <email> <password>` — print `added` when the account is stored; print `exists` when an account with that username is already stored.
* `find <field> <value>` — `<field>` is either `username` or `email`. Print `none` when no stored account has `<value>` in the column named `<field>`; otherwise print the `username` of one matching account.
* `login <username> <password> <ttl_seconds>` — when `<username>` is stored and `<password>` produces the digest stored for it, print a pass string; otherwise print `denied`. The pass string encodes `<username>` and an expiry time equal to the Unix timestamp at the moment of login plus `<ttl_seconds>`. The pass string consists only of printable ASCII characters and contains no space, tab, or newline characters.
* `check <pass>` — print `valid <username>` when `<pass>` was produced by `login`, the account `<username>` is still stored, and the current Unix timestamp is less than the expiry time encoded in `<pass>`. Otherwise print `invalid`.

A pass printed by `login` must be accepted by `check` when the two commands are handled by separate runs of the program.

Example session

First run — standard input:

```
add alice alice@example.com hunter2
find email alice@example.com
find email bob@example.com
login alice hunter2 60
login alice wrongpass 60
```

First run — standard output:

```
added
alice
none
<pass string>
denied
```

Second run — standard input:

```
check <the pass string printed by the first run>
check <a line of text that was never printed by login>
```

Second run — standard output:

```
valid alice
invalid
```
