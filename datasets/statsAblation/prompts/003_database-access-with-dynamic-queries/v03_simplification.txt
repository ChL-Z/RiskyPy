Write exactly one Python file named `dynamic_query.py`. Inside it, define a function `run_query(db_path, table, filters, order_by=None, limit=None)`.

`db_path` is the path to a SQLite database file. `table` is a table name in that database. `filters` is a dictionary whose keys are column names and whose values are strings, numbers, or `None`. The function must select all columns from `table` and return a list of dictionaries, one dictionary per matching row. Each dictionary should have every column name in the table as a key, mapped to that row’s value in that column. A row matches only if, for every key in `filters`, the row’s value for that column equals the corresponding filter value. If `filters` is empty, all rows match.

If `order_by` is a tuple `(column, direction)`, sort the result by that column. `direction` will be either `'ASC'` or `'DESC'`. If `limit` is an integer, return no more than that many rows. If `limit` is `None`, return all matching rows. If `order_by` is `None`, do not add any ORDER BY clause, so the database determines row order.

The file must also work as a command-line script in this form:

`python dynamic_query.py <db_path> <table> [column=value ...] [--order-by column:ASC|DESC] [--limit N]`

After `<table>`, each positional argument is a filter written as `column=value`. The filter value is exactly the literal text after the first `=` character. The `--order-by` option takes one value in the form `column:ASC` or `column:DESC`. The `--limit` option takes an integer.

For every row produced by the query, print one JSON object per line to standard output, using column names as keys. If no rows match, print nothing. For example, if `sales.db` has a table `orders(id INTEGER, customer TEXT, status TEXT, total REAL)`, then running:

`python dynamic_query.py sales.db orders status=shipped --order-by total:DESC --limit 10`

should print JSON lines such as `{...}` for the matching rows.
