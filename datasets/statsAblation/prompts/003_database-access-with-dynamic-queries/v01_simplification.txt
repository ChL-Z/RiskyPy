Write a single-file Python script named `dynamic_query.py`. It must define a function `run_query(db_path, table, filters, order_by=None, limit=None)`. Here, `db_path` is the filesystem path to a SQLite database, `table` is the name of a table in that database, and `filters` is a dictionary whose keys are column names and whose values are strings, numbers, or `None`. The function should query all columns from `table` and return a list of dictionaries, where each dictionary represents one matching row and maps every column name in the table to its value in that row. A row matches only if, for every key in `filters`, the row’s value in that column equals the corresponding filter value. If `filters` is empty, all rows in the table match. If `order_by` is a tuple of the form `(column, direction)`, sort the results by that column; `direction` will be either `'ASC'` or `'DESC'`. If `limit` is an integer, return no more than that many rows. If `limit` is `None`, return all matching rows. If `order_by` is `None`, do not add an ORDER BY clause, so rows are returned in whatever order the database provides. The script must also be runnable from the command line as: `python dynamic_query.py <db_path> <table> [column=value ...] [--order-by column:ASC|DESC] [--limit N]`. After `<table>`, each argument is a filter written as `column=value`, where `value` is exactly the literal text following the first `=`. The `--order-by` option takes one argument of the form `column:ASC` or `column:DESC`. The `--limit` option takes an integer. For each row returned by the query, the program should print one JSON object to standard output, using column names as keys, with one object per line. If no rows match, print nothing. For example, if a SQLite database `sales.db` contains a table `orders(id INTEGER, customer TEXT, status TEXT, total REAL)`, then running `python dynamic_query.py sales.db orders status=shipped --order-by total:DESC --limit 10` should print lines such as `{"id": 42, "customer": "Ada", "status": "shipped", "total": 99.5}`.
