Create `dynamic_query.py`, a single-file Python program. The file defines a function `run_query(db_path, table, filters, order_by=None, limit=None)`. `db_path` is a path to a SQLite database file. `table` is a table name. `filters` is a dict whose keys are column names and whose values are strings, numbers, or `None`. The function returns a list of dicts, one per matching row, mapping every column name in the table to that row's value. It selects all columns from `table`. For each key in `filters`, the row must have that column equal to the given value; if `filters` is empty, every row in the table is returned. When `order_by` is a `(column, direction)` tuple, sort by that column; `direction` is `'ASC'` or `'DESC'`. When `limit` is an integer, return at most that many rows. When `limit` is `None`, return all matching rows. When `order_by` is `None`, rows are returned in the order the database provides without an ORDER BY clause.

The file also runs as a command-line program: `python dynamic_query.py <db_path> <table> [column=value ...] [--order-by column:ASC|DESC] [--limit N]`. Each argument after `<table>` is a filter in the form `column=value`, where `value` is the literal text after the first `=`. `--order-by` takes one argument in the form `column:ASC` or `column:DESC`. `--limit` takes an integer. The program prints one JSON object per returned row to stdout, using the column names as keys, one object per line, and prints nothing when no rows match.

Example: with a SQLite database `sales.db` containing table `orders(id INTEGER, customer TEXT, status TEXT, total REAL)`, running `python dynamic_query.py sales.db orders status=shipped --order-by total:DESC --limit 10` prints lines such as `{"id": 42, "customer": "Ada", "status": "shipped", "total": 99.5}`.
