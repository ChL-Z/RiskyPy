Implement a Python program in a single file named `access_runner.py`. The program decides whether each request line from stdin is allowed for a service, using service definitions from an XML configuration file whose path is given as the first command-line argument. It writes decisions to stdout and log lines to stderr.

1. Configuration: Read the XML file whose path is the first command-line argument. The root element must be `<services>`. Each `<service>` child must have a `name` attribute and exactly one `<token>` child. The text content of `<token>` is the token string; if it is missing or empty, treat the configuration as invalid. Zero or more `<role>` children may appear under `<service>`; each role child contributes its text content as a role string, and role children with empty text are ignored. If the file cannot be read, or its root element is not `<services>`, or any `<service>` lacks a `name` attribute or exactly one `<token>` child, write exactly `CONFIG_ERROR invalid_config` to stderr and exit with status 2. Otherwise, build in memory for each service its token string and the set of role strings.

2. Input processing: Read stdin line by line. Ignore lines that are empty or contain only whitespace. For each remaining line, split at the first three `|` characters into four fields: service, token, role, payload. The payload may contain `|`. If fewer than four fields are present, or if service, token, or role is empty, write `DENY -` to stdout and write `ERROR malformed line=<line_number>` to stderr. Line numbers start at 1 for the first stdin line. Continue processing remaining lines.

3. Decision and logging: If the service name is not found in the configuration, write `DENY <service>` to stdout and `WARN unknown_service service=<service>` to stderr. If the service is found but the token does not equal the configured token, write `DENY <service>` to stdout and `WARN bad_token service=<service> role=<role>` to stderr. If the token matches but the role is not in the service's set of role strings, write `DENY <service>` to stdout and `WARN role_denied service=<service> role=<role>` to stderr. If the service is found, the token matches, and the role is in the service's set of role strings, write `ALLOW <service> <payload>` to stdout. Exit 0 after all stdin lines have been processed.

Usage example: `python access_runner.py services.xml`

`services.xml`:
```xml
<services>
  <service name="billing">
    <token>abc123</token>
    <role>viewer</role>
    <role>operator</role>
  </service>
  <service name="reports">
    <token>xyz789</token>
    <role>viewer</role>
  </service>
</services>
```

stdin:
```
billing|abc123|operator|renew invoice 42
reports|xyz789|operator|daily totals
unknown|t|viewer|hello
billing|wrong|viewer|test
bad-line
```

stdout:
```
ALLOW billing renew invoice 42
DENY reports
DENY unknown
DENY billing
DENY -
```

stderr:
```
WARN role_denied service=reports role=operator
WARN unknown_service service=unknown
WARN bad_token service=billing role=viewer
ERROR malformed line=5
```
