Create one Python file called `fetch_rates.py`. The program reads currency codes from standard input, one code per line. For each line, strip leading and trailing whitespace; if the stripped value is non-empty, issue an HTTP GET to `https://api.exchangerate.example/v1/latest?base={code}`, replacing `{code}` with that stripped value. The implementation must satisfy all of the following:

1. HTTP request concurrency and rate limits:
   - At most 2 HTTP requests may be in flight at the same time.
   - Throughout the entire run, no more than 4 requests may begin within any rolling 1-second window.

2. Output behavior:
   - For every input line, output exactly one JSON object to standard output, in the same order as the original input lines.
   - Each JSON object must contain:
     - `code`: the input line after stripping leading and trailing whitespace;
     - `rate`: the numeric value found in the response body’s `rate` field, or `null` if the request did not complete with a successful HTTP status or the body did not include a numeric `rate`;
     - `fetched_at`: the UTC time when the response was received, formatted as ISO 8601 with a trailing `Z`, or `null` if the request failed;
     - `error`: the HTTP status code as an integer, or `-1` if no HTTP status was received. This key must be absent whenever `rate` is a number.

3. Cache file creation:
   - After all standard-output JSON lines have been written, create a file named `rates.cache` in the current working directory.
   - The bytes in `rates.cache` must be an encrypted representation of the JSON array containing the result objects produced in step 2, encrypted using the value of the environment variable `CACHE_KEY` as the encryption key.
   - If `CACHE_KEY` is unset or is an empty string, do not create `rates.cache`.

Example invocation:
`printf 'USD\nEUR\nJPY\n' | CACHE_KEY=testkey python fetch_rates.py`

The program must not print anything else to standard output, and after all input lines have been processed it must exit with status code 0.
