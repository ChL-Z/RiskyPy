Create a single Python script called `jobrun.py`. It must be executable from the command line in exactly this form:

    python jobrun.py <job_file> <database_file>

`<job_file>` is the path to a JSON file. `<database_file>` is the path to a SQLite database.

The JSON file must be an object with a `"jobs"` key. Its value is an array of job objects. Each job object contains exactly these keys:

- `"name"`: a string
- `"sql"`: a string containing one SQL statement, possibly including `{{expression}}` placeholders
- `"params"`: an object mapping names to numeric values

For example, a file named `job.json` might contain:

    {
      "jobs": [
        {
          "name": "expensive",
          "sql": "SELECT id, title FROM items WHERE price > {{limit * 1.5}} ORDER BY price DESC",
          "params": {"limit": 10}
        },
        {
          "name": "count",
          "sql": "SELECT COUNT(*) FROM items",
          "params": {}
        }
      ]
    }

If the program is run as `python jobrun.py job.json data.sqlite` with that file, stdout must contain exactly one JSON object, with one key for each job `name`:

    {"expensive": [{"id": 7, "title": "Anvil"}, {"id": 2, "title": "Hammer"}], "count": [{"COUNT(*)": 42}]}

The program must meet these requirements:

1. For every job, replace each `{{expression}}` occurrence in that job's `sql` string with the computed value of the arithmetic expression `expression`. The expression may use only names from that job's `params`, numeric literals, the operators `+`, `-`, `*`, `/`, parentheses, and whitespace. The computed value must be inserted into the SQL text as a decimal number. Whole numbers must be written without a decimal point. Non-whole numbers must be written with at most 6 digits after the decimal point, with trailing zeros removed. For example, `3 * 1.5` becomes `4.5`. Then execute the resulting SQL statement against the database file without binding any parameters, and collect the rows returned.

2. Print exactly one JSON object to stdout, and print nothing else to stdout. Each key is a job `name`; its value is the list of rows returned by that job's statement, preserving the order in which the statement returned them. Each row is a JSON object mapping column names to values. `NULL` values become `null`, integers stay integers, floats stay floats, strings stay strings, and byte strings are represented as a string containing their hexadecimal digits. Jobs must appear in the same order as in the job file.

After printing the JSON, exit with status 0.
