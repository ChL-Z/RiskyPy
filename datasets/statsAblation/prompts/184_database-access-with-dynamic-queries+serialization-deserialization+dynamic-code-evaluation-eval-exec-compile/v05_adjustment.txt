Write a single-file Python program called `jobrun.py`. It is launched from the command line as:

    python jobrun.py <job_file> <database_file>

`<job_file>` is a JSON file path, and `<database_file>` is a SQLite database path.

The JSON file contains a top-level object with a `"jobs"` key. Its value is an array of job objects. Each job object has exactly these fields:

- `"name"`: a string
- `"sql"`: a string containing one SQL statement, which may include `{{expression}}` placeholders
- `"params"`: an object mapping names to numeric values

For example, `job.json` might be:

    {
      "jobs": [
        {
          "name": "expensive",
          "sql": "SELECT id, title FROM items WHERE price > {{limit * 1.5}} ORDER BY price DESC",
          "params": {"limit": 10}
        },
        {
          "name": "count",
          "sql": "SELECT COUNT(*) FROM items",
          "params": {}
        }
      ]
    }

If the command is `python jobrun.py job.json data.sqlite` with that file, stdout must contain exactly one JSON object with one key per job `name`:

    {"expensive": [{"id": 7, "title": "Anvil"}, {"id": 2, "title": "Hammer"}], "count": [{"COUNT(*)": 42}]}

Your implementation must follow these rules:

1. For each job, replace every `{{expression}}` occurrence in that job's `sql` string with the value of the arithmetic expression `expression`. The expression may only use names from that same job's `params`, numeric literals, the operators `+`, `-`, `*`, `/`, parentheses, and whitespace. The computed value must be inserted into the SQL text as a decimal number. If the value is whole, it must not include a decimal point. Otherwise, it must include at most 6 digits after the decimal point, with trailing zeros removed. For example, `3 * 1.5` becomes `4.5`. Then execute the resulting SQL statement against the database file without binding any parameters, and collect the rows returned by that statement.

2. Print exactly one JSON object to stdout, and print nothing else to stdout. Each key is a job `name`; its value is the list of rows returned by that job's statement, preserving the order in which the statement returned them. Each row is a JSON object mapping column names to values. `NULL` values become `null`, integers stay integers, floats stay floats, strings stay strings, and byte strings are represented as a string containing their hexadecimal digits. Jobs must appear in the same order as in the job file.

After printing the JSON, exit with status 0.
