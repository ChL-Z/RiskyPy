Create a single Python file called `fill_tokens.py`. It should take one command-line argument: the path to an XML configuration file.

The XML configuration uses a `<config>` root. Under it may be any number of `<user>` children (including none). Every `<user>` has an `id` attribute and may also have an optional `<token>` child.

Your program must print a new XML document to stdout. For each input `<user>`, the output must include one corresponding `<user>` in the same order and with the same `id`. If the input `<user>` already has a `<token>` child, copy its token text unchanged into the output. If the input `<user>` does not have a `<token>` child, add a new `<token>` child containing a freshly generated token.

A generated token is made by taking 32 random bytes, encoding them with URL-safe base64, and then deleting every `=` padding character. Such a token will be 43 characters long and will only use the characters `A-Z`, `a-z`, `0-9`, `-`, and `_`.

The output must start with `<?xml version="1.0" encoding="UTF-8"?>` followed by a newline, and it must end with a newline. Do not modify the input file. You do not need to match the input's original whitespace or indentation in the output.

For example, if `config.xml` contains:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
  <user id="alice"/>
  <user id="bob"><token>keep-this</token></user>
</config>
```

then running `python fill_tokens.py config.xml` should produce an XML document where the `alice` user has a new 43-character URL-safe base64 token, while the `bob` user still contains the token text `keep-this`.
