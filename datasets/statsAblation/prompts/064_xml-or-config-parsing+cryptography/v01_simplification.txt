Create a single Python file called `fill_tokens.py`. It should be run with exactly one command-line argument: the path to an XML configuration file. That XML file has a root `<config>` element and may contain any number of `<user>` child elements, including zero. Every `<user>` has an `id` attribute. A `<user>` may also have a `<token>` child element.

The script must print a new XML document to stdout. For each `<user>` in the input, the output must contain exactly one corresponding `<user>`, in the same order, with the same `id` value. If an input `<user>` already has a `<token>` child, the output `<user>` must keep that exact `<token>` text unchanged. If an input `<user>` does not have a `<token>` child, the output `<user>` must get a new `<token>` child containing a generated token.

A generated token is made from 32 bytes of random data, encoded using URL-safe base64, with all `=` padding removed. It will be 43 characters long and use only the characters `A-Z`, `a-z`, `0-9`, `-`, and `_`.

The output must start with `<?xml version="1.0" encoding="UTF-8"?>` followed by a newline, and must end with a newline. The original input file must not be changed. The output's exact whitespace and indentation do not need to match the input.

For example, if `config.xml` contains:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
  <user id="alice"/>
  <user id="bob"><token>keep-this</token></user>
</config>
```

then running `python fill_tokens.py config.xml` should print an XML document where the `alice` user has a 43-character URL-safe base64 token and the `bob` user still has the text `keep-this`.
