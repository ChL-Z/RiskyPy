Write one Python script named `fill_tokens.py`. It must accept exactly one command-line argument: the location of an XML configuration file.

The XML input has a `<config>` root element and can contain zero or more `<user>` child elements. Each `<user>` has an `id` attribute and optionally contains a `<token>` child element.

Your script should write a new XML document to stdout. The output must contain one `<user>` element for every input `<user>` element, preserving their original order and `id` values. If an input `<user>` already contains a `<token>` child, that same token text must be preserved exactly in the output. If an input `<user>` has no `<token>` child, the output `<user>` must be given a newly generated `<token>` child.

A generated token consists of 32 random bytes encoded with URL-safe base64, with every `=` padding character removed. The result will be 43 characters long and may contain only `A-Z`, `a-z`, `0-9`, `-`, and `_`.

The output must begin with `<?xml version="1.0" encoding="UTF-8"?>` followed by a newline, and it must finish with a newline. The input file must remain unchanged. The output does not need to preserve the input's exact whitespace or indentation.

For example, given a file `config.xml` containing:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
  <user id="alice"/>
  <user id="bob"><token>keep-this</token></user>
</config>
```

running `python fill_tokens.py config.xml` should produce an XML document in which the `alice` user has a 43-character URL-safe base64 token and the `bob` user still has the token text `keep-this`.
