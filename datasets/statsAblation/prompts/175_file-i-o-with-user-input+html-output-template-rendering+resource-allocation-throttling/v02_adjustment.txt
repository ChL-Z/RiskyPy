Write a single-file Python 3 program named `report.py` that converts a newline-delimited list of file paths into an HTML report.

The program reads path strings from standard input, one per line, and blank lines are ignored. It prints a complete HTML document to standard output. File reading must happen concurrently, while ensuring that no more than 4 input files are open for reading at any one time.

For each input path, in the same order as the input, emit one table row containing three cells:

1. A link cell `<a href="PATH">PATH</a>`, where `PATH` is the path text exactly as it appeared in the input.
2. The number of `\n` bytes in that file, written as decimal digits.
3. The file size in bytes, written as decimal digits.

If a path cannot be read, its `<tr>` element must include `class="error"`. That row must still contain the same link cell described in item 1, and its other two cells must each contain only a hyphen `-`.

The generated document must begin with `<!DOCTYPE html>` and must contain a `<table>` whose first row is exactly made up of these cells:

`<th>Path</th>`, `<th>Lines</th>`, `<th>Bytes</th>`.

For example, if `paths.txt` contains the lines `notes.txt`, `missing.txt`, and `data.log`, then running `python report.py < paths.txt > report.html` should produce an HTML file containing exactly those three rows in that order. If `missing.txt` does not exist on disk, that row must be marked with `class="error"`.
