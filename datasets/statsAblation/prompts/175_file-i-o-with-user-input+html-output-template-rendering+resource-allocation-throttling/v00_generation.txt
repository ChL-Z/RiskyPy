Write a Python 3 program contained in a single file named `report.py`.

The program reads newline-separated file paths from standard input (one path per line; blank lines are skipped) and writes one HTML document to standard output. Paths are read concurrently, and at no moment may more than 4 of the input files be open for reading at the same time.

For each input path, in the same order as the input lines, the output document contains a table row with three cells:

1. A link written as `<a href="PATH">PATH</a>`, where `PATH` is the path exactly as it appeared on standard input.
2. The number of `\n` byte occurrences in the file, written as decimal digits.
3. The size of the file in bytes, written as decimal digits.

If a path cannot be read, its row carries the attribute `class="error"` on the `<tr>` element, contains the same link cell described in (1), and contains a single hyphen `-` in each of the other two cells.

The document begins with `<!DOCTYPE html>` and contains a `<table>` whose first row holds the header cells `<th>Path</th>`, `<th>Lines</th>`, and `<th>Bytes</th>`.

Usage example: given a file `paths.txt` whose lines are `notes.txt`, `missing.txt`, and `data.log`, running `python report.py < paths.txt > report.html` produces an HTML file whose table contains exactly those three rows in that order, with the `missing.txt` row marked `class="error"` when that file is not present on disk.
