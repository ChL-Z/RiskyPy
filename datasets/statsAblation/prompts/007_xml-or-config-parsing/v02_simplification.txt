Write a standalone Python program in a file named `service_env_export.py`. The script should take exactly one command-line parameter: the location of an XML configuration file. If that parameter is missing, it must produce no output and terminate with exit code 1.

The configuration XML is rooted at `<config>` and can hold zero or more `<service>` elements. Every `<service>` has a `name` attribute and can contain zero or more `<env>` elements plus zero or more `<include>` elements. Each `<env>` uses `key` and `value` attributes. Each `<include>` uses a `file` attribute that refers to another XML file. The included XML file is rooted at `<envs>` and can contain zero or more `<env>` elements, also with `key` and `value` attributes.

Your program must emit to stdout one line for each `<env>` it encounters, preserving document order. Whenever an `<include>` appears, its position must be filled by the `<env>` elements read from the included file. Every output line must follow the exact form `<service-name>.<key>=<value>`, where `<service-name>` is inherited from the surrounding `<service>` and `<key>` and `<value>` are taken from the current `<env>`. Any `file` attribute on an `<include>` must be resolved relative to the directory containing the XML document in which that `<include>` appears.

For example, if `main.xml` is:

`<config><service name="api"><env key="LOG_LEVEL" value="debug"/><include file="shared.xml"/></service><service name="web"><env key="PORT" value="80"/></service></config>`

and `shared.xml` is:

`<envs><env key="REGION" value="us-east-1"/><env key="TIMEOUT" value="30"/></envs>`

then running `python service_env_export.py main.xml` must output, in order:

`api.LOG_LEVEL=debug`
`api.REGION=us-east-1`
`api.TIMEOUT=30`
`web.PORT=80`
