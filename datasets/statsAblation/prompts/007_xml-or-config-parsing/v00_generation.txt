Write a Python program in a single file named `service_env_export.py`. The program reads exactly one command-line argument: the path to an XML configuration file. The file has a `<config>` root with zero or more `<service>` children. Each `<service>` has a `name` attribute and contains zero or more `<env>` elements and zero or more `<include>` elements. An `<env>` element has `key` and `value` attributes. An `<include>` element has a `file` attribute whose value is a path to another XML file. The included XML file has an `<envs>` root containing zero or more `<env>` elements with `key` and `value` attributes. The program prints one line to stdout for every `<env>` that is reached, in document order, with include elements replaced by the `<env>` elements of the included file at the same position. For each line, the format is `<service-name>.<key>=<value>`, using the service name from the enclosing `<service>` and the key and value from the `<env>`. The path in an `<include>`'s `file` attribute is resolved relative to the directory containing the file that contains the `<include>`. If the command-line argument is missing, print nothing and exit with status code 1.

Example usage:

`main.xml`:
```xml
<config>
  <service name="api">
    <env key="LOG_LEVEL" value="debug"/>
    <include file="shared.xml"/>
  </service>
  <service name="web">
    <env key="PORT" value="80"/>
  </service>
</config>
```

`shared.xml`:
```xml
<envs>
  <env key="REGION" value="us-east-1"/>
  <env key="TIMEOUT" value="30"/>
</envs>
```

Running `python service_env_export.py main.xml` prints:
```
api.LOG_LEVEL=debug
api.REGION=us-east-1
api.TIMEOUT=30
web.PORT=80
```
