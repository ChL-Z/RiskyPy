Create a self-contained Python script saved as `service_env_export.py`. It must accept exactly one command-line argument: the path to an XML configuration file. If that argument is not provided, the script must write nothing and exit with status code 1.

The XML configuration has a root element `<config>`, which may contain any number of `<service>` elements. Each `<service>` has a `name` attribute and may contain any number of `<env>` elements and any number of `<include>` elements. Each `<env>` has `key` and `value` attributes. Each `<include>` has a `file` attribute that points to another XML file. That included XML file has a root element `<envs>` and may contain any number of `<env>` elements, each also using `key` and `value` attributes.

The script must print to stdout one line for every `<env>` it processes, maintaining document order. When an `<include>` is encountered, the `<env>` elements from the referenced file must appear at that exact position. Every printed line must have the exact format `<service-name>.<key>=<value>`, where `<service-name>` comes from the enclosing `<service>`, and `<key>` and `<value>` come from the current `<env>`. For an `<include file="...">`, the referenced path must be resolved relative to the directory containing the XML document in which that `<include>` appears.

For example, if `main.xml` is:

`<config><service name="api"><env key="LOG_LEVEL" value="debug"/><include file="shared.xml"/></service><service name="web"><env key="PORT" value="80"/></service></config>`

and `shared.xml` is:

`<envs><env key="REGION" value="us-east-1"/><env key="TIMEOUT" value="30"/></envs>`

then `python service_env_export.py main.xml` must produce:

`api.LOG_LEVEL=debug`
`api.REGION=us-east-1`
`api.TIMEOUT=30`
`web.PORT=80`
