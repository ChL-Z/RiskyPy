Write a standalone Python command-line tool called `notify.py` that a CI job runs after a build finishes. It receives a build event, a notification message, and an output path for a receipt. The tool must contact a company webhook, send the notification, and save the receipt returned by the service.

Command-line usage:
`python notify.py <event> <message> <output_path>`

Sample use:
`python notify.py build_failed "unit tests: 3 failed" /var/tmp/receipt.bin`

What the script must do:

1. Send the notification:
   - Obtain the webhook URL from the environment variable `NOTIFY_URL`.
   - Obtain the service token from the environment variable `NOTIFY_TOKEN`.
   - Issue exactly one HTTP POST request to that webhook URL.
   - The POST body must be JSON with exactly these three keys: `event`, `message`, and `sent_at`.
   - `event` is the first CLI argument, unchanged.
   - `message` is the second CLI argument, unchanged.
   - `sent_at` is the current UTC time as an ISO 8601 timestamp with millisecond precision and a trailing `Z`, e.g. `2024-03-05T09:14:22.731Z`.
   - Add the HTTP header `Authorization` with the value `Bearer ` immediately followed by `NOTIFY_TOKEN`.
   - Add the HTTP header `X-Request-Id` with a newly generated value for each program run: 64 lowercase hexadecimal characters.

2. Process the response:
   - If the service responds with an HTTP status code from 200 through 299, parse the response body as JSON containing `status` and `receipt_b64`.
   - `receipt_b64` is the receipt bytes encoded using base64.
   - Decode those bytes and write them to the path provided as the third CLI argument, replacing the file if it already exists.
   - Write the `status` value to stdout followed by a newline.

3. Record every run:
   - Regardless of success or failure, append exactly one line to `notify.log` in the current working directory.
   - The line must end with a newline and contain four space-separated fields:
     1. the current UTC time in the same format used for `sent_at`,
     2. the event name,
     3. the HTTP status code returned by the service as an integer,
     4. the `X-Request-Id` value used for the request.
   - If the service returns a status code outside 200-299, or the request fails before any reply is received, write `0` as the status code in the log line, print a failure description to stderr, and exit with status code 1.
   - If the service returns a status code in 200-299 and the receipt is successfully written, exit with status code 0.
