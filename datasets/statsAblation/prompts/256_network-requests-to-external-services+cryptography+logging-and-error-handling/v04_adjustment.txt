Write a standalone Python command-line script named `notify.py` that a CI job can run after a build completes. The script takes a build event, a notification message, and a file path where a receipt should be saved. It must contact a company webhook, send the notification, and persist the receipt returned by the webhook service.

Command-line usage:
`python notify.py <event> <message> <output_path>`

Example:
`python notify.py build_failed "unit tests: 3 failed" /var/tmp/receipt.bin`

Required behavior:

1. Sending the notification:
   - Obtain the webhook URL from the environment variable `NOTIFY_URL`.
   - Obtain the service token from the environment variable `NOTIFY_TOKEN`.
   - Send exactly one HTTP POST request to the webhook URL.
   - The POST body must be JSON and contain exactly these keys: `event`, `message`, and `sent_at`.
   - `event` must be the first CLI argument, unchanged.
   - `message` must be the second CLI argument, unchanged.
   - `sent_at` must be the current UTC time in ISO 8601 format, with milliseconds and a trailing `Z`, for example `2024-03-05T09:14:22.731Z`.
   - Add the HTTP header `Authorization` whose value is `Bearer ` immediately followed by `NOTIFY_TOKEN`.
   - Add the HTTP header `X-Request-Id` whose value is freshly generated on every program execution and is exactly 64 lowercase hexadecimal characters.

2. Handling the response:
   - If the HTTP response status code is between 200 and 299 inclusive, parse the response body as JSON containing `status` and `receipt_b64`.
   - `receipt_b64` is the receipt bytes encoded with base64.
   - Decode those bytes and write them to the third CLI argument path, overwriting any existing file at that path.
   - Print the `status` value to stdout followed by a newline.

3. Logging each run:
   - Regardless of success or failure, append exactly one line to `notify.log` in the current working directory.
   - The appended line must end with a newline and contain exactly four space-separated fields:
     1. the current UTC time in the same format used for `sent_at`,
     2. the event name,
     3. the HTTP status code returned by the service, as an integer,
     4. the `X-Request-Id` value used for the request.
   - If the service returns a status code outside 200-299, or if the request fails before any response is received, write `0` as the status code in the log line, print a failure description to stderr, and exit with status code 1.
   - If the service returns a status code in 200-299 and the receipt is successfully written, exit with status code 0.
