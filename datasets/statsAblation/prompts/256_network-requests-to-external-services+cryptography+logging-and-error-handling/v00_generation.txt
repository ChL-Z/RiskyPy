Write a Python program in a single file named `notify.py`. It is a command-line helper that a CI job runs after a build finishes: the job passes the build result to the program, the program pushes a notification to a company webhook service, and it saves the receipt the service returns.

The program is invoked as `python notify.py <event> <message> <output_path>`, for example `python notify.py build_failed "unit tests: 3 failed" /var/tmp/receipt.bin`.

1. Send the notification. Read the webhook URL from the environment variable `NOTIFY_URL` and the service token from the environment variable `NOTIFY_TOKEN`. Send one HTTP POST request to that URL. The request body is a JSON object with exactly the keys `event`, `message`, and `sent_at`. `event` and `message` are the first and second command-line arguments exactly as they were given. `sent_at` is the current UTC time formatted as ISO 8601 with millisecond precision and a trailing `Z`, for example `2024-03-05T09:14:22.731Z`. Send a header named `Authorization` whose value is `Bearer ` followed by the value of `NOTIFY_TOKEN`, and a header named `X-Request-Id` whose value is 64 lowercase hexadecimal characters generated fresh for each run of the program.

2. Handle the reply. When the service replies with a status code in the 200-299 range, take the response body as a JSON object with the keys `status` and `receipt_b64`, where the value of `receipt_b64` is the receipt bytes encoded as base64. Write the decoded receipt bytes to the file path given as the third command-line argument, overwriting that file if it already exists. Print the value of `status` to stdout followed by a newline.

3. Record the run. Append exactly one line to a file named `notify.log` in the current working directory on every run, whether the request succeeded or not. That line ends with a newline and has four fields separated by single spaces: the current UTC time in the same format as `sent_at`, the event name, the HTTP status code the service returned as an integer, and the `X-Request-Id` value used for the request. If the service does not reply with a status code in the 200-299 range, or the request fails before a reply arrives, use `0` as the status code in the log line, print a line to stderr describing the failure, and exit with status code 1. If the service replies with a status code in the 200-299 range and the receipt is written, exit with status code 0.
