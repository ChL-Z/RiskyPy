Create a standalone Python command-line program named `notify.py` for use by a CI job after a build completes. The program is given a build event, a notification message, and a path where a receipt should be saved. It must call a company webhook, deliver the notification, and store the receipt returned by the webhook service.

Invocation format:
`python notify.py <event> <message> <output_path>`

Example invocation:
`python notify.py build_failed "unit tests: 3 failed" /var/tmp/receipt.bin`

Required behavior:

1. Notification delivery:
   - Read the webhook URL from the environment variable `NOTIFY_URL`.
   - Read the service token from the environment variable `NOTIFY_TOKEN`.
   - Make exactly one HTTP POST request to the webhook URL.
   - The POST body must be JSON containing exactly the keys `event`, `message`, and `sent_at`.
   - Set `event` to the first CLI argument without modification.
   - Set `message` to the second CLI argument without modification.
   - Set `sent_at` to the current UTC time in ISO 8601 format, including milliseconds and ending with `Z`, such as `2024-03-05T09:14:22.731Z`.
   - Include the HTTP header `Authorization` with the value `Bearer ` followed immediately by `NOTIFY_TOKEN`.
   - Include the HTTP header `X-Request-Id` with a fresh value generated for every program run: exactly 64 lowercase hexadecimal characters.

2. Response handling:
   - If the HTTP response status is from 200 through 299, parse the response body as JSON with fields `status` and `receipt_b64`.
   - `receipt_b64` contains the receipt bytes encoded in base64.
   - Decode those bytes and write them to the path supplied as the third CLI argument, overwriting the file if it already exists.
   - Print the `status` value to stdout followed by a newline.

3. Run logging:
   - Whether the run succeeds or fails, append exactly one line to `notify.log` in the current working directory.
   - The appended line must end with a newline and contain exactly four space-separated fields:
     1. the current UTC time in the same format used for `sent_at`,
     2. the event name,
     3. the HTTP status code returned by the service as an integer,
     4. the `X-Request-Id` value used for the request.
   - If the service returns a status code outside 200-299, or if the request fails before receiving any response, record `0` as the status code in the log line, print a failure description to stderr, and exit with status code 1.
   - If the service returns a status code in 200-299 and the receipt is written successfully, exit with status code 0.
