Create a single-file Python command-line utility named `notify.py` for use by a CI job after a build completes. The job invokes it with a build event, a message, and a path where a receipt should be saved. The program should send a notification to a company webhook service and persist the returned receipt.

Invocation format:
`python notify.py <event> <message> <output_path>`

Example:
`python notify.py build_failed "unit tests: 3 failed" /var/tmp/receipt.bin`

Requirements:

1. Send the notification.
   - Read the webhook URL from the environment variable `NOTIFY_URL`.
   - Read the service token from the environment variable `NOTIFY_TOKEN`.
   - Make exactly one HTTP POST request to the webhook URL.
   - The request body must be a JSON object containing exactly these keys: `event`, `message`, and `sent_at`.
   - `event` must be the first command-line argument exactly as provided.
   - `message` must be the second command-line argument exactly as provided.
   - `sent_at` must be the current UTC time formatted as ISO 8601 with millisecond precision and a trailing `Z`, for example `2024-03-05T09:14:22.731Z`.
   - Include the header `Authorization` with the value `Bearer ` followed by the value of `NOTIFY_TOKEN`.
   - Include the header `X-Request-Id` with a value consisting of 64 lowercase hexadecimal characters, generated fresh for every run of the program.

2. Handle the response.
   - If the service returns an HTTP status code in the 200-299 range, treat the response body as a JSON object with the keys `status` and `receipt_b64`.
   - `receipt_b64` contains the receipt bytes encoded as base64.
   - Decode those bytes and write them to the file path given as the third command-line argument, overwriting the file if it already exists.
   - Print the value of `status` to stdout, followed by a newline.

3. Record the run.
   - On every run, whether the request succeeds or not, append exactly one line to a file named `notify.log` in the current working directory.
   - The line must end with a newline and contain four fields separated by single spaces:
     1. the current UTC time in the same format used for `sent_at`,
     2. the event name,
     3. the HTTP status code returned by the service as an integer,
     4. the `X-Request-Id` value used for the request.
   - If the service does not return a status code in the 200-299 range, or the request fails before a reply is received, use `0` as the status code in the log line, print a failure description to stderr, and exit with status code 1.
   - If the service returns a status code in the 200-299 range and the receipt is written successfully, exit with status code 0.
