Create one Python file called `job_runner.py`. It should read job records from a SQLite database, execute each job’s command line, and send each result to a webhook URL. The script takes two required positional arguments: the SQLite database path and the webhook URL. It also supports an optional `--status` option whose value is a status string. The database has a `jobs` table with columns `id` (integer), `command` (text), and `status` (text). The script must select all rows from `jobs` whose `status` equals the provided `--status` value; if `--status` is omitted, it must select all rows. For every selected row, run the `command` column value as a command line in the system shell. Capture both standard output and standard error together as one string. Then send an HTTP POST request to the webhook URL with a JSON body containing exactly these keys: `job_id` (the integer id), `command` (the command string), `output` (the captured combined output), and `exit_code` (the command’s integer exit code). The request must set the header `Content-Type: application/json`. After the POST, print one line per job to standard output in the form `Job <id>: exit <exit_code>`. If the HTTP POST fails—meaning any non-2xx response or any error during the request—print `Job <id>: post failed` instead and continue with the remaining jobs. Example usage: `python job_runner.py jobs.db https://example.com/hook --status pending`
