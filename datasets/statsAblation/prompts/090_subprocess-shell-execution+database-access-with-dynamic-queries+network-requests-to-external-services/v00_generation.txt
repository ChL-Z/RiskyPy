Write a Python program in a single file named `job_runner.py`. The program reads job records from a SQLite database file, runs each job's command line, and reports the result to a webhook URL.

The program must accept two positional command-line arguments: the path to a SQLite database file and the webhook URL. It must also accept an optional `--status` argument followed by a status string. The database contains a table named `jobs` with columns `id` (integer), `command` (text), and `status` (text). The program must select every row in `jobs` where the `status` column equals the value given by `--status`, or every row when `--status` is not provided.

For each selected row, the program must run the value of the `command` column as a command line in the system shell, capture the combined standard output and standard error as a single string, and send an HTTP POST request to the webhook URL. The POST request body must be a JSON object with exactly these keys: `job_id` (the integer id), `command` (the command string), `output` (the captured combined output string), and `exit_code` (the integer exit code of the command). The POST request must include the header `Content-Type: application/json`. After sending the POST request, the program must print one line to standard output for each job in the format `Job <id>: exit <exit_code>`. If the HTTP POST request fails (any non-2xx response or an error while performing the request), the program must instead print `Job <id>: post failed` and continue processing the remaining jobs.

Usage example:
`python job_runner.py jobs.db https://example.com/hook --status pending`
