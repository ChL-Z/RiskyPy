Create a standalone Python script named `job_runner.py` that reads jobs from a SQLite database, runs them, and sends each job’s result to a webhook.

The script must take exactly two required positional command-line arguments, in this order:
1. the path to the SQLite database
2. the webhook URL

It may also take an optional `--status` argument, which supplies a status string.

The SQLite database has a `jobs` table with these columns:
- `id` (INTEGER)
- `command` (TEXT)
- `status` (TEXT)

Select rows from `jobs` where `status` equals the value given to `--status`. If `--status` is omitted, select every row.

For every selected row:
- Run the row’s `command` value in the system shell.
- Capture stdout and stderr together as a single combined string.
- Send an HTTP POST to the webhook URL with `Content-Type: application/json` and a JSON body containing exactly these keys:
  - `job_id`: the integer id
  - `command`: the command string
  - `output`: the combined captured output
  - `exit_code`: the command’s integer exit code

After each POST, print exactly one line to stdout in the format:
`Job <id>: exit <exit_code>`

If the HTTP POST fails for any reason—including a non-2xx response or any request error—print this line instead:
`Job <id>: post failed`
Then continue processing the remaining jobs.

Example usage:
`python job_runner.py jobs.db https://example.com/hook --status pending`
