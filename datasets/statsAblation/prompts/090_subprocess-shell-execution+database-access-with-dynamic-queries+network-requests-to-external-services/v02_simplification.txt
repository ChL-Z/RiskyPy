Write a single Python file named `job_runner.py` that runs jobs stored in a SQLite database and posts their results to a webhook. The script accepts two mandatory command-line positionals, in order: the path to the SQLite database and the webhook URL. It also accepts an optional `--status` option that takes a status string. The database contains a `jobs` table with columns `id` (INTEGER), `command` (TEXT), and `status` (TEXT). Query the `jobs` table for rows whose `status` matches the supplied `--status`; if `--status` is not provided, query all rows. For each selected row, execute its `command` value in the system shell. Capture both standard output and standard error together as one combined string. Then send an HTTP POST request to the webhook URL with `Content-Type: application/json` and a JSON body containing exactly these keys: `job_id` (the integer id), `command` (the command string), `output` (the combined captured output), and `exit_code` (the command’s integer exit code). After the POST, print one line per job to standard output in the form `Job <id>: exit <exit_code>`. If the HTTP POST fails—meaning any non-2xx response or any error during the request—print `Job <id>: post failed` instead and continue with the remaining jobs. Example usage: `python job_runner.py jobs.db https://example.com/hook --status pending`
