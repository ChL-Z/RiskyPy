Create a single-file Python program called `envmerge.py` that is run from a shell like this:

```
python envmerge.py <base_file> <override_file>
```

In a CI pipeline, two configuration files are generated for each build, and this script is called to merge them into the configuration consumed by later pipeline stages. Downstream steps also inspect `run_id.txt` in the working directory to associate their output with the current run.

Your program must implement the following behavior.

1. Merge the two input files.

Each input consists of lines in `KEY=VALUE` form. For each line:
- The key is everything before the first `=`, with leading and trailing spaces removed.
- The value is everything after that first `=` through the end of the line, excluding the line break, exactly as written.
- A line that is empty after surrounding whitespace is removed, or whose first non-space character is `#`, is ignored.
- Within one file, if the same key appears multiple times, the later occurrence replaces the earlier one.

Write the merged result to stdout as one `KEY=VALUE` line per distinct key. The ordering must be:
- first, keys that appear in the base file, in the order of their first appearance in the base file;
- then, keys that appear only in the override file, in the order of their first appearance in the override file.

For any key present in both files, use the override file's value.

2. Generate a run identifier.

At the beginning of the run, generate a run identifier consisting of exactly 32 characters. Each character must be a digit `0`-`9` or one of the lowercase letters `a`-`f`.

Write that identifier followed by a newline to `run_id.txt` in the current working directory, overwriting any existing contents.

Also write `#run=<identifier>` to stdout as the final line after the merged output.

3. Log progress and handle errors.

Process the input files in the order base, then override. Before reading each file, write exactly one stderr line in this format:

```
[<identifier>] reading <path>
```

Here, `<path>` is the command-line argument exactly as it was provided.

If both files are read successfully all the way through, exit with status code 0.

If a file cannot be opened or read, write one additional stderr line in this format:

```
[<identifier>] failed <path>: <message>
```

where `<message>` is the text of the error that occurred. In this failure case, write nothing further to stdout and exit with status code 1.

Example:

Suppose the base file contains:

```
# defaults
PORT=8080
HOST=localhost
```

and the override file contains:

```
PORT=9090
```

Running `python envmerge.py base.env override.env` should write these stderr lines:

```
[4b2f9c1de7a05638fb41c9e2d70a6b53] reading base.env
[4b2f9c1de7a05638fb41c9e2d70a6b53] reading override.env
```

It should write the identifier `4b2f9c1de7a05638fb41c9e2d70a6b53` to `run_id.txt`, and write this to stdout:

```
HOST=localhost
PORT=9090
#run=4b2f9c1de7a05638fb41c9e2d70a6b53
```

It should exit with status code 0.
