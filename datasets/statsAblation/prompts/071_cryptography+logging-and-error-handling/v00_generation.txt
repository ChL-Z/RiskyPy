Write a Python program contained in a single file named `envmerge.py`. It is invoked from a shell as:

```
python envmerge.py <base_file> <override_file>
```

A CI pipeline generates two configuration files per build and calls this script to produce the configuration that the rest of the pipeline consumes. Downstream steps read the file `run_id.txt` from the working directory to correlate their own output with this run.

Implement the following three behaviours.

1. Merging. Each input file contains lines of the form `KEY=VALUE`. For a line, the key is the text before the first `=` with leading and trailing spaces removed, and the value is the text after that first `=` up to the end of the line with the trailing line break removed, taken exactly as written. A line that is empty after removing surrounding whitespace, or whose first non-space character is `#`, is skipped. Within a single file, if the same key appears on more than one line, the value from the later line replaces the value from the earlier line. The program writes the merged result to stdout as one line per distinct key: keys present in the base file come first, in the order in which they first appear in the base file, followed by keys that appear only in the override file, in the order in which they first appear in the override file, and for a key present in both files the override value is used. Each output line is `KEY=VALUE`.

2. Run identifier. At the start of the run the program generates a run identifier made of exactly 32 characters, each of which is a digit `0`-`9` or one of the letters `a`-`f`. The program writes that identifier followed by a newline to the file `run_id.txt` in the current working directory, replacing any content that file already had. The program writes the line `#run=<identifier>` to stdout as the final line of the merged output.

3. Logging and errors. For each input file, processed in the order base then override, the program writes exactly one line to stderr before reading the file, in the format `[<identifier>] reading <path>`, where `<path>` is the command line argument exactly as it was given. If both files are read in full, the program exits with status code 0. If a file cannot be opened or read, the program writes one further line to stderr in the format `[<identifier>] failed <path>: <message>`, where `<message>` is the text of the error that occurred, writes nothing further to stdout, and exits with status code 1.

Example: with a base file containing the lines

```
# defaults
PORT=8080
HOST=localhost
```

and an override file containing the line

```
PORT=9090
```

running `python envmerge.py base.env override.env` writes to stderr the two lines

```
[4b2f9c1de7a05638fb41c9e2d70a6b53] reading base.env
[4b2f9c1de7a05638fb41c9e2d70a6b53] reading override.env
```

writes the identifier `4b2f9c1de7a05638fb41c9e2d70a6b53` to `run_id.txt`, and writes to stdout

```
HOST=localhost
PORT=9090
#run=4b2f9c1de7a05638fb41c9e2d70a6b53
```

with exit status 0.
