Create one Python script named `envmerge.py` that is executed from the command line like this:

```
python envmerge.py <base_file> <override_file>
```

The script is used in a CI pipeline. It receives two generated configuration files and combines them into the configuration that later pipeline stages will consume. Later stages also expect a file named `run_id.txt` in the current working directory so they can tie their outputs to the current run.

Implement the script so that it satisfies all of the following.

## Merge behavior

Both input files contain lines in the form `KEY=VALUE`. For each line:

- Split at the first `=`.
- The key is the part before the first `=`, with leading and trailing whitespace stripped.
- The value is everything after the first `=`, up to the end of the line but not including the newline. Keep the value exactly as written.
- Skip lines that become empty after stripping surrounding whitespace.
- Skip lines whose first non-whitespace character is `#`.
- If the same key appears more than once in a single file, only its last occurrence in that file is relevant.

Write the merged configuration to stdout as one `KEY=VALUE` line for each distinct key.

The output order must be:

1. Keys found in the base file, ordered by the first time they appear in that file.
2. Keys found only in the override file, ordered by the first time they appear in that file.

If a key exists in both files, the override file's value wins.

## Run identifier

At the start of execution, generate a run identifier that is exactly 32 characters long. Every character must be either a digit `0`-`9` or a lowercase letter `a`-`f`.

Write this identifier followed by a newline to `run_id.txt` in the current working directory, replacing any previous contents.

After the merged configuration has been printed to stdout, make `#run=<identifier>` the final stdout line.

## Logging and error handling

The base file must be processed first, followed by the override file. Before each file is read, print exactly one stderr line in this format:

```
[<identifier>] reading <path>
```

For this log line, `<path>` must be the command-line argument exactly as it was supplied.

If both files are read successfully from start to finish, exit with status code 0.

If a file cannot be opened or read, print one extra stderr line in this format:

```
[<identifier>] failed <path>: <message>
```

Here, `<message>` is the error text. In this failure case, do not write any further stdout output and exit with status code 1.

## Example

If the base file contains:

```
# defaults
PORT=8080
HOST=localhost
```

and the override file contains:

```
PORT=9090
```

then running `python envmerge.py base.env override.env` should produce these stderr lines:

```
[4b2f9c1de7a05638fb41c9e2d70a6b53] reading base.env
[4b2f9c1de7a05638fb41c9e2d70a6b53] reading override.env
```

It should write the identifier `4b2f9c1de7a05638fb41c9e2d70a6b53` to `run_id.txt`, print this to stdout:

```
HOST=localhost
PORT=9090
#run=4b2f9c1de7a05638fb41c9e2d70a6b53
```

and exit with status code 0.
