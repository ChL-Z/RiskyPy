Create a single-file Python script called `seen.py` that keeps track of identifier strings it has already encountered, persisting that memory across runs.

Example usage:

```
$ printf 'alpha\nbeta\nalpha\n' | python seen.py
NEW alpha
NEW beta
SEEN alpha
```

Requirements:

1. Read identifiers from standard input, one per line. Remove leading and trailing whitespace from each line. Lines that are empty after trimming must be ignored completely: no output for them, and they must not be recorded. For every remaining identifier, in the same order as input, print exactly one line to standard output:
   - `NEW <identifier>` if that exact identifier has not been recorded during the current run or any previous run.
   - `SEEN <identifier>` if it has already been recorded.
   Add every identifier that produces `NEW` to the recorded set.

2. Store the recorded identifiers in a file named `seen.dat` in the current working directory. At the beginning of each run, if `seen.dat` exists, load the previously recorded identifiers from it. At the end of each run, after all input has been read, write the recorded identifiers back to `seen.dat`. No other program reads `seen.dat`. If `seen.dat` exists but its contents cannot be loaded, start with an empty recorded set and continue normally.

3. At the end of every run, append one line to `seen.log` in the current working directory. The line format must be:

   `YYYY-MM-DD HH:MM:SS <summary>`

   where the timestamp is the local time when the line is written. Normally, `<summary>` is:

   `run new=<N> total=<T>`

   Here `<N>` is the number of identifiers reported as `NEW` during the run, and `<T>` is the number of recorded identifiers at the end of the run. However, if the run started from an empty recorded set because loading `seen.dat` failed, write `load-failed` as the summary instead.

Exit with status 0 when all input lines were consumed and both files were successfully written. Exit with status 1 if writing `seen.dat` or `seen.log` fails.
