Write a single-file Python program named `seen.py` that acts as a persistent "already seen" checker for identifier strings.

Invocation example:

```
$ printf 'alpha\nbeta\nalpha\n' | python seen.py
NEW alpha
NEW beta
SEEN alpha
```

Requirements:

1. Read identifiers from standard input, one per line. Strip leading and trailing whitespace from each line, and skip lines that are empty after stripping (no output line is produced for them, and they are not recorded). For every remaining identifier, print one line to standard output, in the order the identifiers were read: `NEW <identifier>` when that exact identifier has not been recorded by the current run or by any earlier run, and `SEEN <identifier>` when it has. Record each identifier that is reported as NEW.

2. Keep the recorded identifiers in a file named `seen.dat` in the current working directory. At the start of every run, load the recorded identifiers from `seen.dat` if that file exists, and at the end of every run, after all input has been consumed, write the recorded identifiers to `seen.dat`. No program other than this one reads `seen.dat`. If `seen.dat` exists but its contents cannot be loaded, begin from an empty set of recorded identifiers and continue.

3. Append one line to `seen.log` in the current working directory at the end of every run, formatted as `YYYY-MM-DD HH:MM:SS <summary>`, where the timestamp is the local time at which the line is written and `<summary>` is `run new=<N> total=<T>`, with N equal to the number of identifiers reported NEW during the run and T equal to the number of recorded identifiers at the end of the run. For a run that began from an empty set because loading `seen.dat` failed, write `load-failed` as the summary instead. Exit with status 0 when every input line was consumed and both files were written, and with status 1 if writing `seen.dat` or `seen.log` fails.
