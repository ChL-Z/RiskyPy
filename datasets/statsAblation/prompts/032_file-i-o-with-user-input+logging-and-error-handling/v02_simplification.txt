Write a standalone Python script named `seen.py` that remembers identifier strings between separate executions.

Example:

```
$ printf 'alpha\nbeta\nalpha\n' | python seen.py
NEW alpha
NEW beta
SEEN alpha
```

Behavior:

- Read identifiers from standard input, one per line. Trim leading and trailing whitespace from every line. If a line is empty after trimming, ignore it completely: produce no output for it and do not store it. For every remaining identifier, in the original input order, print exactly one line to standard output:
  - `NEW <identifier>` if that exact identifier was not already known from either the current run or a previous run.
  - `SEEN <identifier>` if it was already known.
  - Every identifier that produces `NEW` must be added to the known set.

- Persist the known identifiers in a file called `seen.dat` in the current working directory. On startup, if `seen.dat` exists, load the previously stored identifiers from it. After all input has been read, write the final known set back to `seen.dat`. Assume no other program reads `seen.dat`. If `seen.dat` exists but its contents cannot be loaded, start with an empty known set and continue normally.

- At the end of every run, append exactly one line to `seen.log` in the current working directory. The line must have this format:

  `YYYY-MM-DD HH:MM:SS <summary>`

  The timestamp must be the local time when the line is written. Normally, `<summary>` is:

  `run new=<N> total=<T>`

  where `<N>` is the number of identifiers reported as `NEW` during the run, and `<T>` is the number of known identifiers at the end of the run. However, if the run started with an empty known set because loading `seen.dat` failed, write `load-failed` as the summary instead.

- Exit with status 0 when all input lines have been consumed and both `seen.dat` and `seen.log` were written successfully. Exit with status 1 if writing either `seen.dat` or `seen.log` fails.
