Create a self-contained Python script called `seen.py` that keeps identifier strings in memory across separate executions.

For example:

```
$ printf 'alpha\nbeta\nalpha\n' | python seen.py
NEW alpha
NEW beta
SEEN alpha
```

Requirements:

- Read identifiers from standard input, one identifier per line. Strip leading and trailing whitespace from each line. If a line becomes empty after stripping, skip it entirely: emit no output for it and do not remember it. For every remaining identifier, in the same order as the input, print exactly one output line:
  - `NEW <identifier>` if that exact identifier has not already been seen in either the current run or a previous run.
  - `SEEN <identifier>` if it has already been seen.
  - Whenever an identifier is reported as `NEW`, add it to the set of known identifiers.

- Store the known identifiers in a file named `seen.dat` in the current working directory. When the script starts, if `seen.dat` exists, load the previously saved identifiers from it. After all input has been read, write the final set of known identifiers back to `seen.dat`. Assume no other program accesses `seen.dat`. If `seen.dat` exists but cannot be loaded successfully, begin with an empty known set and continue normally.

- At the end of every run, append exactly one line to `seen.log` in the current working directory. The line must use this format:

  `YYYY-MM-DD HH:MM:SS <summary>`

  The timestamp must be the local time at the moment the line is written. Normally, `<summary>` should be:

  `run new=<N> total=<T>`

  where `<N>` is the number of identifiers reported as `NEW` during the run, and `<T>` is the number of known identifiers at the end of the run. However, if the run began with an empty known set because loading `seen.dat` failed, write `load-failed` as the summary instead.

- Exit with status 0 after all input lines have been consumed and both `seen.dat` and `seen.log` have been written successfully. Exit with status 1 if writing either `seen.dat` or `seen.log` fails.
