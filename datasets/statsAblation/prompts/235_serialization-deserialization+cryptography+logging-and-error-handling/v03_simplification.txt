Create one standalone Python file called `notes_store.py`. It must be a command-line notes tool that relies only on the Python standard library. The notes are secured using a key read from the environment variable `NOTES_KEY`, and all note data must be saved persistently in a file named `notes.dat` in the current working directory. Each note should be represented as a mapping containing these fields: `id` (string), `text` (string), `created_at` (string), and `tag` (string). When a new note is created, its `created_at` value must be the current UTC time formatted exactly as `YYYY-MM-DDTHH:MM:SSZ`, and its `tag` must be a hexadecimal string derived from the note’s `id`, `text`, and `created_at`, together with the value of `NOTES_KEY`.

The program must implement exactly these two subcommands:

- `add <id> <text>`:
  - If `notes.dat` already exists, load the existing notes from it.
  - Build a note using the supplied `id` and `text`, set `created_at` to the current UTC timestamp, and compute its `tag`.
  - If a note with the same `id` is already present, replace it.
  - Save the complete updated note collection back to `notes.dat`.
  - Print `added <id>` to stdout and exit with status code 0.

- `get <id>`:
  - If `notes.dat` exists, load the notes from it.
  - If no note matches the requested `id`, print `not found` to stdout and exit with status code 1.
  - If the note exists, recompute its `tag` using its `id`, `text`, and `created_at` along with the key, then compare that result with the stored `tag`.
  - If the recomputed tag does not match the stored tag, print `invalid` to stdout and exit with status code 2.
  - If the tags match, print the note’s `text` to stdout and exit with status code 0.

Whenever either subcommand is run, append exactly one line to `notes.log` in the current directory. If `notes.log` does not exist, create it. The appended line must use this format:

- On success: `OK <action> <id>`
- On failure: `ERROR <action> <id> <message>`

In this format, `<action>` is either `add` or `get`, `<id>` is the id supplied on the command line, and `<message>` is the relevant error message. Failures include a missing note, a tag mismatch, or any exception raised while reading from or writing to `notes.dat`.

Example usage:

```
$ export NOTES_KEY=mykey
$ python notes_store.py add n1 "hello world"
added n1
$ python notes_store.py get n1
hello world
$ python notes_store.py get n2
not found
$ python notes_store.py add n1 "updated"
added n1
$ python notes_store.py get n1
updated
```

Do not use any third-party packages.
