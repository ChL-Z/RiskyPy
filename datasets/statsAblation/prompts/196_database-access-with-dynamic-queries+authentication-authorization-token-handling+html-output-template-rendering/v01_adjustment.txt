Create a single-file Python script called `report.py`. It is executed as:

`python report.py <database-path> <filter>`

The script should read exactly one line from standard input, remove the trailing newline, and treat the remaining text as the access token. `<database-path>` is the path to a SQLite database. `<filter>` is a string.

The SQLite database contains:
- a `users` table with columns `token`, `username`, and `role`
- a `records` table with columns `owner_id`, `label`, and `amount`

Implement the following behavior.

1. Authentication and authorization:
- Select the `users` row where `token` equals the access token.
- If no such row exists, write nothing to standard output and exit with status code 1.
- If such a row exists but its `role` is not exactly `admin`, write nothing to standard output and exit with status code 1.
- If such a row exists and its `role` is exactly `admin`, continue to step 2.

2. HTML report:
- Write to standard output exactly this HTML structure:
  - first `<html><body>`
  - then `<h1>Report for NAME</h1>`, where `NAME` is the matched user's `username`
  - then `<table>`
  - then `<tr><th>Label</th><th>Amount</th></tr>`
  - then one row for each matching record, formatted as `<tr><td>LABEL</td><td>AMOUNT</td></tr>`, where `LABEL` and `AMOUNT` are that record's `label` and `amount` values
  - then `</table></body></html>`
- A matching record is any row in `records` whose `label` contains the `<filter>` string as a case-sensitive substring.
- Matching records must be printed in the same order they appear in the `records` table.
- Exit with status code 0.

Example:
If `data.db` has a `users` row (`tok123`, `alice`, `admin`) and `records` rows (`1`, `alpha widget`, `10`) and (`1`, `beta widget`, `20`), then running:

`echo tok123 | python report.py data.db widget`

should print an HTML document with heading `Report for alice` and a table containing two rows: `alpha widget` with amount `10`, and `beta widget` with amount `20`.
