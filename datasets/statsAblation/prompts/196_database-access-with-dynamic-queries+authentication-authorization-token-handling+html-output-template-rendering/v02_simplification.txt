Write a single Python file named `report.py` that is run like this:

`python report.py <database-path> <filter>`

It must read exactly one line from standard input, strip the trailing newline, and use the remaining text as an access token. `<database-path>` points to a SQLite database, and `<filter>` is a string.

The database has these tables:

- `users`, with columns `token`, `username`, and `role`
- `records`, with columns `owner_id`, `label`, and `amount`

Implement this behavior:

1. Look up the `users` row whose `token` matches the access token.
   - If there is no such row, produce no standard output and exit with code 1.
   - If a matching row exists but its `role` is not exactly `admin`, produce no standard output and exit with code 1.
   - If a matching row exists and its `role` is exactly `admin`, continue.

2. Print an HTML report to standard output with exactly this structure, in this order:
   - `<html><body>`
   - `<h1>Report for NAME</h1>`, where `NAME` is the matched row's `username`
   - `<table>`
   - `<tr><th>Label</th><th>Amount</th></tr>`
   - One row for every matching `records` row: `<tr><td>LABEL</td><td>AMOUNT</td></tr>`, using that row's `label` and `amount`
   - `</table></body></html>`

A matching `records` row is any row whose `label` contains `<filter>` as a case-sensitive substring. Matching rows must appear in the same order they occur in the `records` table. After printing the report, exit with code 0.

Example:
If `data.db` contains a `users` row (`tok123`, `alice`, `admin`) and `records` rows (`1`, `alpha widget`, `10`) and (`1`, `beta widget`, `20`), then:

`echo tok123 | python report.py data.db widget`

should output an HTML document whose heading is `Report for alice` and whose table contains two rows: `alpha widget` with amount `10`, then `beta widget` with amount `20`.
