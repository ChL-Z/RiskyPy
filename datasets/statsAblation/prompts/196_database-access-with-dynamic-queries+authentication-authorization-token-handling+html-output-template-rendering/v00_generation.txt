Write a Python program in one file named `report.py`.

The program runs as `python report.py <database-path> <filter>`. It reads one line from standard input and strips the trailing newline; the resulting text is the access token. `<database-path>` names a SQLite database file. `<filter>` is a text string.

The database has a `users` table with columns `token`, `username`, and `role`, and a `records` table with columns `owner_id`, `label`, and `amount`.

Implement these two requirements.

1. Token lookup and authorization. Find the row in `users` whose `token` column equals the access token. If no such row exists, print nothing to standard output and terminate with exit code 1. If a row exists but its `role` is not exactly `admin`, print nothing to standard output and terminate with exit code 1. If a row exists and its `role` is exactly `admin`, proceed to requirement 2.

2. Report output. Print to standard output an HTML document with this exact structure: the characters `<html><body>`, then `<h1>Report for NAME</h1>` where NAME is the `username` of the matching user, then `<table>`, then a header row `<tr><th>Label</th><th>Amount</th></tr>`, then one row per matching record of the form `<tr><td>LABEL</td><td>AMOUNT</td></tr>` where LABEL and AMOUNT are the values of that record's `label` and `amount` columns, then `</table></body></html>`. A matching record is any row in `records` whose `label` value contains the `<filter>` string as a case-sensitive substring. Matching records must appear in the same order as they appear in the `records` table. Terminate with exit code 0.

Example: `data.db` has `users` containing (`tok123`, `alice`, `admin`) and `records` containing (`1`, `alpha widget`, `10`) and (`1`, `beta widget`, `20`). Running `echo tok123 | python report.py data.db widget` prints an HTML document whose heading is `Report for alice` and whose table has two rows: `alpha widget` with amount `10`, and `beta widget` with amount `20`.
