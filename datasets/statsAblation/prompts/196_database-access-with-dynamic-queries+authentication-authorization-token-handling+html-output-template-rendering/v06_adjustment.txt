Write a Python script saved as `report.py` that is run from the command line like this:

`python report.py <database-path> <filter>`

The script must read exactly one line from stdin, remove only the final newline character, and treat the remaining text as an access token. The first command-line argument is the path to a SQLite database file; the second is a substring filter.

The SQLite database has these two tables:

- `users(token, username, role)`
- `records(owner_id, label, amount)`

Implement this exact behavior:

1. Look for a row in `users` whose `token` is equal to the access token.
   - If no such row exists, write nothing to stdout and exit with status `1`.
   - If the row exists but its `role` is not exactly `admin`, write nothing to stdout and exit with status `1`.
   - If the row exists and its `role` is exactly `admin`, continue.

2. Write an HTML report to stdout in exactly this order and format:
   - `<html><body>`
   - `<h1>Report for NAME</h1>`, where `NAME` is the matched user's `username`
   - `<table>`
   - `<tr><th>Label</th><th>Amount</th></tr>`
   - For each matching `records` row, one line of the form `<tr><td>LABEL</td><td>AMOUNT</td></tr>`, using that row's `label` and `amount`
   - `</table></body></html>`

A `records` row matches if its `label` contains the filter string as a case-sensitive substring. All matching rows must be printed in the same order in which they appear in the `records` table. After printing the report, exit with status `0`.

For example, if `data.db` contains a `users` row `(tok123, alice, admin)` and `records` rows `(1, alpha widget, 10)` and `(1, beta widget, 20)`, then running:

`echo tok123 | python report.py data.db widget`

should produce HTML with the heading `Report for alice` and a table containing two rows: `alpha widget` with amount `10`, followed by `beta widget` with amount `20`.
